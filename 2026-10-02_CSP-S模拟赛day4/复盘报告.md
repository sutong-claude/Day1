## 2. 这场的真实崩溃链

### 0:10~1:06：A 深度研究
先证明 baseline 下界 `sum |ai-bi|`，再用附件找反例。最关键的一刻是发现答案多出 40，并进一步说出：
“需要一个人撑到最高点和最低点，先撑着再卸下来，会有额外操作。”

这已经触到满分结构的核心：极值约束导致某个支撑点需要绕路。问题不在于没有发现关键机制，而在于没有把动态叙述进一步静态化成“枚举 support，只计算 support 的额外 detour”。

### 1:07~2:38：B 从高质量建模进入实现泥潭
早期观察是好的：
- 若窗口里某个值重复，删除值往往被强制确定；
- 删除一种值后，剩余序列必须严格递增；
- 左右递增段/断点很重要。

但把“存在一个 v”塞进滑窗状态后，左端点移动时最佳 v 可能整体变化，状态不再闭合。  
2:06 后开始写真正的 generator / brute / WA 对拍，这是 Day2→Day4 的明确进步；但 brute 自己漏了“v 不能等于两端点”，说明 oracle 也必须逐条核对题意。

### 2:38 以后：信息增益下降 + 沉没成本
赛时明确说出“每次都要调试，花费巨大时间”，随后又说“第二题解不出来，一题都拿不到满分，后面的题可以直接放弃”。

这是本场最危险的决策：把“当前题能否满分”错误地绑定到“后题是否值得看”。

### 3:02 以后：完全无话可说 + 环境资源事故

因此后半段应视为“认知崩溃 + 工程环境崩溃”的复合故障，而不是简单的心态标签。

## 3. 三份提交为什么全部归零

### A：CE
最终提交：
```cpp
freopen ("Thermokinesis.out, "w", stdout);
```
字符串少一个引号。虚拟机中的另一个版本并不是这个状态，说明“正在测的文件”和“最后提交文件”仍未彻底统一。

### B：TLE / 小数据分支损坏
main 已经读入 n 和数组后，`solve2()` 又重新读了一次 n 和数组。  
因此本来最该保险的 n<=20 暴力分支会把下一组输入甚至 EOF 当作新数据。  
此外 brute 漏了窗口端点不能被过滤的限制。

### C：未提交
这是本场非常关键的损失。C 是 m<=6 的树题，明显带小状态/bitmask 味道，但因为 A/B 长时间研究，几乎没有获得正常阅读和建模时间。

### D：RE
最后版本把 DFS 和文件 I/O 分支注释掉，无条件输出 n!，连样例 4→20 都不满足。  
这是典型的“最后没有稳定 partial 可回滚，只能把手边残局交上去”。

## 4. “如果环境没炸，实际最多能拿多少”应分三层看

不能把“理论上能补满”当作赛时能力。

- **只修工程错误，不增加新算法发现**：A 的部分分版本 + B n<=20 定义暴力 + D n<=20 暴力，合理上限大约在 35~45 左右。
- **保留已经出现的关键观察，并且没有 C 盘/虚拟机事故、能及时止损和扫 C**：大约 60~100 是更有意义的赛场上限区间。
- **把 A 的“支撑极值”观察真正完成成正解**：A 可能直接从部分分跳到 100；此时整场上限可到 120~160+，但这已经包含一次尚未在赛内完成的抽象，不能算“本来稳拿”。

所以本场最值得追的不是“0→200 的幻想”，而是先把已经在手里的 35~45 稳定变成分，再给 A/C 的突破留空间。

## 6. Day4 新增硬规则

1. 任何 10/15/20/30 分方案，一旦写出，立刻冻结成可编译、可提交、可回滚版本。
2. 只有一个文件允许作为 OJ 上传源；提交前不得临时从另一份代码拼 freopen。
3. oracle checklist 必须逐条覆盖：输入、多测、端点、存在性、最优性、格式。
4. 最近 15~20 分钟若只有局部 Debug、没有新的结构性事实，视为“信息增益归零”，必须降级/切题。
5. 前 90 分钟必须扫过四题子任务和算法味道，防止后题恰好是自己擅长的标准算法却完全没看。
6. 最后 10 分钟只允许：编译、最小样例、附件、freopen 检查、提交；禁止推新算法。
7. 录音/录像必须有磁盘水位保护；主机 C 盘不足时应自动停屏幕/音频缓存，而不是拖死虚拟机。
8. “T2 不满分，后面就没必要做”列入赛场禁句。

## 7. 关于录播采集

用户要的不是键盘统计，而是“像看比赛录播一样看见输入最终变成了什么”。

仅记录按键不够，因为鼠标、光标移动、选择、粘贴、IME、undo/redo、终端输出都会改变最终画面。  
以后采集应采用三层证据：

1. **低帧率压缩屏幕录像**：1 fps 左右，分段保存；
2. **语义键盘时间线**：TYPE / KEY / WINDOW / PASTE；
3. **源码/notes 文件快照**：保存时记录真实文件状态。

屏幕录像负责“看到当时画面”，键盘日志负责精确检索，文件快照负责恢复真实代码状态。统计只能是复盘后的副产品。
