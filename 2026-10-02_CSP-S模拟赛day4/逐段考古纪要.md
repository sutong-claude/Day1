# Day4 逐段考古纪要（append-only）

## E-D4-001｜T+00:05～00:34｜A 温控舱｜baseline 已经存在

**来源**：键盘回放校正版 + VM 源码。  
**观察**：早期已尝试围绕极值可动性建立 baseline，而不是完全盲写。  
**后续赛后闭合**：[P] 最大值不增加、最小值不降低；目标极值区间必须被初始极值区间包住。  
**赛后更强结论**：先把每个 a_i clamp 到 [minB,maxB] 可达到显然 L1 lower bound；只有“唯一两端互换”会需要额外支撑。  
**结论**：赛时“要有人支撑最高/最低”的直觉其实接近 full，缺的是把它写成 lower bound + 唯一不可达情形。

## E-D4-002｜T+01:18～02:00｜B｜开始形成主实现

**来源**：全过程复现 + VM。  
**观察**：B 逐渐占据主要时间，状态/last/least/map 等对象不断变化。  
**问题类型**：不是纯实现小 Bug；数学状态本身没有完全闭合。  
**结论**：当变量语义在 Debug 中不停变化，应该暂停并写“对象/必要性/充分性/实现契约”。

## E-D4-003｜T+02:00～02:30｜B｜第一次真正把对拍链跑起来

**来源**：Replay/回放恢复结论。  
**正面进步**：generator + brute/oracle + candidate + diff 真正进入赛场。  
**反转**：oracle 自己漏了端点条件。  
**证据等级**：[X] “有对拍=正确”被本场直接证伪。  
**长期结论**：对拍至少需要 oracle sanity case，checker/brute 都是程序。

## E-D4-004｜T+02:30～03:03｜B｜Debug 黑洞，信息增益接近 0

**来源**：键盘回放。  
**客观行为**：主要变成 c/last/least/map 局部修补、大量复制粘贴和重复运行。  
**新研究结论**：很少。  
**结论**：Debug 是否继续不能看“还在改东西”，要看每15～20分钟是否获得新不变量/反例/复杂度下降。  
**触发器**：若只有索引/变量/局部 patch 而没有新的模型证据，冻结 partial、切题或重建 oracle。

## E-D4-007｜A 正式提交 CE 已由 OJ source × VM diff 精确钉死

**来源**：
- 03包 `虚拟机(1).zip!虚拟机/Desktop/A/main.cpp`
- 02包 Day4 OJ 归档正式提交源码 `record_6abfbb684f6635dea3349ff1.cpp`
- record JSON：2026-10-02 22:10:48，Compile Error，0分。

两份代码主体几乎完全相同，关键差异只有提交版的 file IO：

```cpp
freopen ("Thermokinesis.in", "r", stdin);
freopen ("Thermokinesis.out, "w", stdout);
```

第二行文件名字符串缺少正确的闭引号位置，因此 [P/source] **正式提交源码本身不能通过编译**。

VM 后续版本则变成：

```cpp
//freopen ("Thermokinesis.in", "r", stdin);
//freopen ("Thermokinesis.out, "w", stdout);
```

所以赛后只打开 VM 当前文件，会看到一份已经绕过该 CE 的版本。

**修订结论**：
> Day4 A 的 0 分不能只归成“最后提交失误”；现在可以具体到“traditional IO 行在正式提交版本中引入语法错误，而后续本地版本已把事故行注释掉”。

**长期触发器**：
> 正式提交前单独编译一次“已打开 freopen 的最终文件”，不能只编译平时注释 IO 的开发版。

## E-D4-011｜T1/checker.cpp 名称纠偏｜它不是题目 checker，只是 mismatch counter

**来源**：三包全量展开后的原始 `T1/checker.cpp` 完整源码。

它实际只做：
1. 读 n；
2. 读数组 a[1..n]；
3. 读数组 b[1..n]；
4. 若 b[i]==-1 则跳过；
5. 否则统计 a[i]!=b[i] 的位置数并输出 cnt。

它：
- 不使用 testlib；
- 不读取题目状态/操作语义；
- 不验证 candidate 可行性；
- 不验证最优性；
- 把 b[i]=-1 的位置直接忽略。

所以以后这个文件必须分类为：

> **local comparison utility / mismatch counter**

而不是：
- official checker；
- brute oracle；
- correctness validator。

**新证据规则 [P/source]**：
> 文件名叫 `checker.cpp` 不能自动获得 checker 权威，必须先审计它实际验证的命题。

完整审计：
`tools/archive/Checker_Stress_Oracle源码审计_2026-10-07.md`

## E-D4-012｜T2/gen.cpp 覆盖域极窄｜“跑了很多轮”也不能代表广覆盖

**来源**：三包原始 `T2/gen.cpp`。

generator 固定：
- t=1；
- n∈[1,10]；
- 每个值∈[1,13]。

因此它能提供的是：
- 小数据 smoke test；
- 小规模模型反例；
- candidate/brute 快速差分。

它不能提供：
- 大 n 性能覆盖；
- 大值域边界覆盖；
- 特殊结构族覆盖；
- adversarial distribution 覆盖。

这把 Day4 的“对拍链有了但 oracle/generator 仍需验证”再具体化一层：

> **对拍次数不是覆盖度；必须记录 generator domain。**
