## 2. A《蜗蜗密码》：正确模型是最后出现位置

对每行的26个小写字母维护最后一次出现位置，初值-1；顺扫输入，更新last[ch]；只保留确实出现的字母，按最后出现位置递增输出。复杂度每行O(m+26log26)。

Replay：初版遗漏“未出现字母不应进入结果”的判断，后续加 `if(pos==-1) continue`，正式OJ100。

**迁移信号**：把 `-1` 当不存在的哨兵以后，任意排序、入队、集合构造都要先排除无效项。

## 3. B《蜗蜗猜球》：有限状态要先证明周期

三碗排列交替交换 (1,2)、(2,3)。两步合成三循环；三组两步后得到单位置换，因此无论初态，六步恢复。即使操作次数 n≤10^9，也只需算 n mod 6。输入最终碗位 x 时，分别模拟三个初态的六步表，找与x相符的那一个。

[ASR] 赛时并非只凭印象口算“肯定有周期”，而是把三种起点的运行轨迹逐一列成表，再编码。正式OJ100。

**迁移信号**：操作次数很大、状态极小时，先问操作是不是置换、周期是否可严格证明；纯暴力模拟小状态常比上矩阵更稳。

## 4. C《蜗蜗的外卖机器人》：发现Bug的真实证据链

网格存在障碍，需要按指定顺序依次到达0~9物品，再到终点。把起点S、每个目标、终点T组成固定目标点序列，相邻两站间分别BFS取最短路，求和；由于站点顺序固定、无路径依赖，其各段最短距离之和就是总最优。

**Replay保存演化不是一遍写对：**
- 首版入队写法 `p.push(nx,ny)` 造成编译错误；
- 修成 `p.push({nx,ny})`，消除语法障碍；
- 运行时出现反复入队/卡住，录音出现Ctrl+C；
- 修正真正的状态约束：入队时立刻写 `vis[nx][ny]=true`，保证每个格点只入队一次；
- 打开正式文件IO，最终OJ100。

**应继承的不变量**：BFS必须把“设置visited”和“成功入队”作为同一原子事件，否则多条边重复进入同一格，性能可能失控。

## 5. D《记忆修复》：两条独立失败链

给字符串S,T，选**恰好K个非空、两串中各自不重叠且按顺序对应**的相同连续段，使总字符数最大。

### 5.1 [SRC/E] 内存根因
```cpp
#define int long long
int dp[1010][1010][20][2];
```
全局静态DP字节数：
```
1010*1010*20*2*8 = 326432000 bytes = 311.31 MiB
```
原报告曾在256MiB地址空间限制下复现 SIGSEGV(139)，在512MiB可输出官方样例6。官方归档逐点 verdict 是 **RE**，而不是MLE；评测机真实信号和资源限额并未由OJ原始元数据独立明确记录，故只能写**高可信资源问题**，不能称官方已证实MLE。

### 5.2 [SRC/E] “恰好K段”被代码放宽成“至多K段”
赛时代码引入 `max(...,1LL)`，允许在某些 `k>1` 的状态中直接以单字符作新段，破坏“已开K个非空段”的状态不变量；又在答案处枚举 `k=0..K` 取最大，数学目标被改变。
例如：
```
n=2, m=2, K=2
S=aa
T=ab
```
两串中最多匹配1个字符，无法选择两个非空相同段；正确答案应为0，但原版即使内存足够也可能输出1。不能把“内存降了就一定AC”当成结论。

### 5.3 [REP] 实际提交前仍有剩余时间
前三题已于比赛第41分钟拿到300；D在17:24提交、17:26停止Replay，网页显示还有两个多小时。比赛没有证据表明整段剩余时间已用于系统性压测和状态不变量证明，因此该场最重要的得分资产管理失误是：**缺少提交前对峰值内存和k恰好语义的独立验收，并提前结束了可用研究时间**。
