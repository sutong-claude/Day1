# 一、用户真正想让这个系统做什么

这不是标准题解百科，而是还原每场四小时竞赛中的真实智力劳动。先尊重本人在赛时发明或提出的每一个模型、猜想、分类、最小反例、手玩过程、失败尝试和被迫中断的思路，再沿这条路线验证、修正和优化。绝不能听到用户提出 F 题思路后，直接展示 AI 突然得到的更简单独立正解，取代对用户成果的认真理解。纠错需要给出明确的第一个不成立的前提、最小触发输入、当时为什么会想到、如何最小幅度修补；尊重不是盲从，错误结论仍必须以证明或反例纠正。

用户要求讲题通常遵循：洛谷式标签/估计难度 → 人话复述题意和输入输出/范围 → 简洁核心概述 → 手玩样例、观察、性质 → 逐阶段伪代码和构造代码 → AC 程序；在长课中进一步扩展为 PPT 风格多模块，包括错误路线、partial 梯度、复杂度、实现与复盘。不要大段堆公式与最终代码，也不要把前人标准题解直接覆盖他的过程。

“你怎么想到的”的教学要有**双轨**：轨道一是真实可核查的观察依据、规模信号、程序运行与来源材料；轨道二是明确标为“教学重构”的探索链，从实例、猜想到证伪、修正及结构化优化。重构是帮助理解的教学故事，不是模型可供核验的私有内部逐字思维日志，也不能声称曾亲历某 OJ。

当用户给出原 C++ 时，要保留原码和函数/变量/缩进，优先展示具体 diff 和最小字符修改。修复一个错误不代表完整正确：定义域、语义、溢出、复杂度、正式 IO 和官方成绩要分别验收；最小修改不够时应明确说还缺哪层。

用户反复要求能力级验收：资料扫描不等于精读；文档规划不等于代码实现；Python 模拟不等于实际 C++；本地样例通过不等于 OJ AC；仓库内容存在不等于有最新提交；模型觉得会做不等于比赛已经得分。遇到这些概念交界一定要把证据层级标明。

# 三、证据优先级、标记与不变量

证据优先级不是简单“越晚越准”。分数取同场同一时段的 OJ record.score 与子任务包；提交的代码取官方 OJ source；版本变化取 Replay file_changes 全文与 SHA；未保存动作查 screen/录音；动机/疑问取原始 ASR、notes；数学真值通过独立证明与小数据 oracle。不同日期的 OJ 归档需做字段级并集：较老快照可能有较完整榜单，较新快照可能补充 record metadata，不能无条件 latest-wins。

使用 [P] 代表严格证明，[E] 代表独立暴力、穷举或程序实验，[C] 代表题面/checker 的真实契约，[H] 代表待证猜想，[X] 代表反例，OJ-AC 只代表官方测试通过。另可明确区分 [U] 用户原话、[R] Replay 记录、[S] 提交源码、[G] GitHub commit、[L] Library 原件索引、[I] 后验推断。报告中的 [P] 若仅复述旧报告证明且本轮没有重新复查，应该写“仓库已记载 [P]”，而不是“本轮独立证明”。

复盘的每个重要事件应落为：来源和时间 → 当时看到/做了什么 → 当时的模型/猜想 → 代码/画面变化 → 后来的反例/实验 → 第一个错误点 → 赛时可用的修正或得分状态 → 下场触发器。不能只报告“最终错在哪里”。事件 ID 要查重，Day7 裸 E-D7-013 曾冲突，采用 E-D7-013a/013b，禁止新文档再次制造重复 ID。

Replay v3 推荐 timeline.txt → file_changes.jsonl → screen_*.mkv → raw_keys.jsonl.gz → manifest.json，录音与其独立对照。需记住文件保存轮询有时间空隙、screen 才能看到鼠标和未保存动作，raw 键流有采集器版本和 pause 的语义缺口；录音没有声音并不代表此刻没操作。最终 VM 代码不天然等于官方提交；必须内容归一化后比对，最好 byte exact 并记录是否仅不同于 freopen。赛中录音双转写来自同一次音频，只能互校 ASR，不可视为两份独立证据。

# 十四、接班 AI 逐步施工手册：不是只读 README

第一步，确认当前仓库目标分支、真实 HEAD、是否有别的 AI 同时写入；把这次报告的旧版本时间看清楚，永远优先新原始提交和用户最新消息。先读 AI_MASTER_INDEX、AI_HANDOFF、总协议、全题总表_2026-10-11、证据阅读台账与对应逐段考古纪要，再看本报告的当前状态和待办。

第二步，用 Library 查原件，不要求用户重复上传已经在该账户中的文件。三包完整性索引用于找到具体 source path；按 content-hash 去重、保留 provenance 和 contest mapping；在需要做语义复盘时真正读相关文件全文/指定时间线/屏幕关键帧，而不是只取文档摘要。用户明确要求的原始聊天用消息索引定位，看到6处截断就保留 unknown。

第三步，在一个最值得增量的具体题目上工作，不要同时“计划100项”最后没有产出。优先读用户当时自己提出的思路与 notes，恢复第1/2/3代模型，复现有信息增益的代码和反例，对比官方 source 与 VM save。结论必须分赛时、赛后、后来 AI 推导，且不同证据之间一旦冲突，应写修订原因。

第四步，把一段材料转成完整事件：时间/源 → 原话要点 → 实际保存变化 → 原假设 → 后续验证 → 第一个错误点 → 可复用触发器。立即追加到对应逐段考古纪要，必要时修改题解、版本说明、总表、错因档案；不能只在聊天里说“分析好了”。

第五步，对新增代码进行真实编译、官方样例、边界微测、独立穷举、小随机、极值性能测试，并将可执行命令、语言版本、输入种子、输出/失败限制写入验证报告；报告不能把模拟预测说成官方得分。

第六步，检查新文档是否含个人信息、密码、私有音频/屏幕/原始聊天。如果仓库为 public 则拒绝把这些字节写入 Git。私有 Library 原件不用复制，但必须写一条足够精确的检索指引。

第七步，以真实 commit SHA 验收 GitHub push，并从新 commit 精确 ref 回读关键文件、确认 tree 包含预定路径。若本轮没有 commit，就只能说本轮没有 GitHub 更新。若修改多个 canonical 文件，要有一致版本号、总表状态、README 入口，不能让后续 AI 在三个入口中看到互相矛盾的“最新”。

# 附录A：后来模型最容易搞错的十三个问答

**Q1：为什么Day3比赛的总成绩不是“全都AC就很好”？** 因为A得100、B得65、C得24、D得15，本身已经有非常稳定的价值资产；而B的checker会让错误答案在其没有验证的NO分支获得假绿，这是“验证系统的可信度”问题。下一轮讲题先恢复用户怎么读大样例、发现相消/重复结构，再问局部checker的覆盖条件和正确真值，不把问题归因成从未思考。

**Q2：Day4拿0就表示模型全错吗？** 不成立。A正式交卷发生的是编译期的文件重定向错误；B经历合法域不符合题面的随机生成器、错误oracle与选手程序同向偏离；C几乎没有得到足够正常研究时间；D既有算法试探、又有运行时错误。要把数学失败、实现失败、验证器失败、交付失败分开，才能找下一场可执行的改进动作。

**Q3：Day5 A 为什么不能用一句“应该用单调栈”糊弄？** 因为用户赛时并非没有找到结构：他已经在思考三角包络、接触点，以及后缀最小值能否转为二分查询。这些尝试的核心疑问是“哪个位置的哪个覆盖者应当被返回”，数据结构选择是第二层。讲解时保留他的后缀查询路线，给出一个覆盖值顺序和索引顺序冲突的小案例，再说明单调栈如何维护恰好需要的对象。

**Q4：Day5 D 的完整GF(2)算法为什么不能证明当时被漏拿100？** 因为二阶矩、线性奇偶独立与确定性位集合并是赛后研究得到的候选。赛时原记录只有扫题并主动不研究的行为，没有证据显示这些数学结构当时已经发现。正确的能力评价是赛后能完成更深数学推导，但这不是赛时能力成绩，也不表示“再多看一分钟就能拿100”。

**Q5：Day6 C 的四分类是赛时真的想到的吗？** 已有原始版本时间线显示强制/任选结构进入代码，只是具体局部公式和全局状态没有正确闭合。新模型不能一边沿用赛后的full证明、一边把赛时用户说成完全未发现四类；应该先恢复四类的定义、代码位置及何时语义退化，再用独立真值构造局部相消型反例。

**Q6：Day7 B 为什么有冻结、提交后还是RE？** 冻结的是一份有恢复价值的稳定朴素版本，不意味着它已通过最坏时间/内存限制。算法语义、复杂度、unordered_set遗留造成的内存使用与正式上传字节身份是不同的验收层。把回滚看作正确工程行为，同时仍指出倒序加点+DSU的复杂度转折未完成，才是对原过程公允的分析。

**Q7：Day7 D 末尾退回短代码，就证明D本来没做吗？** 不能。20条main保存历史确切存在，从03:27到03:48持续增长到1663字节，03:52退回583字节。正确结论是曾发展某个候选、调试和否定之后撤回，而不是“从未展开研究”。接班要按保存时刻逐版追溯“是什么反例迫使模型变了”，不能只从最终583字节脑补四小时。

**Q8：Day8 A的abs错误，能否简化成“绝对值不能乱用”？** 这条经验太空泛。赛时先想到坐标反向的问题，才把组合数位移的有符号差替换成abs；更早和更晚都有针对上方/下方的交点分类。真正的不变量是单调路径每个分段横纵位移必须非负，并且d=m时不存在y=m+1层。以后看到路径数量需要对分段端点计算组合数，就用“有向可达性→定义域→排列组合公式→边界四角”顺序确认，而非简单禁用abs。

**Q9：Day8 C的23分证明了完整DP正确吗？** 没有。k[pos]改k[i]是必要的对象身份修补，但仍有O(n²×20)的时间下界风险。用户赛后自述23分，未见新官方逐点record。20bit拆半进一步解决复杂度，但其本地数据全过仍需官方重交和严格证明。任何新模型都不能因为三个版本目标相同，就把它们当一个已验证的正确程序。

**Q10：为什么不直接把私有原始数据复制进GitHub，让下个模型无障碍复盘？** 目前GitHub返回公开可见，即使删除敏感文件，其历史提交仍可能被人访问。用户要的是高保真接班，不是公开全部聊天、录音、截图、键流与账号信息。可行分层是公共仓库放脱敏结论、哈希与检索索引，原始资料留在有授权的Library。若新的模型没有同一账号资料权限，则说明该限制，而不是偷偷构造不存在的证据。

**Q11：目录里有 gen.cpp、duipai.sh 和 WA.cpp，能证明进行过大量对拍吗？** 不能。Day8四个题目目录的生成器和参考程序多数只是模板，并未接入真实随机分布或独立正确oracle。过去Day4曾出现generator非法域与oracle自身错误，所以不仅要问“有没有文件”，还要问运行过哪些命令、生成分布是否合法、oracle由什么保障，以及有没有可复现的测试输出。

**Q12：完整扫描 1.37GB 与完成全部考古差在哪里？** CRC/SHA扫描只验证数据能解压和内容身份，可以支持去重和来源定位；它不产生对用户每一次停顿、每一次重新推导的自动理解。Replay文件保存只记录落盘状态，未保存代码还需screen、raw_keys和录音补偿。长期目标不是让万字报告越堆越厚，而是新增一个可以跨源核验的事件，就在对应纪要里追加一个可继承的最小证据单元。

**Q13：以后报告新分数、训练结果或算法AC时最容易造假的地方？** 第一是把赛时与赛后混算；第二是把本地测试过的candidate写成官方AC；第三是把用户贴出的OJ页面称为AI独立登录核验；第四是把历史仓库中记录的实验数字说成本轮重新执行；第五是把Graph/DP解法存在当作用户赛时已经想到；第六是把Github暂存blob或创建tree当成远端branch已前进。必须给出提交SHA、record ID、命令、版本、日期和边界各自对应的证据，不能一口气以“全完成”覆盖。

# 附录B：接班者必须实践的一次最小闭环

假设后来的模型从仓库只有八场成绩、没有任何用户新输入开始。第一，确认GitHub默认分支与维护分支当前各自的HEAD，确认所需文件的内容SHA。第二，浏览接班报告和证据台账，把“目前已完成”为历史状态，不拿上次提交冒充本次行动。第三，挑 Day8 A70 的最大子任务 TLE，按Library索引找用户赛后源文件与完整OJ后续记录；若只有用户贴出的页面文本，就如实止于该层。第四，保存用户代码的不可修改原样副本和SHA，最小diff分别修d=m合法域与重复逆元开销，编译执行最小反例、最大性能样例和独立枚举真值。第五，生成问题、证明、实现、验收四个层次的叙述，给出真正的内存时间测量环境，避免把AI估算数当实测。第六，在Day8逐段纪要中补一个新的唯一事件ID，修改总表的赛后状态而不更改赛时15。第七，最后提交到选定施工分支并从SHA回读，用户下一条“继续”就应看到新证据和新代码，而非又收到一个几百行规划。

同样的循环可迁移到Day4 B的坏oracle、Day7 C/D的部分分冻结、Day6 C的语义状态退化。评估进度应看“多少关键错误链被强证据关闭、多少赛时思路变成可验证的技能或可运行的分数资产”，而不是看机器人处理了多少个ZIP和页面。

# 附录C：时间原点、同日先后与未来态

所有“最新”要指明具体日期、分支和资料生成时刻。2026-10-11赛时归档在第一批赛后数据之前，用户同日稍后贴出的A70页面与C23结果属于**后续增量**，即使文件名同样写着Day8也不能逆时间覆盖原来的15/400。第三版题解里的20bit候选同样是赛后才出现的推理能力；若后来获得满分，也只能证明新版在该次OJ数据上的表现，不会改变先前何时第一次被创造或验证。其它“录音原文”是不同ASR引擎对同一现场的编码，应按相同物理事件去重，不能把两份转写误作两次独立实验。历史旧分支的修复被后来强证据推翻时，保留旧说法及其错误原因，形成版本化勘误，不应静默删除难看的尝试。

这个体系的最终目的，是让下一位AI在理解用户已走过的路之后再前进，而不是让每一位AI不断用自己的新路线证明“我也会这道题”。
