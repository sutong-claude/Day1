# 1. 前 15 分钟：不是“选一题开冲”，而是建立全卷资产地图

对四题快速扫：

| 字段 | 必须写 |
|---|---|
| 题意一句话 | 我到底要优化/判定什么 |
| n / Σn / q / 时限 | 真正复杂度上限 |
| 子任务 | 每一档可拿多少 |
| 最机械 brute | 能否成为 oracle / partial |
| 强特殊性质 | 题面主动送的结构 |
| full 味道 | 只标 [H]，禁止直接相信 |

### T+15 硬检查

如果还没有扫完四题：
> 停止当前题继续深挖，先完成全卷扫描。

来源：Day4/Day5 前题吞时导致后题根本没获得正常判断窗口。

# 2. 每题写代码前的“60秒语义契约”

在 `notes.txt` 先写三行：

```text
对象：
我要维护 / 查询 / 判定的数学对象究竟是什么？

充要性：
当前 if / 公式为什么必要？为什么充分？

实现契约：
代码返回的东西与上面的数学对象完全同义吗？
```

如果任意一行说不清：

> 不准直接上复杂优化结构。

先做：
- 最小反例；
- 定义级 brute；
- 手玩；
- 对拍。

典型事故：
- Day5 A：要“最小位置 j”，却用“按值 lower_bound”；
- Day6 B：最大速率被偷换成固定平均速率；
- Day6 C：四类出现了，但 forced/optional/impossible/off 语义没钉死。

# 3. 猜想状态必须显式标记

`notes.txt` 使用：

```text
[P] 已证明
[E] brute/exhaustive 暂无反例
[C] 题面/checker契约
[H] 猜想
[X] 已有反例，禁止继续依赖
```

### 反例出现时

禁止：

```text
一个 [H] 被打死
→ 整套思路全部清空
```

必须做依赖删除：

```text
底层 [P]
   ↓
中间 [H]
   ↓
上层推论

若中间 [H] 死亡
只删除依赖它的上层
保留底层 [P]
```

来源：Day3 B。

---

# 4. 正确 brute 太慢时，先问“我重复算了什么”

不要第一反应：
> 套线段树 / 二分 / 换根 / DP。

先写：

```text
brute 每一步重复计算的对象：
____________________________
```

然后尝试四种结构变换：

1. **增量维护**：加一个元素到底只改变什么？
2. **固定参数**：固定一个关键对象后是不是变简单？
3. **交换量词**：存在 v 的窗口 → 固定 v 找窗口？
4. **时间反演**：删除/分裂难 → 倒序加入/合并？

### 强触发器：删除导致组件分裂

```text
固定顺序删除
+ split
→ 立即尝试 reverse time
→ add
+ merge
→ DSU
```

来源：Day7 B。

# 5. “这 X 分一定能拿”是命令，不是评价

一旦口头/notes 出现：

> “这10分稳。”
>
> “这19分一定能拿。”
>
> “这个暴力很好写。”

立刻启动 **10分钟物化协议**：

```text
PROVED
→ 写成 partial_X.cpp / 当前 main
→ compile
→ sample
→ 专项最小边界
→ FROZEN
```

然后才能回去追 full。

来源：Day7 C10 / D19。

---

# 6. 捆绑子任务：一次只闭合一个包

Coderlands tree 证明：

> 四个 70% 的 partial = 可能 0 分。

因此看到 bundled subtask：

```text
选一个包
→ 精确读该包全部条件
→ 写数学证明
→ 只写这一个包
→ 专项构造数据
→ FROZEN
→ 再开下一个
```

不允许同时铺：
- N≤5000；
- 链；
- 星；
- L=R；
然后每个都半成品。

---

# 7. 大样例不是“浪费时间”，但重复手工变换要脚本化

当你在大样例里：
- Ctrl+F；
- 删除外壳；
- 手工重排；
- 提取错误组；
- 一遍遍做相同变换；

如果相同动作 ≥3 次：

> 把动作写成脚本，让程序批量处理 20/200 组。

来源：
- Day3 B sample4；
- Coderlands game 第28组。

### 大样例的正确定位

它可以帮助：
- 找结构；
- 找 counterexample；
- 验证中间不变量。

但不能替代：
- 证明；
- independent brute；
- 小空间 exhaustive。

# 8. Debug 15～20 分钟信息增益检查

每 15～20 分钟问：

> 过去这一段，我得到了什么新的数学事实？

### 有信息增益
例如：
- 新不变量；
- 最小反例；
- 等价改写；
- 正确 query；
- 复杂度瓶颈；
- 证明关键一步。

可以继续。

### 没有信息增益
只有：
- iterator；
- 下标；
- if；
- Debugger 单步；
- “为什么 CPU 不按我想的执行”；
- 改一个系数看输出。

判定：

> **模型 Debug 黑洞。**

动作：

```text
冻结当前最好分数
→ 写一句真正要找的数学对象
→ brute / 反例
→ 或换题
```

来源：Day4 B、Day5 A、Day7 D5000。

# 9. 自由度极低时，停止猜结构

例如：
- k=2 只有一刀；
- 只有一个删除点；
- 一个特殊参数只有 O(n) 种可能。

先问：

> 我能不能直接枚举全部自由度？

Coderlands game：
> k=2 时直接枚举切点，比继续猜“端点/块形态”可靠得多。

# 12. 当前最值得在脑中保留的 8 个 trigger

```text
1. 删除→分裂
   => 倒放→加入→合并→DSU

2. “X分一定能拿”
   => 10分钟物化 + freeze

3. 最小位置满足条件
   => 先想 next greater / monotonic structure
   而不是按值二分

4. 自由度极低
   => exact enumerate

5. 手工相同大样例操作≥3次
   => script it

6. 一个 H 被反例杀掉
   => 只删依赖，不推翻 P

7. bundled subtask
   => 一次闭合一个包

8. 优化代码前
   => 数学对象 / 充要性 / 实现契约
```
