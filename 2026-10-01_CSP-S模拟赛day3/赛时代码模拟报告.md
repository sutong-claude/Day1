# Day3 赛时代码重新模拟

## A：100 分代码

虚拟机 T1 最终代码重新编译后：

- `ex_A1`：2 / 2；
- `ex_A2`：816 / 816。

算法本身是正确的“排序后枚举保留前缀”。实现里最后一次 `pop_back` 后 `tot=0`，仍会算一次 `sum/tot`；因为 `sum` 是 double，通常得到 NaN/Inf，随后在空 vector 上 `upper_bound`，没有影响最终 ans，但这是应删除的脏路径。赛后版已经改成只枚举非空前缀，并完全整数化。

## B：为什么本地看起来全 AC

虚拟机 T2 最终代码重新跑 8 份官方附加样例，再用题目原版 checker：**所有 YES 构造都合法**，表现与赛时完全一致。

但原 checker 源码顶部就写着：`NO is skipped. This program does not decide whether a solution exists.`；代码中遇到 NO 直接 `Skipped`。

因此赛时代码最大的错误不是“构造错”，而是**错判 NO**。

本地全穷举找到的最小无越界逻辑反例（字母表 abc）为：

```text
aabacacb
```

赛时代码输出 `NO`，但翻转 1-based `[4,5]`：

```text
aabacacb -> aabcaacb
```

可以完全消空。

另有实现边界风险：如 n=1 或整个字符串首尾不断相等，赛时代码的 `while (s[l] == s[r]) l++, r--;` 没有 `l<r` 保护，会越过有效区间。
