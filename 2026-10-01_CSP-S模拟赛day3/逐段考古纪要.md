## E-D3-001｜T+00:05～00:11｜A 报数｜贪心已经形成

**来源**：录音原文 + 键流 + 最终 A 源码。

**结论**：A 的问题是“发现快，落地慢”，不是不会贪心。

## E-D3-002｜T+00:48｜B 翻面消除｜正确 oracle 已经被本人说出来

**来源**：录音。  
**当时方案**：枚举 [l,r] → reverse → 栈约简检查，O(n³)。  
**证据等级**：[P] 小数据真值算法。  
**关键失败**：本人把 brute 理解成“低分提交程序”，而不是研究工具，于 00:56 左右说“骗分不如直接做对”。  
**后来证据**：之后近两小时的多代猜想如果有这个 oracle，都可以自动找最小反例。  
**结论**：这是 Day3 最大机会成本节点之一。  
**触发器**：任何“正解猜想”一旦有可写小数据 brute，brute 优先级高于继续手玩。

## E-D3-006｜T+03:40 以后｜D 同类分段｜卡在操作模拟层

**来源**：录音 + final code。  
**当时对象**：左右 unordered_map / 集合相同。

## E-D3-007｜T+01:56～02:09 / 03:03～03:09｜B｜checker 全绿，但官方 sample7 已经有 false-NO 反例

**来源**：
- 原始 keystream `events_20261001_184442.jsonl` / `keys_20261001_184442.txt`；
- VM 原件 `T2/AC.cpp`、`T2/checker.cpp`、`sample1..8.in/out`；
- 2026-10-07 使用原版源码重新编译、重放 8 份官方样例。

详细复现：
`原始材料/keystream_20261001_184442_checker假安全链.md`

### 赛时客观行为 [C/source]

键流证明至少有两轮本地验证：

1. 约 T+01:56～02:09：编译 `AC.cpp`，生成输出，连续跑 sample1～sample4；
2. 约 T+03:03～03:09：重新编译候选与 checker，再把 sample1～sample8 全部跑一遍。

所以旧式归因“B 没有验证/只靠手玩”是不准确的。

### checker 契约 [P/source]

checker 源码直接写明：

```cpp
// NO is skipped. This program does not decide whether a solution exists.
```

候选输出 `NO` 时，它只打印 `Skipped (NO is not verified)`，不判断该 case 是否其实有解。

因此 checker 只能证明：
> 候选给出的 YES 构造合法。

不能证明：
> 候选输出 NO 时确实无解。

### 官方样例直接命中缺口 [E]

原版候选 + 原版 checker + 原版 sample1～8 本地重放：

- 8 份样例 checker 全部 exit code 0；
- 但 sample7 的第4个测试：
  - candidate：`NO`
  - official：`YES 62528 125010`

checker 对这一组输出：
`Skipped (NO is not verified)`
并仍然整份返回成功。

所以这不是“checker 理论上可能漏错”，而是已有确定反例链：

```text
candidate 真错（false NO）
→ 错误类型恰好落在 checker 未覆盖分支
→ checker 跳过
→ 8 份官方样例仍全部显示 green
```

### 修订结论 [X]

以下推断被直接证伪：

> “官方样例都经过 checker，所以候选判定应该基本正确。”

真正成立的只有：

> “候选所有被检查的 YES 构造在这些样例上合法。”

### 下一场触发器

任何 checker / validator 一旦出现：
- `Skipped`
- `not verified`
- 只验证 construction、不验证 existence
- 只检查 YES 或只检查 NO

就必须立刻把“未覆盖 verdict”单独列为 oracle 欠账。

构造题推荐固定双层验证：

```text
candidate YES → construction validator
candidate NO  → brute/existence oracle
```

两层没闭合之前，`checker exit 0` 不得升级为“整题正确”。

## E-D3-010｜B 的真正流程失控点｜不是“不知道在猜”，而是知道后没有切换研究工具

**来源**：上面两份 4:08 原始转写全文。

旧总结写“B 猜想太多”还不够精确。原始录音显示本人其实多次具备**非常清楚的元认知**：

### 第一次

约 T+01:20～01:21，形成“约简后找某种相等位置”的候选后，明确说：

> “我深知，我这猜想很有可能不对。”

这意味着风险识别已经存在。

### 第二次

约 T+02:12，sample/checker 把猜想打死后，明确出现：

> “好像我错了。”  
> “一战回到解放前。”  
> “心态爆炸。”

### 第三次

约 T+02:18，本人直接说：

> “你不能猜结论了，剩下时间不给猜结论了，我觉得这样子不对。”

但客观上之后仍继续用长样例手玩、首尾规律、块结构等方式研究约 25 分钟，直到 02:43 再形成一个新猜想。

**修订结论 [P/process]**：

Day3 B 的核心失败不能只归因于“缺少自我怀疑”。恰恰相反：

> **已经识别‘当前方法在猜’，却没有一个机械动作把这种元认知转换为 brute / stress / 切题。**

所以更准确的训练目标是“元认知 → 强制工具切换”：

```
说出“猜想可能不对 / 不能再猜 / 回到解放前”
→ 5分钟内禁止继续手玩大样例
→ 只允许三选一：
   A. 写 n<=8/10 existence brute
   B. 写 generator + 最小反例搜索
   C. 冻结当前 partial 并切题
```

这比泛泛的“不要猜结论”更可执行。

## E-D3-011｜03:22～03:23｜从“研究”切入“动作焦虑”的原话证据

**来源**：双 ASR 全文互校。

切到 C 后，本人明确说：

> “现在有点静不下来了，因为我太想骗更多的分了。”

紧接着又说：

> “如果我现在不再改写代码，那我就是在丢分。”

这是一条非常有价值的赛时状态证据。

它说明后半场并非单纯“时间少”，而发生了决策模式变化：

```
前半场：愿意长时间手玩 / 推猜想
↓
B 吞时 + checker 失败
↓
后半场：产生“只要没在敲代码就是丢分”的动作焦虑
↓
C：先暴力（健康）但很快转 factorial 押注
D：直接按自己估计的 partial 梯度抢写
```

这解释了一个看似矛盾的现象：

- B 上过度研究、不肯切；
- C/D 上又过度强调立刻编码。

两者其实是**同一时间压力反馈环**的两个阶段。

下一场触发器不应是“多想”或“少想”，而是：
> 每 20～30 分钟检查一次当前动作是否增加了 **证明 / 反例 / 可提交分数** 三者之一；若都没有，才切方法。

## E-D3-013｜B65 得分结构降级｜不是可靠65分 partial，而是 DISTRIBUTION_HIT

**来源**：
- P5631 原始测试点约束表；
- OJ 20 个独立5分组测试结果；
- submitted source。

AC 组：
6,7,8,9,10,11,12,13,15,16,17,19,20。

WA 组：
1,2,3,4,5,14,18。

关键反证：

1. #13 与 #14 属于同一档声明限制（R≤100、其余大范围相同），但 #13 AC、#14 WA。
2. #16～#20 都是 full-general 无特殊性质，但 #16/#17/#19/#20 AC，#18 WA。
3. 失败反馈同时包含：
   - interval does not erase the string：YES 构造错误；
   - a solution exists：false NO。

所以旧式表述：
> “B 有一个稳定65分算法”

应标 [X/obsolete]。

更准确：
> **错误模型在官方测试分布上命中了65%，但同约束族内部都不稳定。**

因此 Day3 B65 不能进入“下一场可依赖 score floor”；它属于 DISTRIBUTION_HIT，而不是 SIZE_BRUTE / SPECIAL_EXACT。

这条和 checker false-NO 事件并不冲突：
checker 漏 NO 是导致错误模型存活的重要赛时因果，但最终 submitted model 还同时存在 YES construction 错误，不能把全部35分损失都归成一个 checker 问题。
