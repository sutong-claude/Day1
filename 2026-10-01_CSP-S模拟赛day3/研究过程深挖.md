# Day3 研究过程深挖：不是题解，而是“你当时是怎么研究的”

> 这份文档不重复四题正解，而是分析每个思路为什么会出现、它离正解多远、为什么被保留或抛弃、应该如何把同样的研究能力变成更稳定的比赛结果。

# 一、研究能力画像

从 Day3 的录音、notes、代码与键盘流看，你的研究风格有一个非常明显的组合：

**强项**
- 先手玩小例子，结构直觉强；
- 很容易发现“什么东西应该不变”；
- 对局部反例敏感；
- 会主动读取 checker / 附件；
- 能在压力下迅速写出模拟暴力。

**弱项**
- “已证明事实”和“暂时猜想”记在同一层；
- 反例主要依赖手工和官方样例，不够自动化；
- 一个猜想被推翻后，容易把它依赖的正确中间结论一起抛掉；
- 很容易在数学结构还没定时提前寻找数据结构；
- 研究进入低收敛状态后，没有硬终止条件。

这意味着你并不缺“想法数量”。恰恰相反，你的想法很多。

真正缺的是：**对想法进行证据分级和快速淘汰。**

# 二、A 报数：典型的“直觉先于证明”

## 研究链

```text
样例 1 2 3 4 5
  ↓
想降低平均数
  ↓
删最大的数最划算
  ↓
排序
  ↓
枚举保留前缀
  ↓
upper_bound 找 > average 的数量
```

这条链很干净。

### 你真正应该补的只有一件事

把“删最大”从直觉写成交换论证。

否则以后遇到相似题：

- 当前直觉恰好错；
- 样例又没卡；

就可能出现 Day1 A 那种长时间围着错误公式转。

## 建议训练

看到“选一个子集最大化与平均值有关的某种计数”：

1. 固定选取数量；
2. 问能否交换成前缀 / 后缀；
3. 再枚举数量。

这可以形成模板。

# 三、B 翻面消除：研究过程其实非常接近数学发现

B 不是简单的“乱猜”。

它经历了一个很真实的研究过程：

```mermaid
flowchart TD
    A[直接枚举 l,r] --> B[发现栈约简]
    B --> C[翻转影响边界]
    C --> D[尝试 O(n²) 合并栈状态]
    D --> E[全局约简 S -> R]
    E --> F[在 R 上猜局部规律]
    F -->|大样例反例| G[继续手工模式挖掘]
    G --> H[发现首尾对称/可剥]
    H --> I[发现中间重复块]
    I --> J[赛时代码: 原串先剥首尾]
    J --> K[checker 只验 YES]
    K --> L[错误自信: “已 AC”]
```

## B 最可惜的点：你其实发现了三条真命题

### 真命题 1：奇数长度必无解

因为每次删除 2 张卡，翻转不改长度奇偶。

### 真命题 2：相邻相同消除的约简结果唯一

你的栈就是标准约简。

### 真命题 3：中心结构与“重复块”有关

最终正确条件确实是循环约简核为 `XX`。

问题不是没有真命题，而是它们没有被标记为“锁定”。

---

## 研究失败的核心机制：证据等级混乱

你的 notes 里同时存在：

```text
n even
a[l-1] = a[r]
s --> R
R same letter
4k = n
C true
```

其中有：

- 定理；
- 必要条件猜想；
- 充分条件猜想；
- 特殊性质观察；
- 被推翻但没划掉的旧结论。

一旦这些都长得一样，大脑会不断重新加载已经验证过的信息。

这会造成两个后果：

1. **重复研究**；
2. **正确基础被错误上层猜想拖下水。**

# 四、B 的研究日志如果按证据分级，应该长这样

```text
[P] n 必须是偶数
[C] checker: YES 构造会真正 reverse+reduce 验证
[C] checker: NO 直接 skipped
[P] reduce(s) 唯一
[H1] 只看翻转边界 a[l-1], a[r] 可以判
[X1] 反例：……
[H2] reduce(s)=R 后，R 有重复字母就可行
[X2] 反例：……
[H3] 循环约简后为两个相同半串 XX
[E] 3 字母 n<=9 穷举无反例
[TODO] 证明 H3
```

注意：

**H1/H2 被杀，不会影响 P。**

这会让研究越来越收敛，而不是每次反例后回到起点。

# 五、B 为什么手玩 100 个大样例不如枚举 3 字母小串

你当时后半段大量时间在看长度 100 的字符串。

这种大样例有两个问题：

1. 人很难知道“为什么它过/不过”；
2. 一个错误猜想被卡住后，很难提取最小原因。

自动穷举可以把反例压到：

`aabacacb`

这种长度 8。

小反例的研究价值远高于 100 字符随机串，因为你能真正看清：

- 哪个消除跨过了边界；
- 为什么“原串先剥首尾”不合法；
- 正确的约简顺序是什么。

**研究时应优先追求最小反例，不是最大压力数据。**

压力数据是最后做性能的。

# 六、C 任务领取：你已经到“根”的门口

C 的赛时研究过程：

```text
读题
  ↓
看到 n<=8
  ↓
任务边全排列暴力
  ↓
模拟领取
  ↓
发现一定有人最后拿不到任务
  ↓
怀疑这个人和优先级极大有关
  ↓
时间耗尽
```

这条链其实相当漂亮。

## 关键原话 1

> “肯定会有个人安排不到。”

对应满分解：

> 成功时 n-1 条边正好让 n-1 个人各拿 1 个任务，因此恰好一个人空闲。

## 关键原话 2

> “安排不到的人有没有可能他是最大的呢？”

对应满分解下一步：

> 这个空闲点作为根，必须比所有邻居“更不优先”（数值更大），否则根会先抢到某条边。

你当时差的不是一个陌生高级数据结构。

你差的是**继续沿最终状态往回推 10～20 分钟**。

# 七、C 暴露出的正向能力：你能从“最终资源分配”找到根

这是值得专门训练的一类题。

以后看到：

- n 个点；
- n-1 个资源/边；
- 每点最多一次；
- 过程按顺序执行；

先问：

> 全部成功后，谁是唯一没被匹配 / 没领到 / 没删除 / 没覆盖的对象？

很多树上过程题都会因此出现一个自然根。

你在 C 已经自发做到了第一步。

# 八、D 同类分段：研究卡在“操作模拟层”

你当时想的是：

```text
左边一个 unordered_map
右边一个 unordered_map
枚举 m
看两个 key 集合是不是相同
```

这是直接照题意模拟。

但高分题通常需要把“集合相同”翻译成逻辑。

对于一个值 x：

```text
x 在左边出现
AND
x 在右边出现
```

等价于：

```text
first_x <= m < last_x
```

所有 x 同时成立：

```text
max(first_x) <= m < min(last_x)
```

存在 m：

```text
max(first_x) < min(last_x)
```

**这一连串没有任何数据结构。**

只有把判定压成这一行后，才应该考虑如何扫描和维护。

# 九、D 给出的研究方法训练：先改写量词

以后题目出现：

- 集合相同；
- 对所有颜色；
- 每一类都至少出现一次；
- 存在一个切点；

先写逻辑式，而不是先写 map。

通用形式：

```text
存在 m，使得对所有 x，P(x,m)
```

尝试换成：

```text
max lower_bound_x <= m < min upper_bound_x
```

最后变成一个 max/min 关系。

D 就是这种题。

# 十、四题的研究差异

| 题 | 你最强的阶段 | 真正缺口 |
|---|---|---|
| A | 交换/贪心直觉 | 形式化证明 + 极简实现 |
| B | 结构发现/模式识别 | 自动反例 + 证据分级 |
| C | 从最终状态反推结构 | 时间 + 把根继续转成偏序 |
| D | 快速模拟拿部分分 | 量词改写 / 抽象判定 |

所以不能用同一种训练方式补四题。

# 十一、最值得加入赛中工具链的“研究协议”

## 1. 每个结论带标签

- `[P]` proved：证明过
- `[E]` exhaustive：小空间穷举过
- `[C]` checker contract：checker 明确保证
- `[H]` hypothesis：猜想
- `[X]` refuted：已有反例

## 2. 每个 H 必须写“如何证伪”

例：

```text
[H] B: 循环核必须是 XX
falsify: 枚举 abc 字母表 n<=10，与 [l,r] brute 比较
```

## 3. 两次结构猜想被推翻后，禁止继续手玩

必须：

- 写 brute；
- 或换题。

## 4. 先找最小反例，再看大样例

大样例用途：

- 性能；
- I/O；
- 随机覆盖。

最小反例用途：

- 研究。

二者不能反过来。

# 十二、结论

Day3 的研究过程证明一件事：

**你不是缺想法，而是缺一个把大量想法快速筛成“定理”的机制。**

最值得训练的不是“再多想 30 分钟”，而是：

> **每出现一个想法，立刻问：这是 P、E、C、H 还是 X？它的最小反例怎么自动找？**

一旦这个流程固定下来，B 这种题的研究效率会发生数量级变化。
