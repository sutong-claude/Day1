# Day3 赛时代码逐段解剖：把代码和当时思路对上

> 目标：不是重新判代码对错，而是从最终留下的源码反推“当时的研究状态”，并指出哪些行是正确想法的沉淀，哪些行是时间压力下的补丁。

# A 报数

## 1. 模板噪音

本题完全不需要。

这类模板不会直接错，但会让一个 15 行题在视觉上变成“有很多东西”。

### 对应录音

A 的核心算法 00:11 左右已经完成，后面主要在：

- sum/tot；

之间来回。

所以 A 的提升方向是**极简实现**。

---

## 2. 用 double 保存整数

```cpp
double sum = 0;
vector<double> a;
```

题目输入是整数，完全可以用 `long long`。

你当时已经在 00:33 左右开始担心：

> “平均数是个小数？”

这个担心反过来让实现更复杂。

其实整数 x：

`x > sum / t`

等价于：

`x > floor(sum/t)`。

所以直接整数除法即可。

---

## 3. 弹空后仍继续计算

```cpp
while (!a.empty()) {
    sum -= a.back();
    a.pop_back();
    tot--;
    auto it = upper_bound(a.begin(), a.end(), sum / tot);
```

最后一轮：

- a 被弹空；
- tot 变 0；
- 仍计算 `sum/tot`。

最终 OJ 100，并不代表这个路径设计合理。

**A 的教训：已经知道答案结构时，不要用“边删边算直到空”的写法制造额外边界；直接枚举 t=1..n 的前缀更稳。**

# B 翻面消除

B 的最终代码极其有研究价值，因为它几乎就是你思路演化的化石。

## 1. 第一段：原串先剥首尾

```cpp
int l = 1, r = n;
while (s[l] == s[r])
    l++, r--;
```

这正对应后半段大量手工样例里发现：

> 成功样例经常首尾能先消掉。

问题是：

**你把“约简后的共轭外壳”错误实现成“原串字面首尾”。**

正确对象应先是整个字符串的唯一约简结果。

这说明当时你已经发现“外壳”结构，但还没有把它放到正确的代数对象上。

### 另一个纯实现问题

没有：

```cpp
l < r
```

保护。

若整个串首尾一路相等，可能越界。

---

## 2. 第二段：中间做栈约简

```cpp
for (int i = 0; i < r - l + 1; i++) {
    if (!st.empty() && st.top().first == t[i])
        st.pop();
    else
        st.push({t[i], l + i});
}
```

这部分体现了一个真正正确的核心：

> 你已经完全接受“相邻相同删除 = 栈约简”。

并且你还保存原始下标：

```cpp
pair<char,int>
```

说明你已经意识到：

> 判定和构造要同时做，下标映射不能丢。

这是很好的构造题习惯。

---

## 3. 第三段：若约简为空，输出 1 1

```cpp
if (st.empty()) {
    cout << "YES 1 1\n";
    return;
}
```

由于允许 `l=r`，翻转单点等于不改变字符串。

如果原串本来就可消空，这个构造是合法的。

这部分正确。

---

## 4. 第四段：检查 R 的两半是否相同

```cpp
int p = len / 2;
int p1 = 1, p2 = p + 1;
while (p2 <= len) {
    if (R[p1] != R[p2]) ...
}
```

这就是你 `02:40～02:56` 发现的“重复块 / 正中间”最终落地。

非常接近满分条件。

但代码没有显式检查：

```cpp
len % 2 == 0
```

奇数时 `p=len/2`，比较长度并不对称。

---

## 5. 第五段：输出第二半映射区间

```cpp
cout << id[p + 1] << ' ' << id[len] << '\n';
```

这说明你最后认为：

> 只需要翻重复块的第二份。

这是正确构造思想的影子。

因此 B 65 不是“瞎写”。

它是：

> **正确抽象的 80% + 一个顺序错误 + 验证盲区。**

# C 任务领取

## 1. n<=8 的 brute 非常直接

```cpp
for (int i = 1; i <= n - 1; i++) {
    if (vis[i]) continue;
    vis[i] = true;
    d[k] = i;
    dfs(k + 1);
    vis[i] = false;
}
```

枚举所有边发布顺序。

叶子处严格按题意模拟。

这是标准、可靠的暴力。

---

## 2. `finish[]` 的语义很清楚

```cpp
bool finish[...];
```

它表示某个人是否已经领过任务。

你赛时调试时忘过一次清空，录音也明确说：

> “我忘了清空了。”

最终版已经在每个排列模拟前清空。

这属于快速调试成功。

---

## 3. 大数据直接 `(n-1)!`

```cpp
else {
    int ans = 1;
    for (int i = n - 1; i >= 1; i--)
        ans = (ans * i) % MOD;
}
```

这不是一个推导出来的算法。

它反映的是 03:37 后的真实决策：

> 时间只剩两分钟左右，尝试撞“所有发布顺序都行”的特殊数据。

结果确实撞到了一部分分，所以从抢分角度不是完全无意义。

但它不应该被视为研究结论。

# D 同类分段

## 1. 小数据分支比你口头估的更重

```cpp
for (int i = 1; i <= n; i++)
  for (int j = i + 1; j <= n; j++) {
    mp1.clear(), mp2.clear();
    for (int k = i; k <= j; k++)
        mp2[a[k]]++;
    for (int k = i; k <= j; k++) {
        ...
        for (auto y : mp1) ...
        for (auto y : mp2) ...
    }
  }
```

不是单纯 O(n³)。

最后两次遍历哈希表，在不同值多时还能再带一个区间不同值数量。

所以 n=2000 超时并不意外。

---

## 2. 这里还有一个切点边界问题

题意要求：

`l <= m < r`

但代码的第二个 k 循环跑到了 `k<=j`。

当 k=j 时：

- 右集合已经空；
- 一般不会判合法，但仍做了一轮无意义工作。

在暴力代码里这会进一步增加常数。

---

## 3. 非降序直接输出 0

```cpp
else if (special == true) {
    cout << 0 << '\n';
}
```

这是未证明特判。

最小反例：

```text
1 1
```

整个区间 `[1,2]` 可切成 `[1]` 和 `[1]`，答案至少 1。

这说明最后阶段你已经从“推导”转成“猜特殊性质”。

---

## 4. 连续相同 run 的计数还漏了最后一段

```cpp
for (...) {
    if (p == a[i])
        cnt++;
    else {
        p = a[i];
        ans += cnt * (cnt - 1) / 2;
    }
}
```

循环结束后没有：

```cpp
ans += cnt*(cnt-1)/2;
```

所以即使“只统计同值连续段”这个策略成立，最后一个 run 也会漏。

这是一种非常典型的最后几分钟 bug。

---

# 结论：四份代码对应四种不同的失败机制

| 代码 | 主要机制 |
|---|---|
| A | 算法正确，写法制造边界和 API 摩擦 |
| B | 数学结构高度接近，关键变换顺序错；checker 未覆盖 false-NO |
| C | 暴力正确，大数据是明确的时间压力押注 |
| D | 模型尚未抽象，直接模拟过重；最后无证明特判产生额外 bug |

以后复盘不能统一说“代码错了”。

必须先判断：

> 是算法模型错？证明缺？实现错？验证错？还是纯时间押注？

Day3 四题恰好四种都出现了。
