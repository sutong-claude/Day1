# Day3 正解验证报告

## 结论
最终四份正解不是“过样例就算”。采用六层验证：**证明、官方附件、全穷举、随机对拍、构造 checker、ASan/UBSan + 最大规模性能测试**。

### 1. 核心压力测试：2,245,655 组全部通过
| 题 | 验证方式 | 数量 | 独立参照 |
|---|---|---:|---|
| A | n=1..8，值域1..5全枚举 | **488,280** | 枚举全部非空子集 |
| B | 二元 n<=16 + 三元 n<=10 全枚举 | **219,642** | 枚举所有反转区间 |
| B | 随机串 n<=120，字母表2..9 | **1,000,000** | 每个 YES 真执行反转+栈消除 |
| C | n<=5 所有标号树×所有优先级 | **15,405** | 枚举全部 (n-1)! 任务顺序 |
| C | n=6/7/8 随机树+排列 | **235,000** | 枚举全部任务顺序 |
| D | n<=8 全枚举 | **87,328** | 独立 O(n²/³) oracle |
| D | n<=20 随机 | **200,000** | 独立 oracle |
| **合计** | | **2,245,655** | |

最新完整重跑：约 **6.95 秒，ALL_STRESS_OK**。

这套对拍确实抓过 bug：C 的换根比例最初写反，全穷举立刻报错；修正为
`ways[v] = ways[u] * old_hook / new_hook`
后才全绿。

### 2. 官方附件全量
- A：2 个附件，逐字输出一致。
- B：8 个文件，共 **45 test cases，Σn=4,002,026**。每组 YES/NO 与官方存在性一致；每个 YES 再交官方 local checker，全部 construction valid。
- C：8 个附件，含 n=200000 大样例，逐字一致。
- D：8 个附件，最大 n=1000000，逐字一致。

### 3. Sanitizer
最终四份代码用 ASan+UBSan 跑完全部官方附件：**无报错**。

### 4. 最大规模性能
| 题 | 规模 | wall | RSS |
|---|---:|---:|---:|
| A | n=1,000,000 | ~0.11s | ~9.3MB |
| B | Σn=1,000,000 | <0.01s | ~1.7MB |
| C | n=200,000 | ~0.07s | ~18.2MB |
| D | n=1,000,000 | ~0.60s | ~122.7MB |

这些是当前本地容器数值，用来确认复杂度数量级，不冒充 OJ 机器绝对时间。

## 关于“100%”
有限随机测试不能在数学意义上证明 100% 正确，所以这里不把“一百万组”包装成证明。可靠性来自：**数学证明 + 小规模完整状态空间穷举 + 大量随机 oracle + 官方大样例 + sanitizer + 最大规模压测**。
