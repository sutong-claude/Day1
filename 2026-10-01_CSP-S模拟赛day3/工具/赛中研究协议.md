# 赛中研究协议：把“灵感”变成可验证的结论

> 来源：Day1～Day3，尤其 Day3 B 的 155 分钟研究过程。  
> 目标：不是限制思考，而是防止“正确不变量 + 错误猜想 + checker 盲区”混成一团。

# 1. notes 中每条结论必须带标签

| 标签 | 含义 | 能否继续依赖 |
|---|---|---|
| `[P]` | 已证明 | 可以 |
| `[E]` | 小空间穷举无反例 | 可以暂时依赖，但仍需证明 |
| `[C]` | checker / 题面明确保证 | 可以，只能在保证范围内 |
| `[H]` | 猜想 | 不可当事实 |
| `[X]` | 已有反例 | 禁止继续使用 |

例：Day3 B 正确写法：

```text
[P] n 必须为偶数
[P] 栈约简结果唯一
[C] checker 会验证 YES l r 的构造合法性
[C] checker 不验证 NO
[H] 约简后的循环核是 XX
[TODO] 用 abc,n<=9 穷举 + 证明
```

# 2. 每个 H 都写“证伪程序”

不是“怎么证明它”，先写：

> 什么最小程序能把它打死？

典型：

- 存在区间 / 构造：枚举所有区间；
- 最优值：枚举全部决策；
- 树过程：n<=7 枚举顺序；
- 字符串结构：字母表压到 2～3，长度压到 8～10。

# 3. 两次结构猜想被推翻后，禁止继续纯手玩

执行顺序：

1. 写 brute；
2. 写 generator / 全穷举；
3. 自动找最小反例；
4. 再继续数学研究。

如果 10 分钟还没有 oracle：**换题。**

# 4. checker 四格契约

拿到 checker 第一件事写：

```text
YES 合法性：?
NO 存在性：?
最优性：?
格式/边界：?
```

只有对应格是 ✅，checker 的绿色结果才能支持那个结论。

# 5. “自言自语”绑定动作

| 你一旦说出 | 必须做 |
|---|---|
| “这个猜想可能不对” | 5 分钟内 brute |
| “不能猜结论了” | 停止手玩，跑 oracle；没有就换题 |
| “绝对对了” | 找证明 / 双向验证，不许直接提交 |
| “再调一会” | 看累计时间；超过 75 分钟就切 |
| “这 X 分很好拿” | 立即实现并提交 |

# 6. 75 分钟硬切

单题从正式开始计时。

到 75 分钟时若没有同时满足：

- 已有可提交分；
- 核心命题有证明或穷举支持；
- 正在明显收敛；

则：

1. 保存当前版本；
2. 提交已知部分分；
3. 写一行“回来时从哪里继续”；
4. 换题。

# 7. 最小反例优先于大样例

研究阶段优先级：

`最小反例 > 小空间全穷举 > 官方小样例 > 官方大样例 > 性能压力`

大样例主要用于最后性能和 I/O，不用于寻找数学规律。
