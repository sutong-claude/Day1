## A：健康的 100

令 x_0 表示第一个工作日前的休息日数，x_i 表示工作日 i 与 i+1 间的休息日数，x_n 表示最后一个工作日后的休息日数。

单工作日 i 的最坏连续段会把左右相邻零全部带上，因此必要条件：x_{i-1}+x_i <= a_i-1。

这也是充分条件。对任意连续工作日 p..q，把单点约束相加，内部 gap 被计两次，因此得到的约束比长区间真正需要的约束更强。

于是原题变成路径上的整数优化：最大化 Σx_j，满足 x_j>=0 且 x_{i-1}+x_i<=a_i-1。

赛时代码先给每个 gap 局部上界，再从左到右消冲突，最终 AC。

### A 代码演化

8 个独立源码状态，仅 1 个 CE：
1. 输入模板。
2. 端点 + 相邻 gap 上界；maxx 写成 x，唯一 CE。
3. 编译通过，但各 gap 独立取满，忽略一个 a_i 同时承受左右 gap。
4. 引入 x[]，开始消除局部超载。
5. 加 x0/xn。
6. 去掉端点重复统计。
7. 超载修正加 max(excess,0)，核心正确。
8. 加传统文件 IO，提交 AC。

这和 Day5 A 的大量 iterator/边界/数据结构 Debug 完全不是同一种状态。

## B：方向接近，但提交的 partial 模型错误

赛时已经看出：记录可视作点；两点有 compatibility；只向后连边，是 DAG；删最少等价于保留最长合法链。真正缺的是把 pair compatibility 代数化。

定义 F(x)=从 0 到进度 x 在各阶段都跑最大允许速率时的最短用时。记录 i<j 兼容 iff：
t_j-t_i >= F(x_j)-F(x_i)。

移项，令 g_i=t_i-F(x_i)，则兼容 iff g_j>=g_i。

所以保留记录必须组成 g 的非降子序列。首记录 g_0=0，末记录 g_end=tend-F(l)。若 g_end<0 则 -1；否则在 0<=g_i<=g_end 的中间记录中求 LNDS，答案 m-LNDS。

速度来自固定集合，LCM=277200，可全部用整数放大，满分复杂度 O((n+m)log m)。

赛时提交却用了 speed=l/tend、work=speed*t[i]，这隐含“最大速率相同 => 全程匀速”的错误命题。题目允许暂停/降速，因此这个 special 从数学上就是错的。另外循环用 i<=n 而不是 i<=m。

## C：0 分的核心是 predicate 错，不是只因为 TLE

固定一组区间，问恰好 k 盏亮是否存在稳定配置。

亮灯看到 k-1 盏其它亮灯，所以必须 k-1 在自己的区间；灭灯看到 k 盏亮灯，所以必须 k 不在自己的区间。

令 A_k={i | k-1∈I_i}，B_k={i | k∈I_i}。亮灯集合 X 必须满足 B_k⊆X⊆A_k 且 |X|=k。

因此固定 k 可行当且仅当：B_k⊆A_k 且 |B_k|<=k<=|A_k|。

赛时代码只统计“包含 k-1 的区间数”，并要求 cnt==k；它完全没处理包含 k 带来的强制与矛盾，所以第一子任务就 WA。

## 六场后的统一病因

现在最统一的一句话是：**从自然语言题意到代码之间，缺少一个数学语义契约层。**

写代码前必须明确：
1. 当前状态/变量究竟表示什么？
2. 当前 if 判定的是哪个必要充分条件？
3. 数据结构返回的对象和数学上要找的是不是同一个？
4. brute/oracle 验证的是完整题意还是只验证一半？

## 下一场新规则

在原有“冻结 partial / 20 分钟无新事实就止损”之外，新增最高优先级规则：

### 写代码前 60 秒语义检查

在 notes 写三行：
1. 对象：我要维护 / 查询 / 判定的数学对象是什么？
2. 充要性：这条条件为什么必要？为什么充分？
3. 实现契约：这段代码返回的东西和上一行对象一模一样吗？

任何一行写不出来：full 不准直接上复杂结构；partial 不准声称“XX 分到手”；先写最小反例或 brute 验证命题。

## 12. 重要补正：C 的“四分类”赛时其实已经想到了

重新逐版本读取 replay/file_changes 后确认：约 03:19～03:21，T3 源码中明确出现了对两个相邻值 k-1、k 的四分支：

- 区间同时包含 k-1 与 k；
- 只包含 k-1；
- 只包含 k；
- 两个都不包含。

这一步本身就是正确正解结构的核心。此前复盘把 C 简化为“赛时只想到 cnt==k”是不完整的。

真正断点发生在**四类的语义解释**：代码把“同时包含”和“只含 k-1”都合并为 cnt++，把“只含 k”与“都不含”都近似忽略，最后仍退化成“包含 k-1 的个数==k”。

正确语义应是：

- 同时含 k-1,k：这盏灯必须亮；
- 只含 k-1：这盏灯可亮可灭；
- 只含 k：该 k 直接不可能稳定；
- 两者都不含：这盏灯必须灭。

因此用户赛时不是没有想到四分类，而是已经走到了关键桥梁上，只差把四类翻译成 forced / optional / impossible / off。
