# Day6 研究过程深挖

> 这份不重复“题解”。  
> 重点是：**赛时是怎么一步一步想到的、哪里其实已经很接近、哪一步应该换方向。**

## 总览

Day6 的四题有一个共同特点：

> 第一眼很难直接贴算法标签。

A 看不出贪心，B 看不出 LNDS，C 看不出计数 DP，D 只能看出有数论。

所以这场最值得研究的不是“模板有没有背到”，而是：
**题面没有算法名字时，如何从最小对象开始压结构。**

---

# A 蜗蜗的休息日程

## 赛时真实链条

### 1. 第一眼想到二分

用户很早就注意到：

> 如果能插 X 个休息日，那么更少通常也能插。

因此想到“答案具有单调性，可以二分”。

这是合理的第一反应，不应该事后评价成“瞎想”。

真正的问题是：

> 就算二分告诉你“尝试插 X 个”，你仍然不会判断/构造。

所以二分没有把核心困难变简单。

**经验：**
看到单调性时先问：
“判定问题真的比原问题简单吗？”

### 2. 转去看 n=1

这是正确降维。

只有一个工作日 a_1 时：
所有能和它组成的合法连续段，最危险就是把两边所有 0 都带上。

于是得到容量直觉：

> 一个 a_i 最多能承受 a_i-1 个相邻休息日。

这里还没有贪心，只是建立“容量”语言。

### 3. 研究边界和相邻 gap

接着自然问：

- 最前面能塞多少？
- 最后面能塞多少？
- a_i 和 a_{i+1} 中间最多塞多少？

这一步把“休息日插在哪里”逐渐压成“每个 gap 放多少”。

### 4. 出现自然但错误的局部最优

对于一个 gap，单独看两边，似乎可以放到：

> 两边容量允许的最小值。

于是很自然地产生：

> 每个 gap 都单独取满，然后加起来。

这不是坏思路，反而是很重要的中间猜想。

### 5. 545 杀死局部独立

用户自己发现 5,4,5：

- 左 gap 想尽量大；
- 右 gap 也想尽量大；
- 中间 4 同时被左右使用，撑爆。

这说明：
**gap 之间不是独立的，相邻两个 gap 共享中间工作日容量。**

到这里，真正状态才出现：

> x_i = 第 i 个 gap 放多少个休息日。

然后第 i 个工作日只约束：
左 gap + 右 gap。

### 6. 为什么最后变成从左到右贪心

当处理到 i：

- 左边 x_{i-1} 已经决定；
- 当前如果超容量；
- 回头改左边会影响更早已经处理好的结构；
- 削右边既能修当前，又给下一步留空间。

因此“只削右边”是很自然的单向决策。

## 正确与赛时思路的距离

不是：

~~~text
完全不会 → 突然神来之笔
~~~

而是：

~~~text
二分
→ 判定不会
→ n=1 容量
→ gap
→ 局部最大
→ 545 反例
→ 相邻共享容量
→ 左到右贪心
~~~

这是一条很健康的研究链。

# B 蜗蜗的计算日志

## 赛时已经走到哪里

用户读懂题以后，逐渐形成：

~~~text
记录 = 点
两条记录之间可以判断兼容
只会从早到晚连
所以是 DAG
删除最少 = 保留最多 = 最长链
~~~

这个抽象已经很强。

真正卡点：

> pair 检查太多，O(m²) 怎么降？

### 赛时容易犯的下一步错误

一看到 O(m²)：
就去想数据结构、二分、优化最长路。

但更好的问题其实是：

> “这条边存在的条件，到底长什么样？”

### 正确桥梁：给每个点找自己的“拖延量”

一条日志有两个时间：

1. 实际时刻；
2. 理论最快做到这个进度的时刻。

它们的差：

> 这一路总共“拖了多久”。

合法过程中可以：
- 停；
- 慢；
- 浪费时间。

所以拖延量可以增加。

但不能减少。

因为拖延量减少，意味着后面把之前浪费掉的时间追回来了，只能靠超速。

于是：

~~~text
compatibility DAG
→ 每点一个拖延量
→ 保留序列中拖延量不能下降
→ LNDS
~~~

### 为什么用户没直接想到

因为赛时问题表面是：
“很多两两边怎么优化”。

而真正突破需要换问法：

> **边为什么存在？能不能把边条件改写成每个点自己的属性？**

这是以后最值得训练的一类变换。

## 特殊性质“所有速率相同”

赛时错误：
把“最大允许速率相同”理解成“应该以固定平均速度匀速走”。

正确理解：

> 一般情况难的是“做到进度 x 理论最快要多久”；所有速率相同后，这个量变得非常简单。

特殊性质只消掉一个困难，不会额外创造“必须匀速”的条件。

# C 蜗蜗的反馈灯阵

## 这题为什么体感最难

它同时套了：

- 每盏灯一个随机区间；
- 灯之间互相影响；
- 稳定配置；
- 集合 S；
- 期望。

第一眼没有明显算法抓手。

### 用户正确做的第一步：固定 k

用户赛时确实在研究：

> 假设最后有 k 盏灯亮，会怎样？

这是关键降维。

固定 k 后：

- 一盏亮灯看到 k-1 个其它亮灯；
- 一盏灭灯看到 k 个亮灯。

于是每个区间只需要回答：

~~~text
k-1 在不在？
k 在不在？
~~~

### 用户赛时已经写出四分类

replay 中明确出现：

1. 同时含 k-1 和 k；
2. 只含 k-1；
3. 只含 k；
4. 两个都不含。

这一步不能被复盘删掉。

### 真正缺的一步：给四类赋“角色”

不要马上 cnt++。

逐类做思想实验：

#### 两个都含
- 灭：看到 k，会想亮；
- 亮：看到 k-1，可以亮；
→ 必须亮。

#### 只含 k-1
- 亮：可以；
- 灭：看到 k，不在区间，也可以；
→ 可选。

#### 只含 k
- 亮：看到 k-1，不满足；
- 灭：看到 k，又想亮；
→ 两边都不行。
→ 这个 k 直接不可能。

#### 两个都不含
- 亮不行；
- 灭可以；
→ 必须灭。

用户赛时的四分类已经把门打开了，真正只差：
**分类 → 行为语义。**

### 为什么 n<=5 的 10 分还应该更机械

即使四分类没想清，也不该让 10 分跟着一起死。

n<=5 时完全可以：

~~~text
枚举随机区间配置
→ 枚举 2^n 个亮灭 mask
→ 逐灯照题意检查
~~~

这不需要任何新命题，是最好的真 oracle。

## 这题的迁移经验

当原始对象很多，但固定参数以后只问它几个 yes/no：

> **按行为分类，不按原始参数分类。**

# D 蜗蜗的频段配对

## 赛时第一阶段是成功的

定义非常直接：
一个询问里枚举所有 pair，算 phi(p_i p_j)，取最大。

用户把这个暴力写对了，第一档 15 全拿。

这已经是一个正确资产。

## 下一步不应先想满分

对于 n,q<=1000 的第二个 15：

最自然的问题不是：
“满分数据结构是什么？”

而是：

> 我这份正确暴力重复算了什么？

### 第一层重复
同一个 phi(x) 被不停试除。

→ 先筛 phi。

### 第二层重复
同一对 i,j 在多个 query 中反复计算。

→ pair 分数 O(1) / 预处理。

### 第三层重复
很多 query 的区间高度重叠。

→ 预处理 best[l][r]。

这是一条非常典型的：

~~~text
正确 brute
→ 消掉重复函数
→ 消掉重复 pair
→ 消掉重复区间
~~~

而不是“暴力超时 → 立刻发明高级结构”。

## 子任务分值纠正

第二档不是 1 分。

表格是 rowspan：
- subtask1：15，n,q<=100；
- subtask2：15，依赖 1，n,q<=1000。

这次解析错误已经回写跨场文档。

# 四题放在一起：这场到底训练了什么

| 题 | 赛时已经想到 | 真正缺的一拐 | 通用技巧 |
|---|---|---|---|
| A | 单调性、容量、gap | 局部最优之间的共享容量 | 反例杀“局部独立” |
| B | compatibility DAG / 最长链 | 边条件压成单点拖延量 | pair → key |
| C | 固定 k、四分类 | 分类的行为语义 | 按行为压状态 |
| D | 正确 pair brute | 一层层删重复劳动 | brute → 预处理 |

所以 Day6 不是“算法不会的一场”。

更准确：

> **四题都在考“把题目重新描述一次”的能力。**

# 下一场迁移规则

看不出算法时，优先顺序：

1. 给一个候选方案，我会不会完全照题意验证？
2. 固定哪个全局量后会简单？
3. 真正承载约束的是点、边、gap、段还是状态？
4. 一个对象对未来只有几种行为？
5. 第一猜想的最小反例？
6. 两两关系能不能变成每点一个 key？
7. 正确 brute 重复算了什么？
8. 到最后再认算法名。

这比一上来扫“DP / 贪心 / MST / 最短路 / 线段树”更适合 Day6 这种题。
