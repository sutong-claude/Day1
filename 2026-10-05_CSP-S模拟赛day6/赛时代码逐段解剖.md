## A
8 个状态从输入模板→局部 gap 上界→发现左右 gap 会共同撑爆→引入 x[]→端点统一→max(excess,0)→文件 IO。唯一 CE 是 maxx 写成 x。

## B
早期 3 个 CE 包括 t 标量与 t[] 冲突、未完成二分 helper、数组/标量混用。后 3 版能编译，但最终 special 的数学模型错误：把最大速率当作固定平均速率；另外 n/m 循环对象混淆。

## C
25 个独立版本全部编译。最终核心判定把“存在恰好 k 盏亮的稳定配置”错误化为“包含 k-1 的区间数恰好为 k”。这证明 C 的失败是 predicate/model，不是编译 Bug。

## D
先修 phi helper 的 CE，再修 i*j→p[i]*p[j]、剩余质因子、phi(1)、x>0→x>1。最终暴力数学正确，仅复杂度不足。

## 分类
- A：模型正确化 → 实现收敛 → AC
- B/C：程序可运行，但 predicate/model 错 → Debug 救不了
- D：模型正确，但复杂度不够 → 稳定 partial

## C 四分类的真实演化（补正）

Replay 的中期 T3 版本曾明确写出四个 if/else：

1. 同时命中 k-1 与 k；
2. 只命中 k-1；
3. 只命中 k；
4. 两者都不命中。

这不是无效尝试，而是非常接近正解的结构发现。失败点在于四类最后被错误压成了一个 cnt：
前两类都 cnt++，后两类不产生正确的“矛盾/强制灭”语义。

所以 C 的准确诊断不是“没有分类”，而是：
**分类正确 → 类别语义没闭合 → 又压回单计数 predicate → WA。**
