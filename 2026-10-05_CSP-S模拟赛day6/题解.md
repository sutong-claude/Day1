# A 蜗蜗的休息日程

## 1. 变量换成 gap

设：

- x_0：第一个工作日前的休息日数；
- x_i：工作日 i 与 i+1 之间的休息日数；
- x_n：最后一个工作日后的休息日数。

第 i 个工作日 a_i 左右分别有 x_{i-1}, x_i 个连续休息日。

只取“左休息日 + a_i + 右休息日”这一段，平均值至少 1，因此：

~~~text
x_{i-1} + x_i <= a_i - 1
~~~

这是必要条件。

## 2. 为什么只看单点就够

任取连续工作日 p..q。

把 p..q 的单点约束加起来：

- 两端 gap 各算一次；
- 中间 gap 各算两次。

因此加起来得到的限制比真正这整段需要的还更强。

所以所有单点约束成立，就自动保证任意长连续段合法。

原题化为：

~~~text
最大化 x_0 + x_1 + ... + x_n

满足：
x_i >= 0
x_{i-1} + x_i <= a_i - 1
~~~

## 3. O(n) 贪心

从左往右。

当 x_{i-1} 已经决定后，x_i 当然希望尽量大。

若当前左右和超过 a_i-1，就只削 x_i：
- 不破坏以前已经满足的约束；
- 还能给下一步留下更多容量。

因此可以线性处理。

## 4. partial

- n=1：答案 a_1-1；
- a_i<=200：可以做小值 DP，但实现未必比 full 更舒服；
- 本题是一个典型“partial DP 反而比 full 贪心笨重”的例子。

# B 蜗蜗的计算日志

## 1. 最小正确模型：两条日志能否共存

定义 F(x)：

> 从进度 0 做到 x，如果每个阶段都跑最大允许速度，理论最少需要多久。

两条日志 i<j 能同时保留，当且仅当：

~~~text
实际时间差 >= 从 x_i 做到 x_j 的理论最快时间
~~~

也就是：

~~~text
t_j - t_i >= F(x_j) - F(x_i)
~~~

### small partial

n,m<=20 时：
- 枚举所有 i<j；
- 能兼容就连边；
- DAG 最长路求最多保留多少条；
- 删除数 = m - 最长链长度。

O(m²) 足够。

## 2. 关键变换：拖延量

给每条日志一个量：

~~~text
g_i = 实际时刻 - 理论最快到达该进度的时刻
~~~

它表示：
“到这里为止，比全速最快方案多拖了多少时间”。

合法过程中：
- 可以暂停；
- 可以慢；
- 所以拖延量可以增加。

但拖延量不能减少：
否则就是后面把之前浪费掉的时间追回来了，只能靠超速。

因此保留下来的 g 必须非降。

原问题变成：

> 在中间日志里找最长不下降子序列。

终点和起点也必须兼容：
- 起点拖延量为 0；
- 终点拖延量为 t_end - F(L)；
- 若终点拖延量 < 0，直接 -1；
- 中间只保留能夹在起点/终点允许范围内的记录。

## 3. 所有速度相同

如果最大速度统一为 v：

~~~text
F(x) = x / v
~~~

为了避免小数，直接比较：

~~~text
v*t_i - x_i
~~~

的非降关系即可。

注意：
“最大速度相同”不等于“整个过程必须匀速”。

## 4. 满分精度

允许速度来自固定小集合，可以取所有速度的 LCM，把所有理论时间统一放大成整数。

然后：
- 预处理分段 F(x)；
- 算所有 g_i；
- LNDS。

总复杂度约 O((n+m)log m)。

# C 蜗蜗的反馈灯阵

## 1. n<=5 的真正机械 oracle

先不要四分类。

枚举当前所有控制器区间后：

1. 枚举所有 2^n 个亮灭 mask；
2. 对每盏灯统计“其它亮灯数”；
3. 如果该数落在 [l_i,r_i]，它下一刻应亮，否则应灭；
4. 检查是否和 mask 一致；
5. 若稳定，记录 popcount(mask) 出现在集合 S 中；
6. 最后算 |S|。

这个版本最笨，但最可靠。

## 2. 固定 k 后的四分类

假设最终恰有 k 盏亮。

- 某灯亮：它看到 k-1 盏其它亮灯；
- 某灯灭：它看到 k 盏亮灯。

于是一个区间只需看 k-1 和 k：

### 同时包含 k-1,k
灯必须亮。

### 只包含 k-1
灯可亮可灭。

### 只包含 k
无论亮灭都会冲突：
这个 k 不可能。

### 两个都不含
灯必须灭。

因此固定 k 可行，当且仅当：
- 没有“只含 k”的灯；
- 必须亮数量 <= k；
- 必须亮 + 可选亮数量 >= k。

## 3. 从枚举区间到计数

后续优化不再枚举每个 [L,R]。

对于固定 k，直接数：
- 有多少区间属于 forced；
- 有多少属于 optional；
- 有多少属于 impossible；
- 有多少属于 off。

这样随机区间的大空间被压成四种行为。

n<=50 时可做计数 DP。

满分方向继续利用：
- fixed k；
- 四分类计数；
- 去掉不必要的二维状态。

**核心判定已完成，完整满分代码仍待正式验证。**

# D 蜗蜗的频段配对

询问 [l,r]，求：

~~~text
max phi(p_i * p_j)
l <= i < j <= r
~~~

## 1. 第一档 15 分

每个 query：
- 枚举所有 pair；
- 直接算 phi(p_i p_j)；
- 取最大。

赛时代码这部分数学正确，已拿 15。

## 2. 第二档 15 分：n,q<=1000

注意：第二档也是 15 分；表格中的“1”是依赖 subtask1，不是分值。

这档不需要满分数论结构。

### 第一步：phi 预处理

p_i<=n，所以 p_i p_j<=n²。

预处理：

~~~text
phi[1..n²]
~~~

pair 分数 O(1)。

### 第二步：所有区间答案预处理

定义 best[l][r]。

区间 [l,r] 的最优 pair：
- 要么不含 l；
- 要么不含 r；
- 要么正好就是 (l,r)。

所以：

~~~text
best[l][r]
=
max(
    best[l+1][r],
    best[l][r-1],
    phi[p_l * p_r]
)
~~~

按区间长度递推。

复杂度 O(n²)，每个 query O(1)。

## 3. 满分数论方向

已知常用恒等式：

~~~text
phi(ab)
=
phi(a) * phi(b) * gcd(a,b) / phi(gcd(a,b))
~~~

因此 pair 分数同时受：
- phi(a)；
- phi(b)；
- gcd(a,b) 的质因子集合

影响。

赛时已经意识到 gcd 会进入结构，这个方向是有价值的。

但目前没有一份经过完整证明 + 压测的满分实现，所以仓库不把某个未经验证的数据结构方案标成“正解”。
