# A. 蜗蜗的休息日程｜100

## 1. 变量替换

把“工作日之间插多少个休息日”当变量。

令：
- `x_0`：第一个工作日前休息日数；
- `x_i`：工作日 i 与 i+1 之间休息日数；
- `x_n`：最后一个工作日后休息日数。

对工作日 i，它所在的最长连续区间会把左右两个 gap 一起吃进去。

因此必须：

[
x_{i-1}+x_ile a_i-1.
]

同时：
[
x_ige 0.
]

目标就是最大化：

[
sum_{i=0}^{n}x_i.
]

原题被压成了**路径上的整数优化**。

## 2. 为什么单点约束已经足够

对任意连续工作日区间 p..q，把单点约束相加：

[
(x_{p-1}+x_p)+cdots+(x_{q-1}+x_q)
]

内部 gap 会被算两次。

所以这些单点约束比长区间真正需要的约束更强。

因此只要每个 i 的相邻 gap 条件满足，所有长区间自动满足。

## 3. 赛时实现

赛时代码：
- 先给 gap 局部上界；
- 再从左到右消掉相邻约束超载；
- 处理两端；
- 最终首交 100。

### 这题的训练触发器

当题目说：
> 每个位置的限制由左右相邻空隙共同决定

先尝试：
> 把“位置”翻成“gap 变量”，看是否变成路径局部约束。

# B. 蜗蜗的计算日志｜赛后 full 已闭合

## 1. 赛时最重要的观察其实是对的

记录可以看成点：

[
(x_i,t_i).
]

两条记录之间存在：
> “前一条记录以后，能否合法到达后一条记录”

的 compatibility。

时间严格向后，所以天然是 DAG。

删最少记录：

[
	ext{等价于保留最长合法链}.
]

赛时真正缺的是：
> 怎样把 pair compatibility 变成一个一维关系。

## 2. 定义最短时间势函数 F(x)

令：

[
F(x)=	ext{从0到进度x，在每个阶段都用最大允许速度时的最短时间}.
]

对于 i<j，两记录兼容当且仅当：

[
t_j-t_ige F(x_j)-F(x_i).
]

移项：

[
t_j-F(x_j)ge t_i-F(x_i).
]

定义：

[
g_i=t_i-F(x_i).
]

那么 compatibility 直接变成：

[
g_jge g_i.
]

## 3. 问题变成 LNDS

因此要保留的记录必须按原顺序构成：

> `g_i` 的最长非降子序列。

边界记录也要满足。

若最终记录：

[
g_{end}<0
]

说明即使用全程最大允许速度也赶不到终点，答案为 -1。

否则只保留合法范围内的中间记录，求 LNDS。

复杂度：

[
O((n+m)log m).
]

## 4. 赛时为什么会 0

赛时 special 用了：

[
speed=l/t_{end}
]

然后：

[
work=speedcdot t_i.
]

这偷偷假设：
> 最大允许速率相同，所以实际过程必须匀速。

但题目允许：
- 停顿；
- 降速。

所以“最大速率”不等于“固定平均速度”。

这是数学 special 本身错误，不是简单 coding bug。

### 触发器

看到：
> 分段速度上限 / 最短可达时间

优先定义：
> **最短时间势函数 F(x)**

再把绝对时间减掉势函数，看能否得到单调序列。

# C. 蜗蜗的反馈灯阵｜fixed-k 判定已闭合；整体 full 仍需补

> 这一题赛时已经想到四种局部关系。真正错误是四类的**语义翻译**，不是“完全没分类”。

## 1. 固定最终亮灯数量 k

如果某灯最终亮：

它看到其它亮灯数量：

[
k-1.
]

因此必须：

[
k-1in I_i.
]

如果某灯最终灭：

它看到全部亮灯数量：

[
k.
]

因此必须：

[
k
otin I_i.
]

令：

[
A_k={imid k-1in I_i}
]

[
B_k={imid kin I_i}.
]

亮灯集合 X 必须满足：

[
B_ksubseteq Xsubseteq A_k
]

并且：

[
|X|=k.
]

所以固定 k 可行当且仅当：

[
B_ksubseteq A_k
]

且：

[
|B_k|le kle |A_k|.
]

## 2. 四类的正确语义

对每个区间，看是否包含 `k-1`、是否包含 `k`：

| 类型 | 语义 |
|---|---|
| 同时包含 k-1 与 k | **必须亮** |
| 只包含 k-1 | **可亮可灭** |
| 只包含 k | **k 不可能** |
| 两者都不含 | **必须灭** |

赛时代码已经写出过这四分支，但随后把：
- “同时包含”
- “只含 k-1”

都近似合成 `cnt++`，最终退化成：

> 包含 k-1 的数量是否恰好等于 k。

这不是正确充要条件。

## 3. 当前缺口

固定 k 的数学判定已经闭合。

但仓库当前还没有把“如何对所有 k 高效统计/输出”重新独立证明成最终 full，因此：

> **full 状态仍标待补。**

后续 AI 不得直接把 fixed-k lemma 冒充整题已经完成。

# Day6 的真正训练价值

Day6 不是“115 分，比 Day5 好一点”。

它第一次把跨场病因钉成：

```text
自然语言
→ 数学对象
→ 必要/充分条件
→ 实现契约
→ 代码
```

A 证明：
> 数学对象闭合时，实现能力完全可以支撑一遍 AC。

B/C 证明：
> 如果数学 predicate 本身错，再能 Debug 也救不回来。

因此后续写复杂代码前固定做：

1. 对象；
2. 必要性；
3. 充分性；
4. 实现是否同义。
