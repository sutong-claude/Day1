### 真正没完成的最后一步

三个部件当时是分开的：

```

+
pair compatibility
+

```

```

```

```
<=>

```

> 每个点只带一个 key，求 LNDS。

- 不会 DP；
- 不会最长链；
- 不会把日志画成点；
- 完全没想到最大速度边界。

而是：

> **没有把二元不等式做移项/势函数化，让“边关系”变成“点属性”。**

## E-D6-014｜C 最小反例闭合｜单计数 predicate 同时有假阴性和假阳性

**来源**：
- OJ C 正式提交源码 `record_6ac338254a5cd1a28f0cdeed.cpp`
- 原题题面
- Replay T3 31 个保存版本
- 2026-10-07 新写精确小空间 oracle：枚举所有区间选择 × 所有 (2^n) 灯态

### 正式提交 predicate [P/source]

对每个候选亮灯数 `k=i`，代码只统计：

```cpp
v = k - 1;
cnt = # { j : l[j] <= v <= r[j] };
if (cnt == k) ok++;
```

也就是把“区间包含 k-1 的灯数量恰好为 k”直接当成：
> 存在恰好 k 盏亮的稳定配置。

### 正确固定 k 语义：必须同时看 k-1 和 k

对第 j 盏灯定义：

```
A_j = [k-1 in I_j]
B_j = [k   in I_j]
```

如果最终这盏灯亮：
- 它看到其余 k-1 盏亮；
- 必须 A_j=1。

如果最终这盏灯灭：
- 它看到其余 k 盏亮；
- 必须 B_j=0。

于是四类是：

| A | B | 语义 |
|---:|---:|---|
| 1 | 1 | **必须亮** |
| 1 | 0 | **可亮可灭** |
| 0 | 1 | **整体不可行** |
| 0 | 0 | **必须灭** |

固定 k 可行当且仅当：
1. 不存在 `A=0,B=1`；
2. forced_lit ≤ k ≤ forced_lit + optional。

赛时代码只看 `A` 的总数，直接丢掉了：
- forced 与 optional 的区别；
- impossible 类。

这正好与 E-D6-010 的 Replay 版本历史闭合：
> 四分类曾经真实进入代码，后来为了压缩又退回单个 cnt。

### 最小期望级假阴性 [E/X]

输入：

```text
2
0 0
```

每个控制器只能取唯一的 `[0,0]`。

真实情况：
- 配置 10 稳定；
- 配置 01 稳定；
- 所以 `S={1}`，`|S|=1`。

正式 predicate：
- 对 k=1，两个区间都包含 0，所以 cnt=2≠1；
- 对 k=2，cnt(1)=0；
- 输出贡献 0。

因此：
> **真实期望 = 1，提交代码 = 0。**

这是从 `n=2` 就出现的最小全输入反例。

### 最小局部假阳性 [E/X]

固定两区间：

```
I1=[0,0]
I2=[1,1]
```

提交 predicate 对 k=1：
- 恰有一个区间包含 0；
- 因而判定 k=1 可行。

但真实枚举 4 种灯态：
- 没有任何稳定配置；
- `S=∅`。

所以单计数不仅会漏掉真解，也会凭空制造假解。

### 一个容易误导调试的“误差抵消”现象

当：
```
d=(1,1)
```
枚举 9 种区间组合后：

- 真实 `E|S| = 8/9`
- 错误 predicate 算出的期望也恰好是 `8/9`

也就是说：
> **逐实例 predicate 已经错，但总体期望碰巧抵消。**

这解释为什么只拿少量随机/期望样例看最终数值，可能产生“好像没问题”的假安全感。

### 新的验证触发器

概率/期望题中，如果最终答案是：
> 对每个随机实例先算一个离散集合/判定，再取期望

那么不能只对比最终期望。

至少要分两层：
1. **local predicate oracle**：逐实例比较集合 S / 可行 k；
2. **expectation aggregate**：再比较期望。

否则 false-positive / false-negative 可能在期望层互相抵消。
