## E-D2-002｜暴力为什么晚了约2小时

**来源**：录音自述。  
本人给出三条原因：
1. 知道错但没有小反例；

## E-D2-008｜A 对拍 oracle 边界复核｜1e4 人工截断在 generator 全域内是安全的

**来源**：
- 三包原始 `duipai_T1/gen.cpp`
- 三包原始 `duipai_T1/ac.cpp`
- 2026-10-07 独立扩域穷举复核

### generator 的真实定义域 [P/source]

`gen.cpp` 只生成：
- 二进制串；
- 长度 1..10。

因此转成整数后：
```
ans ∈ [0, 1023]
```

### oracle 的可疑点

`ac.cpp` 的真值搜索是：
```cpp
for (int i = 0; i <= 10000; ++i)
    minimize popcount(i) + popcount(i + ans);
```

`i<=10000` 是人工截断，不能因为文件名叫 `ac.cpp` 就默认正确。

### 本轮独立验证 [E]

对 generator 的完整数值域 `ans=0..1023`，逐个比较：

```
min_{0<=i<=10000}
vs
min_{0<=i<=65535}
```

结果：
- 1024 个 ans；
- mismatch = **0**；
- 扩展搜索中“第一次达到最优值”的 i 最大仅 **170**。

### 修订结论

Day2 A 后半段启动对拍后，至少在实际 generator 覆盖域里，**oracle 并没有因为 1e4 截断制造假真值**。

所以 Day2 A 的积极经验可以写得更强：
> 真正启动 brute/gen 后，这套研究工具不仅“存在”，而且在实际 generator 定义域内经独立穷举复核是可靠的。

但边界必须保留：
> 这不证明 `i<=10000` 对任意更长二进制输入都充分；oracle 的可靠性必须和 generator domain 一起陈述。

完整审计：
`tools/archive/Checker_Stress_Oracle源码审计_2026-10-07.md`

## E-D2-012｜D 第一交漏一半 mask 的原因可以精确到 vector 长度

D1：

```cpp
int t=i;
wolves.clear();
while (t != 0) {
    wolves.push_back(t % 2);
    t /= 2;
}
```

而 `isValid` 首先检查：

```cpp
wolves.size() == n
```

所以一个 mask 想真正进入语义验证，最高位必须已经到第 n 位。

也就是：
> 实际只覆盖 `i in [2^(n-1),2^n-1]` 那半个空间。

这比“少补几个0”更精确：
**漏的是最高位为0的整整一半 assignment。**

## E-D2-014｜13:40:32→13:51:49｜C 🔴｜严格不等式修成正确 30 分 brute

**来源**：

### 13:40:32：第一版把题意的“≥”写成了“>”

早期版本判断一段是否“好”：

```cpp
if (tota > totb && tota > totc)
```

而原题是：

```
红 >= 黄 且 红 >= 蓝
```

所以这不是卡常/复杂度问题，而是 predicate 本身少了等号。

最小反例甚至只有一格：

```
n = 1
s = "5"
```

数字 5 = 101，表示红=1、黄=0、蓝=1。

真实：
- 红≥黄；
- 红≥蓝；
- 单格就是好段；
- truth = 1。

旧版：
- 1 > 0 成立；
- 1 > 1 不成立；
- 输出 0。

因此旧版有明确 [X]，不能称为“已经有 30 分暴力”。

### 13:49:50：提交前约 2 分钟，predicate 被修正

`debug/main.cpp` 已改成：

```cpp
if (tota >= totb && tota >= totc) {
    f[i] = max(f[j - 1] + (i - j + 1), f[i]);
} else {
    f[i] = max(f[i], f[j - 1]);
}
```

03 包 OJ 正式 C source 的算法主体与该版本一致，只补了 traditional file IO。

OJ 结果：
- subtask #1：Accepted 10；
- subtask #2：Accepted 20；
- subtask #3：TLE 0；
- 总分：**30 / Time Exceeded**。

### 独立验证 [E]

把每格所有 7 种非空 RGB 状态全部枚举，对最终 O(n²) 版本与独立 interval-DP oracle 比较：

- n = 1..6；
- 总实例数 = **137,256**；
- mismatch = **0**。

因此本轮可以把 Day2 C 的 30 分状态写得更精确：

> [P/E] **最终提交是语义正确的 O(n²) partial；30 分来自复杂度边界，而不是碰数据。**
