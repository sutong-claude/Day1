### B 🧶（0 分，未交）

**题目本质：** 对每个 i，f(i, j) = 前 i 个串里选 j 个的最长公共前缀，求 ∑ⱼ f(i, j) xor j。

**你的思路复原：**

- 11:49 “字典树如果退化成链……难办了。**现在我能高速算出来每一个，但这复杂度差得远了去了**” ← 卡在这
- 12:45 “你不挨个算，你怎么能做到的呢？”
- 赛后你说的做法：“每插入一个串，把它顶上的全维护一遍，全部重新算改动的东西”——这就是维护 mx[d]，是对的

**你已经有的：** 设 `mx[d]` = 深度 d 上经过次数最多的那个结点的次数。那么 **f(i, j) = 最大的 d，使得 mx[d] ≥ j**。这就是你 11:45 说的“每层最大值”。

**你卡住的地方：“不把每个 f 都求出来，怎么能算出最后的值？”**

先说清楚一件事：**每个 f 都求出来了，都存在数组 f[1..i] 里，只是不重新求。**

你的算法：每插入一个串，把 j = 1..i 的 f 全部重算一遍，再加一遍 xor。一共 1 + 2 + … + n ≈ n²/2 次，n = 5×10⁵ 时是 1.25×10¹¹。

正解：插入第 i 个串以后，**f 数组里只有很少几格会变**。只改变了的格子，改的时候把和也跟着改：

- 先把这格原来的 `f xor j` 从和里减掉
- 改 f
- 再把新的 `f xor j` 加回去

没变的格子一格都不碰，它们对和的贡献原样留着。这就是“不挨个算也知道和”的全部秘密：**和是一直维护着的，不是每次重新加出来的。**

**哪几格会变？** 插入一个串，它经过的每一层只有一个结点 +1，所以每层的 `mx[d]` 最多 +1。`mx[d]` 从 m 变成 m + 1 时：

- 对 j ≤ m：本来就有 mx[d] ≥ j，没变
- 对 j ≥ m + 2：还是 mx[d] < j，没变
- 只有 j = m + 1：条件从“不成立”变成“成立”，所以 **只有 f(m+1) 可能变大，变成 max(f(m+1), d)**

所以插入第 i 个串，最多改 |sᵢ| + 1 格。所有串加起来 ∑|sᵢ| + n ≤ 1.5×10⁶ 次。

**用样例 1 走一遍**（a、ab、abc、abcd，答案 0、6、4、12）：

|---|---|---|---|---:|
| a | j=1：0 xor 1 = 1，和 = 1 | 第 1 层 mx 0→1 → f₁：0→1，和 −1 +0 | 1 | **0** |
| ab | j=2：0 xor 2 = 2，和 = 2 | 第 1 层 mx 1→2 → f₂：0→1，和 −2 +3；第 2 层 mx 0→1 → f₁：1→2，和 −0 +3 | 2 1 | **6** |
| abc | j=3：+3，和 = 9 | f₃：0→1（−3 +2）；f₂：1→2（−3 +0）；f₁：2→3（−3 +2） | 3 2 1 | **4** |
| abcd | j=4：+4，和 = 8 | f₄：0→1（−4 +5）；f₃：1→2（−2 +1）；f₂：2→3（−0 +1）；f₁：3→4（−2 +5） | 4 3 2 1 | **12** |

每一行都只动了“这个串经过的层数”那么多格。动画讲义里有样例 2 的逐步动画（8 个串、有分叉、有重复串）。

一共改 ∑|sᵢ| 次，O(∑|sᵢ|)。核心就这几行（完整代码 `正解代码/B_毛线.cpp`）：

```cpp
ans += (0 ^ i);
for (int d = 0; d <= len; d++) {
    // u 走到第 d 层的结点
    cnt[u]++;

        int j = mx[d];
```

**为什么 2×10⁵ 和 2×10⁶ 有区别（你 12:05 问的）：** 2×10⁵ 允许 O(n log²n)（二维偏序，CDQ 分治），可以拿 60 分；2×10⁶ 在 1 秒内只能 O(n) 或很轻的 O(n log n)，必须找题目的特殊结构。

**正解思路（供了解，现阶段拿 30 分就是对的）：**

1. 设 u[i] = i − f[i]，意思是“前 i 格里最少有几格不在好段里”。转移：u[i] = min(u[i−1] + 1, 所有 X[j] ≤ X[i] 且 Y[j] ≤ Y[i] 的 j 的 u[j])
2. **特殊结构：** 有红子的格子，X、Y 都不减；没有红子的格子，X、Y 都不增、且至少一个减。点 (X, Y) 每一步要么往右上走、要么往左下走，两维永远同方向
3. 往右上走时，新“看得到”的点只在一列和一行上 → 每列、每行各维护一个有序表
4. 往左下走时，u 只可能不变或 +1 → 只要判断“有没有 u 值等于当前 u 的点在左下方”→ 每个 u 值维护一条阶梯（极小点集合）
5. 只有“没红子而且没被覆盖”的格子才需要记下来

**子任务 2（全是 L，15 分）怎么做：** 左看的村民 i 要求“前面恰好 bᵢ 个狼”。从左往右，每个人两种状态：

- i 是村民：前面的狼数必须等于 bᵢ
- i 是狼：i−1 必须是村民，前面的狼数 = b(i−1) + 1

每个状态的狼数都是确定的，O(n) DP。你 12:52 说的“第一个人肯定说 0”就是这个 DP 的第一步。

**正解（供了解）：**

1. 如果知道狼的总数 W，右看的村民也能换成“前面有 W − bᵢ 个狼”，就是上面那个两状态 DP，O(n)
2. 看相邻两个村民 i → j（j = i+1 或 i+2）：
    - 都左看：b[j] = b[i] + 中间狼数，和 W 无关
    - 都右看：b[j] = b[i] − 中间狼数，和 W 无关
    - **一左一右：只有一个 W 能走**（左→右：W = b[i] + b[j] + 中间狼数；右→左：W = b[i] + b[j] − 中间狼数）
3. 所以一共只有 O(n) 条“挑 W 的边”。把每个位置“能不能从前一个、前两个村民走过来”写成 2×2 的 0/1 矩阵，线段树维护乘积；枚举 W 时只把这个 W 的边打开、看能不能走到终点、再关上。O(n log n)
4. 找到 W 后普通 DP 回溯出方案；n = 1 时一个人当狼总是合法

大样例全部用 checker 规则校验合法；和穷举暴力随机对拍 10500 组（包括判 −1）全对；∑n = 2×10⁶ 最慢 0.43 秒。代码 `正解代码/D_狼人.cpp`。

## 十一、环境两个坑（你问的）

### 1. `Syntax error: word unexpected`（11:22 和 12:31，一共约 10 分钟）

**不是你代码的问题，是文件夹名里的括号。**

- 10:18 你“下载第二遍，防止附件有用”，第二份自动叫 `problem_185(1).zip`，解压出来的文件夹名带括号
- Code::Blocks 20.03 在 Linux 上运行程序时，路径只把空格转义（源码 `compilergcc.cpp` 里的 `EscapeSpaces`），括号不管；再交给 `cb_console_runner`，它用 `system()` 调 `/bin/sh` 去执行（源码 `ConsoleRunner/main.cpp`）
- sh 把路径里的 `(` 当成语法。我在这边复现了：把 `…/problem_185(1)/T1` 交给 sh，输出一字不差是 `Syntax error: word unexpected (expecting ")")`；同一个程序放进不带括号的文件夹，正常输出 474
- 所以你当时的几个观察都对得上：“别的代码没问题”（别的文件夹没括号）、“注释掉还不对”（和代码无关）、11:30 在终端直接运行就好了、12:31 在桌面那个 `problem_185(1)` 里“又抽风了”

**怎么办：** 附件只下一遍；已经带括号就右键重命名，把 `(1)` 去掉；或者直接用终端运行。bag v2 的 `run.sh` 给路径加了引号，不受影响。

### 2. 复制粘贴失灵（10:44、12:38）

**你发现的规律是对的：复制的那个窗口关了，就粘不了。**

- Linux 图形界面（X11）里，Ctrl+C 并没有把内容存进一个公共的剪贴板，只是那个窗口声明“我手里有东西”。粘贴时，系统去问那个窗口要。窗口关了，就没人给了
- Windows 会自己存一份，所以你以前没遇到过
- 另外两个容易混的：在终端里粘贴是 **Ctrl+Shift+V**（Ctrl+V 不行），复制是 **Ctrl+Shift+C**（Ctrl+C 是中断程序）；鼠标选中文字、按滚轮也能粘贴，这是另一套“选区”，同样要求原窗口还开着

**怎么办：** 复制完先别关原来的窗口；要搬整份代码，用文件（`cp`、另存为），别靠剪贴板。

## 附四：我是怎么做出来的（你问的）

**先说实话：** 四题我都没见过。我的做法和你 13:17 以后做的是同一套：**先写暴力，再猜，每个猜想拿几千组随机数据和暴力对，错了就扔。** 区别只是我从一开始就这么做，而且我跑一千组只要几秒。C 和 D 我都猜错过好几次，是暴力告诉我错了。

| 题 | 我怎么想的 | 猜错过几次 |
|---|---|---|
| A | 认出来了：“用最少几个 ±2ᵏ 凑出一个数”是有名的问题（有符号二进制 / NAF，LeetCode 2571 就是它）。二进制加减最少项的标准做法是从低位做、记进位，就写了数位 DP。然后用 `a + b − b` 的暴力把 12 位以内全部对了一遍 | 0 |
| B | 推出来的，没靠猜：① 选 j 个串的最长公共前缀 = 字典树里“下面至少有 j 个串”的最深结点；② 每层取最大值得到 mx[d]，f(j) 就是“mx[d] ≥ j 的最大 d”；③ 问自己“插入一个串，到底有几个量变了”，发现每层 mx 最多 +1，只动一格 f；④ 用样例 1 手算一遍（就是四.B 那张表）再写代码 | 0 |
| C | 最难。先写 O(n²) 暴力，再把条件写成前缀差 X、Y（和你 12:01 想的一样）。标准做法 CDQ 分治是 O(n log²n)，2×10⁶ 在 1 秒里跑不完，只能找结构。**猜错了 4 次**，见下表。最后发现“每一格 X、Y 同涨同跌”，才找到对的做法：5000 组 0 错，再上 C++，900 组 + 大样例 + 2×10⁶ 计时 | 4 |
| D | ① 先想“如果知道总狼数 W，就是简单 DP”；② 发现 W 只在“左看的人和右看的人挨着”的地方被钉死；③ 第一版带着“所有可能的 W”往后推，结果对了，但我用程序专门去找坏数据，找到集合能涨到 14 个，最坏会变成 O(n²)；④ 换成“枚举 W，每次只打开这个 W 的几条边”，用线段树维护 2×2 的 0/1 矩阵；⑤ 第一版最坏 1.5 秒，超时，改成非递归线段树 + 剪枝，降到 0.43 秒 | 1（慢） |
