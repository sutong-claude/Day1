## 每场目录的标准结构

| 内容 | 作用 |
|---|---|
| 复盘报告.md | 比赛发生了什么：时间、策略、结果、失分 |
| 题解.md | 题本身怎么做：partial → full → 正确性 |
| 研究过程深挖.md | 思路怎么一步步长出来、在哪里拐错 |
| 赛时代码逐段解剖.md | 有 replay 时做源码版本考古 |
| 正解代码/ | 经过验证的实现 |
| 正解代码/暴力/ | 可拿子任务/可作 oracle 的机械 brute |
| 赛时代码/ | 赛中各版本，保留时间信息 |
| 原始材料/ | 归档、转写、VM/replay 说明与原始证据 |
| 动画讲义/、讲解视频/ | 需要时生成的教学资产 |

并不是每个早期 Day 都已经补齐所有栏目；缺口见 [补题队列](补题队列.md)。

## 项目维护原则

1. 原始材料与结论分开；
2. 旧结论被推翻时回写正文，不只在聊天里说；
3. 赛时思路必须以录音/replay 为准，不能只看最终代码猜；
4. 正解必须注明验证等级；
5. 未完成的 full 不包装成已证明；
6. 重要对话结论写入会话成果/，成熟后再并入长期文档。
