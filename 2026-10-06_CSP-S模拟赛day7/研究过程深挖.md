# A 兄弟

## A0 [H]：每组不断删最小

诱因：
- 限制直接按父亲分组；
- 最大化时看起来应该把小值删掉。

缺点：
- 表述偏过程化；
- 还没处理负数。

## A1 [P]：每组只关心前两大

因为每组基础最多1个，只有一个组能额外取第2个。

于是：
- 基础贡献 = 每组最大可取；
- 额外贡献 = max(各组第二大)。

## A2 [P]：负数过滤

发现 a_i 可负。

最大值：
- 负数不取；
- 每组只在正权中找前2。

最小值对称：
- 正数不取；
- 每组只在负权中找最小2个。

最终模型闭合。

### A 的研究特征

A 的每次修改都有**数学事实驱动**：
- 发现负数；
- 修选择规则；
- 再改实现。

这是健康研究。

# B 凯瑟琳的委托分组

## B0 [P]：按题意递归删点

通过手玩样例确认：

```
当前组件
→ 找 rank 最小点 x
→ x 是负责人
→ 删除 x
→ 每个新组件递归
```

这是精确题意模型。

## B1 [E]：直接组件 DFS 的 O(n²) brute

对每个剩余组件 DFS：
- 找最小 rank；
- 再递归。

赛时样例全部通过；OJ 前45也支持小规模正确性。

## B2 [X→E]：实现层 Debug

先后错误：
- 没锁父方向；
- 递归返回组件不对；
- 重新走回已处理区域。

约01:31修掉。

这类 Bug 不应该和后面的算法复杂度问题混为一谈。

## B3 [P]：瓶颈 = 重复组件扫描

赛时明确形成事实：

> DFS 本身不慢，慢的是每次 calc 重新统计组件最小 rank。

这已经是正确性能剖析。

## B4 [H]：预处理组件最小值

失败原因：

> 组件不是静态子树；前面的负责人被删除后，后续组件边界不断改变。

一个静态“某节点子树最小 rank”并不能回答动态删点后的组件。

## B5 [H][X]：直接重写递归，让统计信息跟着 dfs 走

对应保存的 1178B / 1156B 版本。

失败特征：
- 代码结构本身已经出现 root/mi 语义错位；
- 说明数学状态没有定义清楚就开始重写。

本人很快识别失败并回滚。

这是**正确止损动作**。

## B6 [E]：稳定 brute 冻结

01:53 单独保存 `WA.cpp`。

这一动作以后应保留。

## B7 [H]：线段树 / 树上结构 / 换根

目标仍然是：

> 给一个当前连通块，快速得到其中 rank 最小点。

但问题在于“当前连通块”由历史删除决定。

继续在正向时间维护，等价于动态删点后处理组件分裂，本身就难。

## B8 [H]：离线

第二轮研究已经说出：

> 不模拟这件事，能不能离线处理。

这是本场 B 最接近正解的时刻。

## B9 [P]：赛后关键翻转——时间反演

正向：

```
删除负责人
→ 一个组件分裂成多个
```

倒放：

```
逆序加入负责人
→ 多个组件合并
```

树上每个已激活邻接组件恰好对应正向删除后的一个下级组。

DSU 根维护该组件当前最高优先级负责人。

于是：
- 每个组件负责人向 v 汇报；
- 合并后 v 成新根。

O(n α(n))。

### B 真正应该沉淀的触发器

不是“学会并查集”。

而是：

> **固定删除顺序 + 连通块分裂难维护 → 试倒放。**

# C 砂糖的培养方案

## C0 [H]：概率博弈太复杂，先看特殊性质

这是正确策略。

## C1 [P]：v=50

当高优先级获胜概率 p=1/2：

- 每一场无论谁高谁低，目标方案胜率都是1/2；
- 配对策略失效；
- 冠军需要赢 r 场。

所以：

[
P=2^{-r}
]

这是赛时真正已经完成的10分性质。

## C2 [P,赛后]：极端排名15分

L=R=1 或 L=R=2^r：
- 全局最高：p^r；
- 全局最低：(1-p)^r。

这是赛后很容易补出的性质，但**不要标成赛时已知**。

### C 的研究教训

扫特殊性质是有效的。

失败点不是“没找到分”，而是：

> 找到 C10 后没有立刻物化。

# D 提纳里的巡林路线

## D0 [P]：N≤100 brute

很快得到：
- 枚举叶子对；
- 还原路径；
- 求所有点到路径的最大距离 H；
- 更新 H×dist 与计数。

这是完整19分方向。

## D1 [H]：能不能把 N³ / N² 暴力提升到5000

这个追问本身合理。

错误在顺序：

> D0 还没写成稳定资产，就直接进入 D1。

## D2 [H]：围绕某个节点/分支高度组合的5000公式

最终候选版本试图把路径拆成：
- 一个“父方向”最大距离；
- 两个“子方向”最大深度；
- 用乘积拼答案。

诱因：
- 树直径/两条分支类问题常能通过 top2 深度解决；
- 目标也包含“路径长度 × 到路径距离”。

但这里真正优化对象是**一条任意叶子路径的整条集合**，H 依赖“所有点到整条路径的距离”，不能由一个局部中心的几条高度简单决定。

因此局部 top2 信息不闭合。

## D3 [X]：样例/运行直接打出错误值

经过大量实现修补后，错误仍存在。

本人最终没有把错误归咎于“还有一个 Bug”，而是说：

> “证明算法不可行。”

这其实是正确的模型止损。
