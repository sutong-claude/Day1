# 四、A《兄弟》：35分钟 AC，但不是“一眼秒题”

## 4.1 第一代思路：删掉每组小的

读题后很快看出：

- 兄弟只由父亲决定；
- 平时每组最多保留一个；
- 全局只有一个组可以额外保留一个。

最初语言是“把每组最小的删掉”。

这虽然不是最终表达，但已经抓住了**分组容量**。

## 4.2 第二代：每组只需要前两大

很快继续压缩：

- 每组第一大一定是基础收益；
- 如果要使用全局那一次“多一个兄弟”的权限，只需要看该组第二大；
- 最终额外取所有第二大中的最大值。

## 4.3 第三代：发现负数，数学规则修正

约14分钟重新看数据范围，发现有负权。

于是最大值不是“每组必须取一个”，而是：

- 只取正数；
- 根节点也只在正时加入。

最小值对称：
- 只取负数；
- 每组先取最负；
- 全局再补一个第二负。

这一步很重要：

> 你不是“代码 patch 负数”，而是先修正了数学选择规则，再改代码。

## 4.4 实现 Debug

后面还经历：
- priority_queue 大小根方向；
- 大样例运行；
- 第二答案不对；
- 一个“少写等号”类实现问题。

36分钟左右两个样例全过，随后提交，一交100。

### 对 A 的能力评价

A 现在应标为：

> **建模速度快 + 能主动重读约束 + 能把最大/最小做成对称结构 + 实现 Bug 可在短时间内自愈。**

## 5.6 第二轮 B：02:44 已经摸到“离线”

你后来重新审查为什么当前方案难优化，开始否定“在当前模拟框架里修 calc”的思路。

录音已经出现：

> 不直接模拟这件事，能不能“离线或者啥处理”。

这距离正解其实很近。

真正缺的一步是：

```
正向：
按 p 删除点
→ 连通块不断分裂
→ 很难动态维护

倒放：
按 p 逆序加入点
→ 连通块不断合并
→ DSU
```

所以这题最准确的评价：

> **你已经做到“正确 brute + 复杂度定位 + 试图换框架 + 想到离线”，只差“时间反演”这个算法触发器。**

## 5.7 最终 45 / RE 的技术原因

最终稳定版仍有两个层级问题。

### 时间层

每次删除负责人后，重新遍历每个新连通块找最小 rank：

[
n+(n-1)+cdots=O(n^2)
]

### 内存层

`calc()` 还把整个组件塞入 `unordered_set`：

```cpp
unordered_set<int> mp;
calc(y, mp, ...)
```

这个集合后续完全不用。

递归深时，上层 set 还活着，下层又建立新 set，内存可非常夸张。

这很好解释最终：
- 前两档 45 分过；
- 大数据 227.2 MiB；
- RE。

但赛时认知问题仍然不是“没看出 calc 慢”。
