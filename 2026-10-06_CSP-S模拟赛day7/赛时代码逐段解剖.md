# 3. B 的 unused unordered_set：要正确归因

`calc`：

```cpp
inline int calc(int root, unordered_set<int>& st, int fa, int mi) {
    st.insert(root);
    ...
}
```

调用：

```cpp
unordered_set<int> mp;
int m = calc(y, mp, root, n + 1);
dfs(root, m);
```

但 `mp` 从不读取。

因此它纯粹增加：
- 哈希桶；
- 节点分配；
- 递归层同时存活内存。

这很可能是 227.2MiB RE 的直接放大器。

但是：

> 删除它不等于满分。

因为 `calc` 重扫组件仍是 O(n²)。

## D1：03:48完整候选

文件：

`赛时代码/历史版本/D_5000候选_03-48.cpp`

它做：

1. `calc(1,0)` 建 parent；
2. 枚举每个 i；
3. 尝试从 `fa[i]` 往外算一侧最大距离 `ma`；
4. 对 i 的其他邻接分支算深度；
5. 取最大两条 `ma1,ma2`；
6. `tot=ma1+ma2`；
7. `res=ma*tot`；
8. 更新答案和计数。

这是一套具体的“把最优叶子路径拆成局部几条分支高度”的猜想。

## D2：为什么这个模型诱人

树上大量题：
- 直径；
- 经过某点的最长路径；
- 去掉一点后的最大深度；

都可以靠 top1/top2 分支深度。

而本题目标：

[
H(A,B)cdot dist(A,B)
]

看起来也像：
- 一部分控制路径长度；
- 一部分控制离路径最远高度。

所以想按某个中心 i 用几个分支高度组合，并不荒唐。

## D3：真正不闭合的地方

H 是：

> **全树所有点到整条 A-B 路径的最大距离。**

它依赖整条路径经过哪些点，而不是只依赖一个局部中心的三条高度。

两个候选叶子路径可能：
- 在 i 附近局部高度完全相同；
- 但经过远处不同支路；
- 导致 H 不同。

因此“局部 top2 + 父方向最远”的状态不足以决定目标。

这就是模型层缺信息。

## D4：为什么 Debug 很久后才判死

因为候选代码本身同时有：
- parent/dfs 实现细节；
- d[] 初始化；
- top1/top2；
- 递归返回值；

这些实现 Bug 会制造一种错觉：

> “也许数学对，只是代码没按我说的跑。”

所以03:33～03:49大量 Debug 的真正危险不是 Debug 技术差，而是：

> **一个未证明的数学模型和一堆实现 Bug 混在一起，无法知道当前错误到底来自哪层。**

最终03:51本人说“证明算法不可行”，才完成层级切换。
