# 3. T2：从正确 O(n²) 到 full 失败，再安全回滚

## v1 ～ v8：搭出定义直译递归

核心状态逐渐稳定为：

- a[x]：节点 x 在排列中的 rank；
- vis[x]：x 是否已经被选为某级负责人；
- calc(component)：扫当前剩余组件，找 rank 最小节点；
- dfs(boss, mi)：以 p[mi] 为当前负责人，删除它，递归各组件。

早期最大 Bug：
calc 没有 father，树上会沿边来回递归。

约 91 分钟加入 fa 参数后解决。

它之后被保存成 T2/WA.cpp。

这说明“冻结版”并非临结束抢救，而是赛中真的留下了可回滚点。

# 4. B 最终 RE 的具体实现原因

最终 calc：

~~~cpp
inline int calc(int root, unordered_set<int>& st, int fa, int mi) {
    st.insert(root);
    mi = min(mi, a[root]);
    ...
}
~~~

但 st 的内容在调用返回后根本没有任何用途。

这是历史版本残留。

调用侧：

~~~cpp
unordered_set<int> mp;
int m = calc(y, mp, root, n + 1);
dfs(root, m);
~~~

问题：

1. mp 收集整个组件，哈希节点单个开销远大于 int；
2. 深层 dfs 递归返回前，上层 mp 仍然存活；
3. 在链/特殊优先级结构上，可能同时保留规模近似 n + (n-1) + ... 的集合；
4. 递归本身最坏也可深到 O(n)。

OJ 隐藏 subtask3：
- #3-1 AC，62.3 MiB；
- #3-2 RE，227.2 MiB；
- #3-3 AC，33.1 MiB；
- #3-4 RE，227.1 MiB。

这高度符合“结构相关的内存峰值”而不是随机语义错误。

即使删除 unordered_set：
- 会大幅降内存；
- 但每层仍重新 DFS 扫组件；
- 时间最坏 O(n²)；
因此只能是更强 partial，不是 full。

# 6. T4：20 个源码状态，但模型从未被证明

T4 第一份代码约 207 分钟才出现。

核心尝试：

1. 固定 1 为根，求 father；
2. 枚举某个点 i；
3. 算 i 外侧的最远深度 ma；
4. 算 i 各子树向下最深两条 ma1,ma2；
5. 用 ma × (ma1+ma2) 一类式子尝试代表答案；
6. 不断修：
   - 距离起点；
   - 是否 +1；
   - 排除 father；
   - 两个最大值相等时的更新；
   - 计数重复；
   - 根/叶边界。

代码版本数很多，但这些修复都建立在同一个未证明模型上。

最后：
- 样例/手算持续对不上；
- ~3:51 用户主动判定算法不可行；
- v20 直接重置成：

~~~cpp
for (int i=1;i<=n;i++)
    for (int j=i+1;j<=n;j++) {
    }
~~~

这证明：
**D 的主要损失不是“最后一个 Bug 没调出来”，而是模型本身不等价。**
