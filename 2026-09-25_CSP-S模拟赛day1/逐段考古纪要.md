# Day1 逐段考古纪要（append-only）

> Day1 是仓库里最早的一场，已有录音转写/VM/草稿证据，但还没有 Replay v3。以下先把现有复盘中已经能由多源证据支持的关键节点拆出来；以后找到更原始材料继续追加。

## E-D1-001｜T+00:03～00:06｜A 记录带｜核心点对变化其实很早就推对

**来源**：录音 + 草稿。  
**[P]** 翻转 [l,r] 后：
- 区间内部顺序对/逆序对互换；
- 跨区间边界的点对相对先后不变。

因此净收益只取决于区间内部点对。

**结论**：Day1 A 不是“完全不会逆序对”，而是核心数学观察 6 分钟内已经出现。

## E-D1-002｜T+00:06｜全场最贵的一次漏范围

**来源**：录音 + 题面。  
**当时判断 [X]**：按 T×n 估成巨大规模，认定必须 O(n)。  
**被漏条件 [C]**：全局 ∑n ≤ 8000。  
**后果**：本来可接受的 O(n²) 被过早排除，近 2 小时追一个不存在的复杂度目标。  
**迁移触发器**：复杂度估计必须把题面最后一行“总和范围”单独抄进 notes。

## E-D1-003｜T+00:58｜输出超过理论上限，却继续修符号

**来源**：录音。  
**现象**：n=5 时逆序对最多10，程序却得到20。  
**证据 [X]**：这已经不是正负号/初值问题，而是公式结构错误。  
**当时行为**：继续互换 lst/rst、改符号。  
**结论**：遇到答案超理论上限，应立即停局部 patch，写最小 brute / 重建公式。

## E-D1-004｜T+01:54｜终于发现 ∑n≤8000

**来源**：录音。  
**意义**：此时正确 O(n²) 路线重新合法。  
**后续**：写出了固定端点增量 + multiset 的正确方向。  
**问题**：std::distance(multiset iterator) 是线性，导致整体接近 O(n³)。  
**结果**：A 20 TLE。  
**迁移**：在 STL 上写 distance 前先确认 iterator category；“前面有几个比我大”默认考虑 Fenwick/离散化。

## E-D1-005｜T+02:18～02:41｜B 联动面板｜checker 被读了，但判定核心没提炼出来

**来源**：录音 + checker.cpp。  
**checker事实 [C]**：可行当且仅当对所有 i，a_i≤i。  
**赛时**：已经读 checker、画 i→a_i 图，却没有把 feasible 函数变成定理。  
**结果**：只写两类特判，25分。  
**结论**：构造题拿到 checker 后，先搜索 feasible/impossible/NO 路径，不要只看输出格式校验。

## E-D1-006｜T+02:48～03:04｜D 轮换密钥｜模型其实已经推到质因子/小凯入口

**机会成本**：完全背包就能覆盖前45分，但最后未形成提交。  
**结论**：Day1 最大问题不是没有算法直觉，而是不会把“模型已经够拿分”及时降级成部分分实现。

### v1→v2：是输出协议修正＋枚举边界修正 [P/source diff]

`T2_2.cpp` 的非 identity 分支**缺少** `cout << "YES" << '\\n'`；在 v2 补上。同时计数循环与实际输出循环的上界均从 `i<=n-1` 改为 `i<=n-2`。其余 general 构造主体未重写。

这说明此阶段主要修复了“输出 verdict/构造长度”层面，而**不能**解释为此时已经解决 general feasibility。

### v2→v3：只加两个 tiny-case special [P/source diff]

v3 在非 identity 的 `YES` 分支前插入：

```cpp
if (n <= 2) { cout << 1 << '\\n' << 1 << '\\n'; return; }
if (n <= 3) { cout << 3 << '\\n' << "1 1 1" << '\\n'; return; }
```

其他算法主体一致。尤其 `ok2`（全部 `a_i==1`）三代都算了，但未用于任何控制分支；它表明源码**检测**了 all-ones 性质，却不代表该性质已变成正确的 general 判定。

### 交付对应 [P/source equality]

OJ B 正式源与 v3 **仅差末尾一个换行字符**：去掉末尾换行后逐字完全一致。于是可以准确写为：

> “OJ scored algorithm body 等于这份 10:37:22 的 v3；不是某份不知名的赛后补题代码。”

严格说原始字节 hash 不相同，不可误写成 byte-identical / exact SHA match。

### 已有回归与 OJ 结果相互独立的支持 [E / OJ]

此前 E-D1-009 的 48 case 重放已发现：v2→v3 使 all-ones 子任务从 11/14 变成 14/14；正式 OJ #3 = Accepted 15，#2 identity = Accepted 10，总得分 WA25。**这是可以闭合整组分数的有效 partial patch，而不是 full 构造证明。**

### general 判定的最小反例 [X/source]

v3 仍对任何非 identity 输入无条件打印 `YES`。例如合法非降输入 `n=2, a=[2,2]`，位置 1 的值 2 已无法减小，最终必不可能成为 `[1,2]`；但程序选了 `n<=2` 固定输出。故此路线 general 不正确，不得把 25 分称为可推广的稳定 general 算法。

### 赛时语音/屏幕证据边界

**本节点没有与每次代码保存一一对齐的原始语音或屏幕帧。** 不能补写“用户在 10:24 说了什么”、不能把“改码原因”当作已被录音证实。当前可证的是源码状态、文件时间、OJ 正式字节与分数。

### 下一场触发器

1. 非 identity 的构造分支必须先调用/证明 `feasible`，禁止 `YES` 一律输出后再靠 tiny-case 特判补丁。
2. 对 group partial，固定三行状态：`已满足输入性质 → candidate 已验证 → 整组全过`，达到组级闭合就冻结，不因它不是 full 而贬值。
3. 保存并比对最后编译源码与 OJ source；即使只差末尾换行，也在证据表里写 **normalized exact**，不是 byte exact。


## E-D1-012｜Day1 A 的数学错误已在提交前修复；最终失分应与复杂度分开

**原始来源**（01包 → `虚拟机(2).zip` → `虚拟机/Desktop/CSP-S/Day1/`）：

- `problems/T1.cpp`：ZIP mtime 2026-09-25 **08:48:18**，SHA-256 `b57d970c5785397cf61b1c54c1f53b1968a181fdf4540204b406093e260e35cc`，旧 `lst/rst/ma` 前缀差分公式；
- `problems/T2.cpp`：ZIP mtime **09:10:14**，SHA-256 `e9e6dd1dafc94613493a857adadf573eac2deef50e7a5e37dcbef121c5669335`，固定左端点、逐右端点显式维护 `x/y` 的版本；
- 03包 → 2026-09-28 Day1 OJ 完整归档 → `03_我的提交/A_A 蜗蜗的记录带/record_6ab6745fb8c09340fef1c02c.cpp`：正式 source，SHA-256 `f5a400409d9b8bf271439c5281c73e649860fd8e08752d63a9059379737adc97`。

OJ source 与 `problems/T2.cpp` **只差末尾换行**，去末尾换行后逐字一致；此时正式 submitted model 已经不是旧前缀差分公式。此前 OJ 结果 A20 / TLE 不变。

### 第一次模型（08:48）[X/E]

它用 `lst[i]` 表示前缀逆序对、`rst[i]` 表示前缀正序对，然后尝试通过

`res = (rst[i]-lst[i]) + ma`

求最佳翻转增益。这种拼接不能正确处理被选区间与之前前缀之间的点对。

**本轮重新编译原版，并以独立 `O(n^4)` 小规模真值（直接翻转所有区间、对每个结果按点对枚举逆序）对拍**：

- n=2..7 的全部排列 **5,912** 例；
- 08:48 旧版 **3,518** 例与真值不符；
- 字典序最小反例 n=3，`[3,1,2]`：
  - 原版输出 2；
  - 正确最大逆序对 3（翻转整个区间可得 `[2,1,3]`? 注意本例取右端点不同的区间；实际最优请以机械 oracle 为准）。

**修订注意**：以上括号只是解释性尝试，不依赖其示例作为正确性证据；反例以原版/机械 oracle 的实际输入输出为准。

### 提交模型（09:10）[P/source + E]

新代码对每个 `l` 重新开两个 `multiset`，右端点 `r` 增加时分别累计：

- `x`：区间内逆序点对数；
- `y`：区间内正序点对数；
- `now = 全局原逆序对 - x + y`。

这是直接由“翻转只交换区间内部正序与逆序点对”推出的正确公式；而且本轮重新编译该 VM 原版，在同一 **5,912** 个排列上全部与独立 brute 一致（**0 mismatch**）。

因此这场 A 的历史不能缩成：

> “最终是因为前缀差公式错了而失分。”

更准确是：

```text
08:48 错误前缀拼接（3518/5912 小空间错误）
  ↓ 版本更替（保留源码）
09:10 显式枚举区间的正确数学模型（0/5912 小空间错误）
  ↓
OJ 正式提交主体与 09:10 VM 版本一致
  ↓
同一份算法仍用 std::distance(multiset iterator)
  ↓
对每个 (l,r) 做线性距离计算，最坏 O(n³)
  ↓
A20 / TLE
```

其中 `std::multiset` 为双向迭代器；`std::distance(it,end)` 是线性遍历，并不会因 `upper_bound` 是对数就让整句查询成为 `O(log n)`。

### 最后证据边界和触发器

本节点**没有一一对应的原始语音/屏幕帧**证明每次保存时用户的口头推理，不能把“为什么决定改写”写成用户原话。ZIP mtime 只能确认保留下来的文件状态时间。

**下一场触发器**：
- 从猜想公式改为定义级区间枚举并通过 brute 后，立即**单独**估算循环内每个 STL 操作的复杂度；
- 看到 `distance(set/multiset.lower_bound(x), end)`，必须标记 **线性**，改为 Fenwick / 平衡树 order statistics 或重排扫描消去查询；
- 算法正确性 [P/E] 与得分可行性 [C/TLE] 两张证据表分开维护。
