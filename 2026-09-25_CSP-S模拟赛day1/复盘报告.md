## 四、逐题复盘

### A｜蜗蜗的记录带（20 → 本可以 100）

**题目本质**：翻转一个区间以后，逆序对最多是多少。∑n ≤ 8000，所以 O(n²) 就够。

**你想对的部分**（录音 16:26 至 17:49，草稿纸 1）：
- 翻转 [l, r] 后，区间内原来的顺序对全变成逆序对，逆序对全变成顺序对
- 一个在区间内、一个在区间外的点对，以及两个都在区间外的点对，都不受影响
- 所以净收益 = 区间内顺序对数 − 区间内逆序对数，也就是你写的 x − y

这是整道题的核心结论，你 6 分钟就推出来了。

#### 偏差 1：漏读 ∑n ≤ 8000（最贵）

录音 18:24 你按"T 最多 10⁵，n 最多 8000"估了 8×10⁸，于是认定必须 O(n)。数据范围最后一行写着 `∑n ≤ 8000`。一旦看到它，O(n²) = 6.4×10⁷，完全够。

这一句把你带进了一条根本不存在的路，吃掉约 1 小时 50 分。

#### 偏差 2：前缀逆序对相减 ≠ 区间逆序对

你的公式（草稿纸 1）：

> 区间 [i, j] 的收益 = (rst[j] − rst[i−1]) − (lst[j] − lst[i−1])，其中 lst/rst 是前缀逆序对数/前缀顺序对数

**为什么它看起来对**：前缀和相减求区间和，这个套路你用过很多次。

**为什么不成立**：前缀和相减只对"每个元素自己贡献的量"成立。逆序对是**点对**。

用 P(r) 表示 [1, r] 里的点对数，那么：

> P(r) − P(l−1) = [l, r] 内部的点对 **+ 一端在 [1, l−1]、一端在 [l, r] 的跨界点对**

跨界点对被算进去了，公式就错了。

**最小反例**：`[3, 1, 2]`
- 正确答案是 3：翻转 [2, 3] 得到 [3, 2, 1]
- 你的最终版输出 2
- 原因：区间 [2, 3] = [1, 2] 里有 1 个顺序对、0 个逆序对，真实收益 +1。但前缀相减会把位置 1 的 3 和 1、2 组成的两个跨界逆序对也算进来，得到 −1

我用全排列暴力测了你的最终版：n=3 错 1/6，n=4 错 7/24，n=6 错 378/720。

`[2, 1, 3, 4]` 更离谱：你输出 6，可 n=4 最多只有 6 对，而正确答案是 5。**输出超过理论上限，就说明公式本身是错的，不是正负号的问题。**

这正是你 T+0:58 遇到的"怎么出现 20 了"，当时就该停下来重新建模。

#### 偏差 3：草稿纸和代码里 lst 的含义是反的

- 草稿纸 2 写的是：**"顺 lst 0 0 2 / 逆 rst 0 1 1"**
- 代码里 `lst[i] = lst[i-1] + num`，num 是前面比我大的个数，所以 **lst 是逆序**

录音里你前后四次说"我搞反了"（1:14:04、1:20:06、1:21:04 "我把一开始那个 bug 又改了回来"、1:35:36），每次都在两套定义之间切换。

**规则：变量含义写在代码第一行注释里，草稿纸和代码用同一个名字。**

#### 偏差 4：`std::distance` 在 multiset 上是 O(n)

你在 T+1:56 改写的 O(n²) 版本，思路完全正确：枚举左端点 i，右端点 j 往右扩，边扩边维护区间内的逆序对。

问题出在 `distance (st1.upper_bound(a[j]), st1.end())`：
- set/multiset 的迭代器只能一步一步走，distance 是 O(距离)，不是 O(log n)
- 整体接近 O(n³)
- 就算没有 distance，multiset 的插入常数也很大：p_i = i 的数据里 distance 每次是 0，n=8000 照样跑 **6.1 秒**，所以子任务 2 也挂了，最终只拿到子任务 1 的 20 分

**实测**（和赛时同一份代码，在一台正常的 4 核服务器上跑）：

| 大样例 | n | 你交的代码 | 只换树状数组 | O(n²) 正解 |
|---|---:|---:|---:|---:|
| 1 | 100 | 0.009s | 0.006s | 0.007s |
| 2 | 多组全递增 | 0.34s | 0.03s | 0.02s |
| 3 | 2000 | **9.2s** | 0.02s | 0.01s |
| 4 | 5000 | **>60s** | 0.20s | 0.06s |
| 5 | 8000 | **>60s** | **0.57s** | 0.11s |

两份代码都在 `正解代码/` 里：
- `A_记录带_赛时代码只换树状数组.cpp`：你的原结构，只把 multiset 换成树状数组，约 15 行改动
- `A_记录带_On2.cpp`：纯 O(n²)

#### 正解（O(n²)，不需要任何数据结构）

设 inv(l, r) 为区间 [l, r] 的逆序对数。固定右端点 r，让 l 从 r−1 往左走，用 cnt 累计 [l, r−1] 里比 a[r] 大的个数：

> inv(l, r) = inv(l, r−1) + cnt

用一个一维数组 f[l] 存 inv(l, 当前 r)，每次加 cnt 就行。收益 = C(len, 2) − 2·inv(l, r)。答案 = 原逆序对数 + max(0, 最大收益)。

**下次识别信号：**
- 数据范围里出现 `∑n ≤ X` → 复杂度按 X 算，不按 T × n 算
- "区间里的点对统计"（逆序对、相等对等） → 不能前缀相减，要么固定一端增量维护，要么二维 DP
- 要"前面有几个比我大" → 树状数组，不是 set

### B｜蜗蜗的联动面板（25 → 本可以 40，满分可达）

**题目本质**：构造题。先判断有没有解，再构造操作序列。

**你当时的状态**：
- 找到两个正确的必要条件："A_n 必须 ≤ n"、"a_1 只能被值为 1 的人改"
- 把问题建成图 i → a_i（草稿纸 3、4）
- 读了 checker（录音 2:51 "这个 checker 看明白了"）
- 最后特判 a_i = i 和全 1，拿了 25 分
- 你的代码**永远输出 YES**，所以所有有 NO 的子任务都拿不到

#### 被错过的最大信号：checker 里直接写了判定条件

你下载的 `checker.cpp` 第 17 到 22 行：

```cpp
static bool feasible(const TestCase& tc) {
    for (int i = 1; i <= tc.n; ++i) {
        if (tc.a[i] > i) return false;
    }
    return true;
}
```

**有解当且仅当对所有 i 都有 a_i ≤ i。** 你当时在找"第一个 NO 为啥"，答案就写在这 6 行里。

**以后拿到 checker，第一件事就是搜 `NO` / `feasible` / `impossible` 这几个词。**

另外 checker 还校验了 `K == n(n+1)/2 − Σa`，说明操作次数是固定的。题面里的 K ≤ n(n−1)/2 其实是自动满足的，不是需要你去控制的限制。

**为什么是 a_i ≤ i（必要性）**：数值只增不减。如果某个 a_i > i，由于数组有序，位置 i 到 n 这 n−i+1 个数最后都 ≥ a_i ≥ i+1，但 [i+1, n] 里只有 n−i 个不同的值，塞不下。这是抽屉原理。

我用暴力搜索验证过：n ≤ 7 的全部 2353 个有序数组，这个条件和"是否有解"完全一致。

#### 正解构造：归纳 + 链式上推

归纳假设：前 i−1 个位置已经变成 1 到 i−1 的一个排列。现在加入位置 i，它的值是 t = a_i ≤ i。
- 如果 t = i，直接成立
- 否则值 t 出现了两次（原来的持有者，加上位置 i），值 i 还没人有。按 v = t, t+1, …, i−1 的顺序，每次把"原来持有 v 的那个位置"加 1，推到 v+1

**为什么每一步都合法**：推的时候，1 到 i−1 这些值始终都有人持有（被推走的那个值，由刚推上来的那个位置或位置 i 顶上）。要给位置 x 加 1，需要有人的值等于 x，而 x ≤ i−1，一定有人持有。

总操作数正好是 Σ(i − a_i) = K，复杂度 O(n²)。代码见 `正解代码/B_联动面板.cpp`。

验证：
- 5 组大样例全部通过（用 checker 的逻辑逐条模拟）
- n ≤ 8、值不超过 n+2 的全部 33097 个数组，全部通过

**你能拿但没拿的分**：
- 子任务 1（∑n ≤ 8，15 分）：直接 DFS 搜索，状态最多 8⁸ 个，还能剪枝
- 你的 25 分再加 15 分，就是 40

- 构造题先解决判定：写暴力、打表、看 checker
- "所有数只增不减 + 最后变成排列" → 想抽屉原理

### C｜蜗蜗的晶体树阵（0 → 本可以 70，满分也不难）

**题目本质**：以 k 为根的树形 DP。"强共振需要一个核邻居"这一类，就是经典的"保安站岗 / 最小支配集"型三状态 DP。半径 L 只影响深度 ≤ L 的点。

**你当时的状态**：看了 6 分钟（T+2:41 至 2:47）。判断"八成是换根""感觉像 DP 但难写"，然后去看 T4。T+3:40 回来翻大样例，发现"后面输出都是同一个数……估计就是达到上限了"。

**这个观察是对的**：L 超过最大深度以后，所有点都在半径内，答案固定为 Σmax(m, w)。这正是子任务 2 的解法，你已经看出来了，只差把它写成代码。

**偏掉的地方**：
- **不是换根**：根是固定的（调谐器接在 k），直接以 k 为根就行
- **子任务 1、2 都是送分题，各 10 分，各一行代码**：
  - 子任务 1（w_i = 1）：m_i ≥ 1 = w_i，共振永远不比恒稳亮，当核更是 0，答案恒为 Σm_i
  - 子任务 2（q=1 且 L=n）：所有点都在半径内，都能自由共振，答案是 Σmax(m_i, w_i)
- 子任务 3、4（n, q ≤ 5000）：每次询问重做一遍 O(n) 的 DP，O(nq) = 2.5×10⁷，拿 10+40 = 50 分
- 加起来 70 分

**正解（O(n + q)）**：以 k 为根，对每个点 v 求：
- `g0(v)`：v 的父亲**不是**核时，v 子树的最大亮度
- `g1(v)`：v 的父亲**是**核时（或者 v 在半径内，可以自由共振），v 子树的最大亮度
- `core(v)`：v 自己当核，= Σ g1(儿子)

转移：
- g0(v) = max( core(v),  m_v + Σg0(儿子),  w_v + Σg0(儿子) + max over 儿子c of (core(c) − g0(c)) )
  - 第三项要求至少一个儿子当核
- g1(v) = max( core(v),  max(m_v, w_v) + Σg0(儿子) )

询问 L 的答案 = 深度 < L 的所有点的 max(m, w) 之和 + 深度恰好为 L 的所有点的 g1 之和。

**理由**：
- 深度 < L 的点，自己和所有邻居都在半径内，当核没有任何好处（亮度 0，邻居本来就能共振），所以直接取 max(m, w)
- 深度 = L 的点能自由共振，它的状态等价于"父亲是核"，也就是 g1。但它也可能值得当核，去支撑深度 L+1 的儿子，这种情况已经包含在 g1 的 core 选项里

预处理每一层的和，每次询问 O(1)。

验证：4 组大样例全部通过；300 棵随机小树（n ≤ 7）和 3ⁿ 暴力比对，全部一致。代码见 `正解代码/C_晶体树阵.cpp`。

**下次识别信号：**
- "某点要有一个邻居是 X 才能选 Y" → 支配型 DP，三状态（自己是 X / 被儿子支撑 / 等父亲支撑）
- "距离某点 ≤ L 的部分被豁免" → 以那个点为根，按深度分层
- **读到子任务表里有 "L = n" 这种条件，先想它是不是让题目退化成了平凡情况**

### D｜蜗蜗的轮换密钥（0 → 本可以 45，满分是经典套路）

**题目本质**：f^k = 恒等，所以 f 是一个排列；没有不动点，所以每个环长 ≥ 2；每个环长都要整除 k。问题变成：**n 能不能写成若干个"k 的约数（≥2）"之和**。

任何 ≥ 2 的约数都是 k 的某个质因子的倍数，一个长 d 的环可以拆成 d/p 个长 p 的环。所以问题进一步等价于：**n 能不能写成 k 的质因子的非负整数组合**。这是 Codeforces 986F 的原题。

**你推对的部分**（录音 3:06 至 3:12）：
- "能不能让你拆分成若干个环" ✓
- "能否拆成若干个质数" ✓
- "这跟小凯的那个钱有关" ✓：两个质因子时，就是 NOIP 2017 小凯的疑惑
- "第一步把 k 分解质因数" ✓

**偏掉的地方**：
- 草稿纸 4 写的是"P₁+…+Pₖ = n，P₁…Pₖ 互质，**P₁×P₂×…×Pₖ = k**"。**乘积等于 k 是多余的限制**。题面写了"不要求 k 是最小正周期"，所以只要每个环长整除 k，连 lcm = k 都不需要
- 小凯的疑惑只能处理两个数。三个以上质因子要用**同余最短路**（墨墨的等式、跳楼机）
- 最可惜的是：模型对了之后没写**完全背包**：
  - 子任务 1、2（n, k ≤ 1000）：对 k 的约数做完全背包
  - 子任务 3（n ≤ 10⁶）：对质因子做完全背包，不同的 k 最多 50 个
  - 一共 10+15+20 = **45 分**，二十行代码
- 你最后写的 `T4pian.cpp` 是枚举全排列模拟，n > 10 就跑不动，而且没写完

**正解**：先筛出 3.2×10⁷ 以内的质数，对每个不同的 k 分解质因数。
- k = 1：全部 NO（f(x) = x 不允许）
- 只有 1 个质因子 p：看 n 能否被 p 整除
- 2 个质因子 p < q：n = ap + bq，令 b ≡ n·q⁻¹ (mod p) 取最小值，检查 bq ≤ n
- 3 个及以上：最小质因子 p₁ ≤ ∛(10¹⁵) = 10⁵。对模 p₁ 的每个余数跑最短路，dist[r] = 能凑出来的、模 p₁ 余 r 的最小数。n 可行当且仅当 dist[n mod p₁] ≤ n

验证：3 组大样例通过；n, k ≤ 60 的 3600 组和背包暴力比对，全部一致。代码见 `正解代码/D_轮换密钥.cpp`。

**下次识别信号：**
- f^k = id → 排列 + 环长整除 k
- "用几种固定的数凑出一个很大的 n" → 同余最短路，模最小的那个数
- **模型推出来以后，先按子任务写最暴力的实现，再想优化**

## 九、经验教训（可以直接加进 Skill）

### 本场最大教训

**读数据范围要读到最后一个字。** `∑n ≤ X` 决定复杂度，漏读它一次，毁掉一整场。

### 题型规则

1. 区间点对统计（逆序对等）**不能前缀相减**：P(r) − P(l−1) 里多了跨界点对。要么固定一端增量维护，要么二维 DP
2. "前面有几个比我大" → **树状数组**。`std::distance` 在 set/map/multiset 上是 O(n)；要在 set 上 O(log n) 求排名，得用 pb_ds 的 tree
3. 构造题：先判 YES/NO（暴力打表、看 checker），再"前 i−1 个排好了，加第 i 个"
4. 树上"需要一个邻居是 X" → 三状态支配型 DP
5. "用几种固定的数凑很大的 n" → 同余最短路
6. f^k = id → 排列、环长整除 k；**"不要求最小周期"意味着连 lcm 都不用管**

### 调试规则

1. **输出超过理论上限或低于下限** → 公式结构错，停止调参数
2. 同一处正负号改了两次还不对 → 停下来，在纸上用 n=3 手算每个变量
3. 变量含义写在代码第一行注释，草稿纸和代码用同一个名字
4. 大样例跑超过时限 2 倍 → 当成复杂度错，不怪机器

### 比赛策略规则

1. **开赛 15 分钟通读四题**，每题列出"一眼能拿的子任务"，比如 C 的 L=n、D 的背包
2. **每题先交暴力**，再想正解
3. 知道会 TLE 的已交代码，优先级高于没思路的新题
4. 每道题开写前说一句"我预计这题能拿 X 分，最多花 Y 分钟"，到点就换题
