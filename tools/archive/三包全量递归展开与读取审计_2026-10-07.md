## 5. 重要新规则：全量处理 != 全部同时塞进模型窗口

三包展开后 5GB 级原始字节不可能同时驻留单次模型上下文。

因此“全部装入上下文”的可执行定义应固定为：

```
完整递归展开
→ 每个路径都有处理状态
→ 文本全文读取
→ 大型数据逐字节统计
→ 媒体全字节哈希 + 时间元数据
→ 内容哈希去重
→ 原始来源链可追溯
→ 需要推理时从这份全量索引回取原文
```

禁止把：
- 只列文件名；
- 只抽前中后几段；
- 只读智能总结；
- 只扫 depth≤3

说成“全量已读”。

## 6. 后续自动化的硬验收

每轮从三包继续工作时，优先从**未深推理**而不是“未索引”的对象里挑：

1. 已全文读但尚未形成比赛结论的录音/Replay；
2. 同名不同 SHA 的源码版本；
3. OJ 多快照字段冲突；
4. checker / stress / archive 脚本；
5. 正式提交源码与工作区/Replay 不一致处；
6. PDF 低文本但可能有视觉题面信息的对象。

本轮已经把“文件有没有处理过”从主问题变成了可审计事实；下一阶段重点是把 1,470 份唯一文本里的高价值原始证据继续转化成逐题结论。
