## 4. ZIP 内容哈希去重：重复非常严重

对已经递归打开的 nested ZIP 计算内容 SHA-256：

- 重复哈希组：**34 组**
- 落在重复组里的 ZIP 出现次数：**169 次**

这意味着后续不能按“路径数量”估算工作量，
必须按 **content hash** 去重。

### 典型重复

#### Day2 problem_185

同一 SHA 在三包/多份 VM 中出现 **15 次**。

路径包括：

- 01 VM：`Day2/problem_185.zip`
- 01 VM：`problem_185(1).zip`
- 01 VM：`problem_185(2).zip`
- 02 Day7 VM 快照中的对应副本
- 03 Day6 / 旧 VM 快照中的对应副本

所以第一次认真读透后，其余副本只需登记 provenance，不应再重复分析。

#### Day4 sample1 / sample2

同一 sample ZIP 在不同快照中各重复约 **12 次**。

#### Day3 sample / problem_1874

## 5. 新的长期处理单位：不是“文件路径”，而是 Evidence Object

以后处理优先使用：

```text
Evidence Object =
content SHA
+ 最早/最新 provenance
+ 所属比赛
+ 文件角色
+ 已提炼到哪里
```

例如同一个 `problem_185.zip` 出现 15 次，
不应产生 15 份题面分析。

应产生：

1. 1 个 canonical 内容对象；
2. 15 条 provenance；
3. 若副本时间不同，再判断是否存在真实版本变化。
