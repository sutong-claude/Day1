# 比赛归档助手 v7-alpha：DOM-first Hydro / 代码源新版适配

状态：**实验版，尚未在真实登录态代码源新 OJ 做完整端到端冒烟测试。不要替换稳定版 v6。**

## 为什么要重构

v6 的根本问题不是少几个 selector，而是把“HTTP 请求拿到的 HTML / 猜测 API 路由”当成主要事实来源。

代码源新版 / Hydro 系页面更适合反过来：

1. **当前浏览器实际渲染 DOM 是第一事实来源**；
2. 登录态背景页（真实浏览器 tab）是第二来源；
3. 官方公开路由 / API 只用于补充；
4. 原始 GET 只能做兜底和诊断，不能冒充用户实际看到的页面。

用户实测的新 OJ 还存在：
- 问答 / 澄清就在题目列表页下方；
- 本人递交也直接显示在该页下方；
- 题目页有“在线编程 / 递交 / 在题库中打开 / 答疑 / 题解”等真实入口；
- record 详情页的逐测试点结果对复盘很重要；
- 纯文本重排 PDF 与浏览器 Ctrl+P 的真实页面差别很大。

## v7-alpha 已完成

### DOM worker

新增通用背景页面 worker：
- 用 GM_openInTab 打开目标 URL；
- 复用当前浏览器登录态；
- 等待 DOM 稳定；
- 回传完整渲染 HTML、正文、链接、表格。

因此代码源新版不再只靠猜测 /record、/discussion、/clarification 接口。

### 代码源 / Hydro

- 比赛题目列表页：优先保存实际渲染 DOM。
- 本人递交：先解析页面底部可见递交，再用 /record 路由补充并去重。
- record：保存渲染后的记录详情、测试点表格、源码和打印入口。
- 问答 / 澄清 / 讨论 / 题解：先按当前页面标题区块抓取，再打开页面中的真实相关链接；猜测路由降级为 fallback。
- 排行榜：优先浏览器渲染页，HTTP GET 仅 fallback。

### PDF

v6 的“本地阅读 PDF”是把抽取后的文字重新排版，不是浏览器 Ctrl+P。

v7-alpha：
- 明确改名为“文本阅读版（非网页打印）”；
- 每个题面 / record 建立浏览器打印队列；
- 菜单加入“当前页：浏览器 Ctrl+P 打印 PDF”。

系统打印对话框不能由普通 userscript 可靠自动点击“保存”，因此目前不虚构“全自动 Ctrl+P”。

### Y4 / 课程

课程页不再只保存题目表：
- 保存完整渲染课程页面 HTML / TXT；
- 收集附件 / PDF / ZIP / Office 资源链接；
- 保存题目及本人提交；
- 生成打印队列。

## 下一步真实冒烟测试

测试目标：
1. 一个已结束的代码源新 OJ 比赛；
2. 一个题目详情页；
3. 一个 record 详情页；
4. 一个 Y4 / course 页面。

验证项：
- 页面下方问答是否完整；
- 页面下方递交是否完整；
- record 测试点表格是否完整；
- 源码是否完整；
- 渲染 HTML 是否和眼睛看到的一致；
- 打印队列是否能一键定位需要 Ctrl+P 的页面；
- 课程附件是否遗漏；
- 未登录 / 权限不足时是否给清晰 warning 而不是伪装“0 条”。

## 后续平台计划

先把 Hydro/代码源做成稳定的 DOM-first 基础层，再逐步补：
UOJ / LibreOJ / SYZOJ / HOJ / QDUOJ / DOMjudge / HUSTOJ 等开源 OJ profile。

原则：每个平台必须有真实页面夹具或真实冒烟测试，不能只靠 URL 猜适配。
