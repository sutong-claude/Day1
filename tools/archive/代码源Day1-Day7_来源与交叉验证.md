## 3. 一个重要归档现象：verdict 不能代替 score

例如：
- Day1 A = TLE，但实际 20 分；
- Day1 B = WA，但实际 25 分；
- Day3 B = WA，但实际 65 分；
- Day3 C = WA，但实际 24 分；
- Day6 D = TLE，但实际 15 分；
- Day7 B = RE，但实际 45 分。

后续严禁只看 Accepted / WA / TLE / RE 就判断一题“拿了多少”。

必须读：
- `record_*.json`；
- `记录详情.txt`；
- `测试表格.json`；
- 其中真实的 `score`。

## 5. 原始 OJ 归档不是 Replay 的替代品

OJ 归档回答：
- 题面是什么；
- 最终提交是什么；
- 得分 / 测试点是什么；
- 榜单快照是什么。

Replay / 录音回答：
- 中间到底写过什么；
- 什么时候推倒；
- 哪个 Bug 何时产生；
- 哪些想法从未保存到文件；
- Debugger / 网页 / 下载数据当时发生了什么。

因此应按问题选择证据：

| 问题 | 首选证据 |
|---|---|
| 最终得分 | OJ record |
| 最终提交源码 | OJ source |
| 中间源码状态 | file_changes |
| 屏幕/Debugger/下载行为 | screen |
| 数学想法 | 录音 / notes |
| 精确快捷键 | raw_keys |

## 6. 仓库策略

大体积原始 ZIP 不重复塞进 Git 历史。

仓库保存：
- 精确文件名；
- SHA-256；
- 完整性；
- 脱敏证据；
- 关键源码；
- verifier；
- 时间线。

原始 ZIP / screen / raw_keys / 音频继续保留在私有证据层。

这样既不让原材料“被埋没”，又避免 Git 被不可 diff 的二进制淹没。
