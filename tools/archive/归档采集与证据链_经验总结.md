# 归档采集与证据链：从七场代码源到 Coderlands

## 0. 真正目标

不是“爬到一份题面”。

而是让赛后 AI 能同时回答四类问题：

1. **事实**：题目、分数、榜单、测试点、最终源码；
2. **过程**：四小时里实际做了什么；
3. **思维**：为什么产生这个猜想、为什么切题、为什么没想到；
4. **工程**：当时跑的是哪份代码、样例是否正确、环境有没有事故。

所以一场可复盘比赛至少需要四层证据：

```text
OJ / 平台归档
+ VM / 工作区
+ Replay 捕捉器
+ 录音 / notes
```

缺任何一层，都只能回答部分问题。

---

## 1. 代码源：v7 的正确方向是 DOM-first

Hydro 的 `/record` 接口会因为权限 / 版本返回 403。

所以归档器不能把：

> API 失败

解释成：

> 用户没有提交。

v7 的核心原则是：

> **优先保存登录态浏览器已经真实渲染出来的事实，API 只作为补充。**

具体包括：
- 题目列表；
- 本人可见提交；
- 本人可见源码；
- 讨论 / 澄清；
- 排行榜；
- 原始页面快照。

本轮 Day1～Day7 的完整归档都可以恢复 4/4 题面，并核对本人提交与源码数量。

---

## 2. “完整 ZIP + AI 纯文本版”是很值钱的双轨设计

ZIP 负责：
- 原始 HTML；
- JSON；
- 请求响应；
- PDF；
- 诊断；
- 可审计目录结构。

AI 纯文本版负责：
- AI 不需要先解 ZIP 才能读；
- 可以全文搜索；
- 可以直接进入上下文；
- 能把题面、提交、源码、测试点一次交给模型。

所以：

> ZIP 是证据包；AI txt 是阅读层。

以后任何新平台适配器都应该同时产出两者。

---

## 3. Coderlands：不要先猜 API，先把浏览器行为当事实

目前能确认：
- Vue SPA；
- Vue Router；
- Axios；
- Element UI 风格；
- hash 路由；
- 榜单 / 提交详情异步加载。

但这些完全不足以证明：

> “底层一定是 Hydro / HUSTOJ / QDUOJ”。

所以 Coderlands 适配器不应该从“猜它是哪套 OJ”开始。

正确路线：

```text
站内正常搜索比赛
→ 进入比赛上下文
→ 打开题面 / 榜单 / 成绩详情
→ 记录 DOM 或真实请求
→ 再决定 API adapter 还是 DOM adapter
```

人工浏览已经覆盖：
- 4 道题；
- 2 页规则；
- 54 行榜单快照；
- 本人 4 个提交详情；
- 榜首 net；
- 一位 tree 详情。

这天然就是未来自动化的回归基准。

---

## 4. Coderlands 首版统一数据模型

建议统一成：

- `contest`
- `problem`
- `rank_row`
- `submission`
- `capture_manifest`

`capture_manifest` 必须记录：
- 抓取时间；
- 当前页面；
- 每类记录数；
- 未采集项；
- 选择器命中数；
- 错误 / 重试。

不要保存：
- Cookie；
- token；
- 密码。

提交详情是异步加载的。

刚打开弹窗时可能短暂显示：
- 0 分；
- 暂无测试点。

所以采集器必须等待真实测试点明细出现以后再读取，不能把占位状态当最终事实。

---

## 5. 证据规则

### 最终事实
优先：
`OJ record / 页面最终详情 > 记忆 > 聚合摘要`

### 过程事实
优先：
`screen + file_changes + raw_keys + 录音`

### 算法正确性
优先：
`证明 [P] > 独立穷举 [E] > OJ-AC`

OJ-AC 绝不自动升级成 PROVED。

### checker / brute
它们自己也是程序，也要验证。

Day3 checker、Day4 oracle、Coderlands 错格式样例都已经证明：

> “有验证器”不等于“验证链可靠”。

## 6. 一场比赛赛后的理想材料

```text
archive/
  contest
  problems
  submissions
  standings
  discussions
  raw_pages
  diagnostics
  AI_CONTEXT

contest_capture/
  timeline
  file_changes
  screen
  raw_keys
  manifest

BAG 四题工作区
录音原文
必要时 VM 快照 / 递归文件清单
```

然后 Git 仓库保存脱敏提炼：
- 完整性报告；
- 来源哈希；
- 关键源码；
- 时间线；
- 版本考古；
- verifier；
- 复盘结论。

这才叫“原材料没有被埋掉”，而不是把所有 ZIP 扔进一个目录后永远没人读。
