# A 三角画布

## 1. 把几何压成 endpoint

第 i 个三角形：

~~~text
左端 x = i
高 d_i
右端 x = i + d_i
~~~

定义：

~~~text
r_i = i + d_i
~~~

斜边方程：

~~~text
y = r_i - x
~~~

所有斜边斜率都是 -1。

所以两个三角形谁在上面，只看 r。

---

## 2. 未来谁会接管当前包络

对于 j>i：

### r_j < r_i

在两者重叠的 x 范围里：

~~~text
r_j - x < r_i - x
~~~

j 完全被 i 压住。

### r_j = r_i

斜边重合，
j 的整个三角形都包含在 i 已覆盖的同一斜边区域里。

它不会产生新的“更高包络”。

### r_j > r_i

从 j 开始：

~~~text
r_j - x > r_i - x
~~~

j 会真正接管包络。

因此本文采用 strict formulation：

> 对 i 找右边第一个 j，使 r_j > r_i。

记作 nxt[i]。

说明：
如果用“>=”作为 handoff，也可以构造一致递推，因为 equal-endpoint 三角形只是沿同一斜边继续；但必须保证转移定义一致。本题这里统一用 strict >，和赛后单调栈实现对应。

---

## 3. DP

设：

~~~text
f[i] = 从 i 开始所有三角形并集面积的两倍
~~~

从右往左算。

若 nxt[i]=j 且 j 在当前三角形结束前：

~~~text
j < i + d_i
~~~

记：

~~~text
h = j-i
~~~

当前三角形在 [i,j] 贡献的是一个梯形。

两端高度：
- 左：d_i
- 右：d_i-h

doubled area：

~~~text
h * (d_i + d_i-h)
= h * (2*d_i-h)
~~~

于是：

~~~text
f[i] = f[j] + h*(2*d_i-h)
~~~

---

## 4. 没有提前接管者

如果 strict next greater 不存在：

~~~text
nxt[i] = n+1
~~~

那么当前三角形完整贡献：

~~~text
d_i^2
~~~

注意：

> n+1 是 sentinel，不是实际 blocker。

赛后曾经出现过：

~~~text
n=1
d1=2
~~~

把 n+1 误当真实位置，算成 3；
正确 doubled area 是 4。

因此 sentinel 必须先单独排除。

在 d_i>=1 的题目条件下，如果 i+d_i<=n，那么位置 i+d_i 本身满足：

~~~text
r[i+d_i] = i+d_i + d[i+d_i] > i+d_i = r_i
~~~

所以 strict NGE 最迟会在 i+d_i 出现。

因此不存在 strict NGE 时，当前三角形已经延伸到序列右边界之外，后续没有需要再接的 suffix，直接：

~~~text
f[i] = d_i^2
~~~

即可。

---

## 5. strict next greater：单调栈

需要：

> 右边第一个 r_j > r_i。

从右往左维护单调栈：

~~~cpp
while (!st.empty() && r[st.top()] <= r[i])
    st.pop();

if (st.empty()) nxt[i] = n + 1;
else nxt[i] = st.top();

st.push(i);
~~~

复杂度 O(n)。

---

## 6. 不会单调栈时，也有 O(n log n) 正解

这是赛时已经接近想到的路线。

对固定 i：

~~~text
F(m) = max(r[i+1 ... m])
~~~

随着 m 增大，F(m) 单调不降。

所以：

~~~text
F(m) > r[i]
~~~

一定是：

~~~text
false false ... false true true ...
~~~

用 ST 表 / RMQ 查区间 max，
二分第一个 true。

总复杂度：

~~~text
O(n log n)
~~~

因此本题最应该记的优化链：

~~~text
O(n²) 向右扫
→ RMQ + 二分 O(n log n)
→ 单调栈 O(n)
~~~

# B 巡检路线

## 1. 先看赛时 15 分性质

检测点：

~~~text
A_1 < A_2 < ... < A_n
~~~

补给点：

~~~text
B_1 < B_2 < ... < B_n
~~~

如果：

~~~text
A_i >= B_i  对所有 i
~~~

那么一路向右即可。

到 A_i 前已经经过至少 B_1...B_i，
拿到 i 个试剂盒，
足够完成前 i 次检测。

最远必须走到 A_n。

所以：

~~~text
answer = A_n
~~~

这是赛时严格正确拿到的 15 分。

---

## 2. 一般情况：什么时候一定要回头

若：

~~~text
A_i < B_i
~~~

那么走到第 i 个检测点 A_i 时，
左边最多只有 i-1 个补给点。

前 i 次检测需要 i 个盒子，
所以至少有一个检测不能在第一次经过时完成。

必须先走到 B_i 或更右取得第 i 个盒子，
再回到 A_i 或更左。

因此产生一个“必须右→左跨过”的坏区间：

~~~text
[A_i, B_i]
~~~

只保留 A_i<B_i 的这些区间。

---

## 3. 坏区间有特殊顺序

因为 A_i、B_i 都严格递增，

坏区间按原编号排列时：

~~~text
L_1 < L_2 < ...
R_1 < R_2 < ...
~~~

不会出现乱序嵌套。

于是一次：

~~~text
走到 R_j
再回到 L_k
~~~

可以同时解决连续的一组：

~~~text
k, k+1, ..., j
~~~

---

## 4. O(m²) 分组 DP

设 m 是坏区间数量。

~~~text
dp[j]
=
正常“来回”解决前 j 个坏区间
所需的最小额外路程
~~~

最后一组如果是 k..j：

~~~text
额外 = 2*(R_j-L_k)
~~~

所以：

~~~text
dp[j]
=
min over k<=j
(
dp[k-1] + 2*(R_j-L_k)
)
~~~

O(m²)。

这是最适合先独立写出来验证的版本。

---

## 5. O(m) 优化

拆：

~~~text
dp[j]
=
2*R_j
+
min over k<=j
(
dp[k-1] - 2*L_k
)
~~~

维护前缀最小值：

~~~text
best = min(best, dp[k-1]-2*L_k)
~~~

每个 j O(1)。

---

## 6. 最后一组可以只回、不再回来

最终至少要访问：

~~~text
M = max(A_n, B_n)
~~~

若最后一组从 k 开始，
可以先走到 M，
最后一次直接回到 L_k 后结束，
无需再返回右侧。

所以候选：

~~~text
2*M + dp[k-1] - L_k
~~~

还要比较：
所有坏区间都普通来回解决后停在 M：

~~~text
M + dp[m]
~~~

取最小即可。

# C 日志摘要

## 赛时已知问题

最终赛时代码存在：

1. 多测 / 文件 IO 的 RE；
2. n=1 分支把“日志条数 n”当“字符串长度”；
3. 长度 2 的局部贪心只看下一条少量字符，信息不够。

最小反例：

~~~text
s1 = "aa"
s2 = "ab"
~~~

局部策略可能输出：

~~~text
aab
~~~

但更小的是：

~~~text
aaab
~~~

说明：
“每个串只看很短局部”不能决定全局字典序。

## 当前可靠 partial 方向

小 n / 小总长度时：

- 每个字符串枚举所有非空后缀；
- DFS 枚举组合；
- 拼接后取字典序最小。

这个版本适合作为 full 的 oracle。

仓库不把任何未经验证的字符串贪心包装成 full。

# D 灯光预案

## 当前可靠 partial

若 q 很小：

~~~text
枚举 2^q 个指令子集
~~~

对每个子集按题意模拟最终灯光 / 目标量。

若同时 n 小，
直接重算即可。

这可以覆盖早期小子任务，并作为 oracle。
