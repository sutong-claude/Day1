# A. 蜗蜗的三角画布｜赛时接近 full，真正缺的是 first-by-position

## 1. 把几何压成 endpoint

令：

[
r_i=i+d_i.
]

第 i 个三角形斜边：

[
y=r_i-x.
]

所有斜边斜率完全相同。

所以右边三角形 j 若：

[
r_j<r_i
]

它在与 i 重叠的区间里始终压在 i 下方，不会接管上包络。

因此真正需要的是：

[
nxt(i)=min{j>imid r_jge r_i}.
]

注意关键词：

> **位置最小。**

不是：
> 满足条件的 endpoint 值最小。

这就是 Day5 最核心的语义差异。

## 2. 为什么 lower_bound / upper_bound 错

赛时第一版按 endpoint 值排序后 lower_bound。

它解决：

[
min r_j,quad r_jge r_i
]

题目需要：

[
min j,quad j>i, r_jge r_i.
]

两者不同。

第二版甚至在没有保持有序的 vector 上直接二分，连二分前提也不成立。

## 3. 正确工具：Next Greater or Equal

从右往左维护单调栈：

```cpp
while (!st.empty() && r[st.back()] < r[i])
    st.pop_back();

nxt[i] = st.empty() ? n + 1 : st.back();
st.push_back(i);
```

具体 `>` / `>=` 按题目边界定义统一。

本质：

> 右边第一个 endpoint 足够高的位置。

## 4. suffix DP

若：

[
j=nxt(i)
]

并且 j 还落在当前三角形水平范围内，令：

[
h=j-i.
]

i 在 ([i,j]) 这一段主导包络，二倍面积为：

[
h(2d_i-h).
]

因此：

[
f_i=f_j+h(2d_i-h).
]

若不存在有效 blocker：

[
f_i=d_i^2+f_{min(i+d_i,n+1)}.
]

## 5. 赛时为什么会感觉“修了一百个 Bug”

前半场确实有很多独立实现 Bug：
- STL 接口；
- iterator；
- pair first/second；
- off-by-one；
- 越界；
- DP 下标；
- h 定义。

但第二版后期这些大多被修掉。

最后大量症状主要来自同一个上游错误：

```text

↓

↓

↓

```

所以：
> 症状很多 ≠ 最终还有几十个独立 Bug。

# D. 蜗蜗的灯光预案｜赛后完整题解：GF(2) 奇偶影响类 + 二阶矩

> **版本修订 2026-10-08**：此前本节只给出 `q≤10` 的 9 分枚举，标记「full 待补」。现将其保留为历史赛时信息，并补赛后完整证明与实现。赛时状态仍是 **0 分 / 未提交**；以下为 **POSTCONTEST_FULL_[P/E]，未经 OJ-AC**。

## D1. 题意、数据范围与部分分

给 `n` 个整数 `a_i` 和 `q` 条编号不同的可选操作 `(l,r,x)`，每条可以执行一次或不执行。执行即对 `[l,r]` 中每个位置按位异或 `x`；顺序无关。对一种选择 `U`，定义

```text
K(U) = sum_{1 <= l <= r <= n} (a_l(U)+...+a_r(U))^2
```

求所有 `2^q` 个子集选择的 `K` 总和，模 `1,000,000,007`。

官方约束：[C] `1≤n≤1000, 0≤q≤100000, 0≤a_i,x<128`，每条 `1≤l≤r≤n`。编码只有 **7 个 bit**。

| 子任务 | 分值 | 题面约束 / 特点 | 可用路线 |
|---|---:|---|---|
| 1 | 4 | `n≤10,q≤10` | 枚举 `2^q` 真值 |
| 2 | 5 | 依赖1；`n≤100,q≤10` | 同上，总计9分 |
| 3 | 6 | `n≤100`，5位编码，所有操作 `l=r` | 独立位置位分布 |
| 4 | 9 | `q≤500`，操作区间两两不相交 | 区间独立性专项 |
| 5 | 8 | `n≤30,q≤20`，5位编码 | 枚举子集 / 按位统计 |
| 6 | 11 | 依赖5；`n≤30,q≤5000`，5位编码 | 相同影响集合归类 |
| 7 | 19 | 依赖1–2、5；`n≤300,q≤300` | 完整二阶矩 |
| 8 | 30 | 依赖1–3、5–7；`n≤500` | 完整二阶矩 |
| 9 | 8 | 依赖1–8；无额外限制 | 完整二阶矩 |

### 最先应写的暴力 / 独立 oracle

对每个 `mask∈[0,2^q)`：
1. 拷贝初始数组；
2. 枚举被选中指令，真实按位 XOR 更新；
3. 对每个 `l` 持续累加 `r` 方向的前缀，求所有连续段的平方贡献。

复杂度约 `O(2^q(qn+n²))`、空间 `O(n)`，足够作为 `q≤10` 的 **9 分理论 partial** 和后续 full 的小数据真值。**用户赛时没有把它写成提交资产**，不能把它计入赛时得分。

## D2. 核心观察：因为平方，只需要一阶期望和两两协方差

随机、独立、等概率选择每一条操作，令 `u_t∈GF(2)` 为是否执行第 `t` 条操作。

对每个位置 `i` 和二进制位 `b=0..6`，定义长度为 `q` 的**影响向量** `v_{i,b}`：

```text
v_{i,b}[t] = 1   iff  t号操作覆盖位置i 且 x_t 的第b位是1。
```

则执行完后，该位变为

```text
bit_{i,b}(U) = initial_bit_{i,b} XOR <v_{i,b}, u>  (mod 2).
```

按 `v` 分类：

- **`v=0`**：这一位完全没有被任何操作改变，恒等于初始位。
- **`v≠0`**：`<v,u>` 为公平随机位，均值 `1/2`。
- **不同的非零 `v,w`**：两个线性形式在 GF(2) 上必线性独立，因为非零向量在 GF(2) 的唯一非零标量是1；故 `<v,u>` 与 `<w,u>` **两两独立**，协方差为零。
- **相同的非零 `v`**：共享一个随机奇偶位，不能当作独立。初始 bit 为0时 XOR 后位值随它正变；初始 bit 为1时取其补，系数为负。

注意：不同的三个非零影响向量可以存在线性关系，因此**不是全体随机位彼此独立**；但 `K` 是二次式，**两两独立足够**。

## D3. 把每个整数写成共享随机源的线性组合

对每个**非零影响向量类** `g` 定义随机位 `P_g=<g,u>`，则 `E[P_g]=1/2`，`Var(P_g)=1/4`，不同类协方差为0。

令位置 `i` 的两倍均值为 `M_i = 2 E[a_i(U)]`。

逐 bit 构造：
- `v_{i,b}=0`：`M_i += 2*2^b*initial_bit`；
- `v_{i,b}≠0`：`M_i += 2^b`。

对每个非零类 `g` 和位置 `i`，把属于这个类的 bit 权重带符号相加：

```text
C[g][i] = sum_{b: v_{i,b}=g} (initial_bit==0 ? +2^b : -2^b).
```

**同一位置若多个 bit 属于同组，必须先加系数再平方，不能分别计算。**

此时有一个精确恒等式：

```text
a_i(U) = M_i/2 + sum_{g != 0} C[g][i] * (P_g - 1/2).
```

故任意区间 `I=[l,r]` 的和 `A_I(U)=sum_{i∈I}a_i(U)` 满足

```text
4 * E[A_I(U)^2]
  = (sum_{i in I} M_i)^2
    + sum_{g != 0} (sum_{i in I} C[g][i])^2 .
```

**证明 [P]**：展开平方。所有中心化随机变量 `P_g-1/2` 的均值0；不同非零类之间协方差0；同一个类的方差 `1/4`。交叉项全部消失，只剩平方的均值项和每类方差项。

原题要求总和而不是期望；每个子集等概率，故只需乘 `2^q`。

令 `S(c)=Σ_{l≤r}(Σ_{i=l}^r c_i)^2`。最终：

```text
answer = powmod(2,q) * inv4 * [ S(M)+Σ_{g≠0} S(C[g]) ] mod 1e9+7.
```

`inv4=250000002`。**这是代数精确式，不是蒙特卡罗估计。**

## D4. 不要逐区间计算 S(c)：加权位置平方展开 O(n)

位置 `i` 属于 `i(n-i+1)` 个连续段；一对 `i<j` 共同属于 `i(n-j+1)` 个连续段。

因此

```text
S(c) = sum_i i(n-i+1)c_i^2
     + 2 sum_j (n-j+1)c_j [sum_{i<j} i*c_i].
```

从左到右维护 `prefixWeighted = Σ_{i<j} i*c_i`，单次 O(n)。

`C[g]` 绝大多数为空，不必为每个组构造长度 `n` 的数组；把该组的非零 `(position,coefficient)` 顺序存起来，合并相同位置后扫描即可。所有非零位权项合计不超过 `7n`，所以计算**全部** `S(C_g)` 的时间是 O(7n)。

## D5. 怎样在 q=10^5 时给影响集合精准分组

`q` 是大维度，但 `n≤1000`，所有 `(i,b)` 只有 `7n≤7000` 个。

对每个 bit 维护一个长度为 `ceil(q/64)` 的 `uint64_t` bitset，记录**当前位置的影响指令 ID**。每条指令 `(l,r,x)` 对每个置位的 bit：
- 扫到位置 `l` 时 toggle 该指令 ID；
- 扫到 `r+1` 时再 toggle 一次。

扫描每个位置后，把7份完整 bitset 归入等价类。

可使用 hash bucket 加速找候选 ID，但是**hash 相同必须逐字节比较完整 bitset**，不能把概率碰撞写成数学正确性证明。仓库代码保留每份实际位集，只用 hash 进行加速，所以**归类本身精确**。

复杂度在正常 hash 桶行为下约为：

```text
时间 O(7q + 7n*ceil(q/64) + 7n + log q)
空间 O(q + 7n*ceil(q/64))
```

极端 hash 桶大量碰撞会让精确比较更慢，但不会使答案错误；内存按题面最大参数仍可控（实际压力输入测得约93MiB）。

边界：
- `q=0`：所有向量皆零，唯一方案直接由 `S(M)/4` 恢复真实 `K`；
- `x=0` 的操作不影响任何位，但仍是独立的可选指令，总预案数仍乘 `2^q`；
- 参数完全相同的两条操作也有不同指令 ID，不能合并为一次操作；
- 同一组多个 bit 的权重必须先合并。

## D6. 样例手算：52 为什么自然出现

样例一 `n=2, a=[1,3], q=1, [1,2] xor 2`。

bit1 同时影响位置1和2，但初始取值互补：

```text
M = [4,4]                 (两倍均值)
C_group = [+2,-2]
S(M) = 4²+4²+8² = 96
S(C) = 2²+(-2)²+(2-2)² = 8
answer = (96+8) * (2/4) = 52.
```

第二个样例 `q=0`，程序算出1001，与原题相符。
