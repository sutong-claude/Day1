# Day5 逐段考古纪要（append-only）

## E-D5-001｜A 三角画布｜正确目标已接近，查询对象写错

**来源**：Replay v3 + 两版历史代码 + 复盘。  
**数学对象**：需要找第一个位置 j>i，使 r_j>r_i。  
**赛时实现**：把“按位置找第一个满足条件”误写成“按值 lower_bound”。  
**状态**：[X] 数据结构接口与数学 query 不一致。  
**结论**：这是 Day5 最重要根因，不是“单调栈没背”。  
**触发器**：写二分/树状数组/线段树前，先用一句中文写函数究竟返回“位置、值、数量还是最值”。

## E-D5-002｜约 T+01:19｜A｜本人已经说“算法有问题/全盘推倒”

**来源**：录音。  
**意义**：元认知已经判断不是局部代码 Bug。  
**后续问题**：仍在原优化框架中持续修补。  
**结论**：当本人已经明确说“算法有问题”，应该立刻回到 brute/数学对象，而不是继续调同一数据结构。

## E-D5-003｜A 第二版｜复杂结构并没有增加证明

**来源**：历史版本。  
**现象**：第二版更复杂，但查询的单调前提仍未证明。  
**结论**：代码复杂度上升不等于算法信息量上升。  
**迁移**：任何“为了让它更快而新增一层数据结构”，必须先写出它依赖的单调性/可合并性。

## E-D5-004｜B 巡检路线｜15 分是稳定资产

**来源**：OJ record（15 WA）+ 复盘。  
**状态**：[E/P partial] 至少一档 partial 逻辑实际通过。  
**正面意义**：在 A 长时间失控时，B 仍证明“正确 partial 可以成为分数地板”。  
**迁移**：已经拿到分的版本必须冻结，不和 full 研究共用唯一工作副本。

## E-D5-005｜T+03:36 以后｜A/C｜最后阶段开始抢 partial

**来源**：录音 + OJ 多次 C 提交。  
**事实**：C 在末段出现 RE→RE→WA；A 的最后保分修改也发生回归。  
**结论**：最后 20～30 分钟新增未经证明的算法分支，收益/风险比很差。  
**触发器**：最后30分钟进入 delivery mode：只做已证明 partial、编译、样例、freopen、提交，不开新模型。

## E-D5-006｜跨 Day4 对照｜Debug 对象错了

Day4 B 与 Day5 A 的共同模式：
- 表面看是在“调代码”；
- 实际上数学状态/查询接口不闭合；
- 局部 patch 无法修复模型错误。

**长期结论**：Debug 前先分类：实现 Bug / 模型 Bug / 复杂度 Bug / 环境 Bug。分类错了，调得越久损失越大。
