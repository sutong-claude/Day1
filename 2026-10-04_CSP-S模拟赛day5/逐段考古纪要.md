## E-D5-016｜C 第三交 exact source × exhaustive tiny oracle｜WA0 的根因分成三层

**原始证据链**：
- [P/source] 三包 03 → `代码源新 OJ_6ac0cd3c4a5cd1a28f028a12_2026 CSP-S 复赛赛前模拟赛 day5_完整归档_2026-10-05T12-44-41-386Z.zip` → `02_题面/C_C 蜗蜗的日志摘要/题面.md`；
- [P/source] 同一归档 → `03_我的提交/C_C 蜗蜗的日志摘要/record_6ac1dd8a4a5cd1a28f06ca55.cpp`；该正式 source SHA256 为 `1fe58756e48eb807daab13a1fd3ba6a65a905e2a4d10f1249f4ae106324c9bb2`；
- [P/OJ] 本场已有提交链对齐：C 最终第三交约 13:00:58，打开 `Hina.in/out` 后由 RE 转为 WA0；
- [E] 将**正式提交字节**编译为 gnu++17 -O2，用 `Hina.in/out` 运行，逐例与独立 suffix 枚举 oracle 比较。复现脚本：`验证/C_日志摘要_tiny_oracle.py`。

### 数学契约（必须先成立）

每条 `s_i` 必须保留一个**非空后缀**，按原顺序拼接，求字典序最小值。最小空间真值可以逐串枚举所有后缀，再取笛卡尔积的最小拼接结果。这个定义同时提供两个检查：
1. 输出是否来自任意**合法方案**（feasible）；
2. 若合法，是否在合法方案中**字典序最小**（optimal）。

### 第一层：[X] `n=1` 被错当成字符串长度

正式 source 写：
```cpp
if (n == 1) {
    for (int i = n; i >= 1; i--)
        st.insert(s[1].substr(i, n-i+1));
}
```
这里 `n` 是日志条数而非 `s[1].size()`；所以只枚举 `substr(1,1)`。

- 输入 `T=1,n=1,s_1="a"`：唯一合法答案 `a`，正式输出空行；
- 输入 `T=1,n=1,s_1="ab"`：最小合法后缀是 `ab`，正式输出 `b`；
- 对 `"aab"` 甚至输出 `a`，而 `a` 不是 `aab` 的后缀。

本层不是“选错最小后缀”这么简单，**连非空性和后缀合法性都可能不满足**。

### 第二层：[X] `n>1` 未检查长度，却无条件访问 `s[i][1]`

原题允许 `|s_i|=1`，但代码在 `n>1` 分支对任意字符串访问第二个字符。

以 `s=["a","a"]` 为例，C++ `std::string::operator[](size())` 在此得到终止符 `'\\0'`；`s[i][0] > s[i][1]` 于是向答案逐次拼入 NUL。真实 `aa`，正式程序输出原始字节 `00 00 0a`。

这属于**输出不可能由非空小写字母后缀组成**的交付/实现语义错误；它独立于字典序贪心本身。

### 第三层：[X] 即使把 `|s_i|=2` 全部满足，局部策略仍然错

用下面的同一子任务内最小反例：
```
1
2
aa
ab
```

真值为 `aaab`：第一条保留 `aa`，第二条保留 `ab`。正式输出 `aab`：第一条只保留 `a`，第二条保留 `ab`。二者都合法，但 `aaab < aab`，第三个字符 `a < b`。

代码的局部判定 `min(s[i+1][0],s[i+1][1]) > s[i][0]` 在相等边界便决定截掉一个 `a`；而最优性依赖**整个后续拼接串**，不由下一条的两个字符决定。

这把“`|s_i|=2` special 不充分”的旧结论从人工反例升级成严格 OJ-source 运行证据：[E/X]。

另外：`s=["bab","ab"]` 时提交程序输出 `aab`，真正最优为 `abab`；因为 `"a"` 不是 `"bab"` 的非空后缀，此输出**甚至不合法**。这条反例没有单字符输入，表明“直接取第二个字符”也不等价于保留后缀。

### 完全枚举统计 [E]（有限定义域，不宣称 full）

| 定义域 | 实例数 | 与真值不符 | 输出本身不合法 |
|---|---:|---:|---:|
| 字母 `a/b`、每串长度1..3、n=1..3 | 2,954 | **2,481** | **1,952** |
| 字母 `a/b`、全部串长2、n=2..5 | 1,360 | **495** | **0** |

第二行的每个输出仍是合法拼接，但有 495 个不最优；第一行还有大量非法拼接。两类错误**不能合并成一句“特殊情况没写好”**。

### 三、新的赛后数学突破：期望二阶矩只需要 pairwise correlation

题面每条指令是否执行对应一个独立均匀布尔变量 `u_t`；对每个位置 `i` 和 bit `b=0..6`，记录其受哪些指令影响的二进制向量 `v(i,b)\in GF(2)^q`。

输出 bit = 初始 bit XOR `<v,u>`。

- 若 `v=0`，bit 始终固定。
- 若 `v≠0`，bit 公平为 0/1。
- 若两个非零向量 **不同**，对应两个 GF(2) 非零线性形式在 GF(2) 上线性独立，因而两两独立，即使三个及以上形式整体可能线性相关。
- 若向量相同，则两个 bit 取决于**同一个**随机奇偶值；必须保留协方差，不能全当独立随机位。

令 `M_i=2 E[a_i(U)]`，对每个非零向量组 `g` 构造 `C_{g,i}`：该组在 `i` 的所有 bit 权值之和，初始 bit 为0时权值正，为1时权值负。

对任何区间 `[l,r]`：

```
4 E[(sum_i a_i(U))^2]
 = (sum_i M_i)^2 + sum_{g!=0}(sum_i C_{g,i})^2 .
```

故设 `S(c)=Σ_{l≤r}(Σ_{i=l}^r c_i)^2`，

```
答案 = 2^q * inv(4) * ( S(M) + Σ_{g!=0} S(C_g) ) mod 1e9+7。
```

[P/math] 这是**完整等式**，而非近似概率算法：独立指令的 uniform distribution 让不同非零 GF(2) 线性形式两两正交，二次目标不需要高阶独立性。

### 四、计算和精确性

1. 位置从左往右扫；每条 `[l,r],x` 在 `l` 与 `r+1` 产生 bitset toggle 事件，编码「影响这个 bit 的具体指令 ID 集合」。
2. 每个位置 × 7 bit 取得完整的 `ceil(q/64)` 个 `uint64_t` 状态，按内容归类。64-bit hash **只当桶索引**，冲突之后逐字比较 bitset，组相等性是确定的 [P/source]。
3. 计算 `S(c)` 时不枚举全部 `[l,r]`：展开平方，位置 `j` 的贡献为
   `j(n-j+1)c_j² + 2(n-j+1)c_j(Σ_{i<j} i*c_i)`。
   维护加权前缀和即可按非零位置一次线性扫完。
4. 同一个 `(位置,组)` 可能含多个 bit，**先合并权值再平方**；否则会漏同位置不同 bit 的协方差项。
5. `q=0`、`x=0`、重复区间/重复指令、同一 bit 全位置受影响等边界都由原模型覆盖；即使两条指令参数一致，它们的 ID 不同，依然是独立二元选择。

实现：
- `正解代码/D_灯光预案_二阶矩_确定性位集.cpp`
- `验证/D_灯光预案_独立穷举对拍.py`

典型规模的预期计算量：约 `O(7q + 7n ceil(q/64) + 7n)` 次状态字处理/事件归集（哈希桶平均情况，碰撞会执行精确比较）；空间上界约 `O(q + 7n ceil(q/64))` 个数据单位。本题参数下已测单进程一组 1000/100000 压力输入可运行；不是官方 OJ 验收。
