~~~

最后一步才是：
monotonic stack。

# 2. 数学主体其实已经收敛

设：

~~~text
r_i = i + d_i
~~~

第 i 个三角形斜边：

~~~text
y = r_i - x
~~~

所有斜边平行。

因此右边某个 j：

- r_j <= r_i：在重叠区间内不会高过 i；
- r_j > r_i：从 j 开始它可以接管上包络。

于是当前三角形真正关心的不是：

> 后面哪个 endpoint 最小 / 最大？

而是：

> **最早哪个位置 j，endpoint 已经超过我。**

这是一个位置查询。

赛时到约 3:28 已经明确说出：

> “不是找到最小最大的，而是找到最小位置还比他大的。”

这句话必须在复盘里保留。

# 3. 第一代代码为什么会越 Debug 越深

第一代大量使用：

- multimap；
- lower_bound；
- iterator；
- pair；
- erase。

表面上错误很多。

但真正的问题是：

> 数据结构按 endpoint 值排序。

所以 lower_bound 回答：

> “哪个 endpoint 值最小但足够大？”

而题目要：

> “哪个位置最早且 endpoint 足够大？”

即使所有 iterator 都写对，
算法仍然错。

这就是典型：

> **实现对象与数学查询对象不一致。**

# 5. 赛时其实已经想到一个完全可以 AC 的替代方案

用户后面回忆：

> “我记得我提过一个后缀最大值再二分，但是嫌麻烦。”

录音对应的更准确说法是：
后缀 / 区间最大值 + 二分。

核心不是普通 static suffix max。

对固定 i，定义：

~~~text
F(m) = max r[k],  i < k <= m
~~~

随着 m 右移：

~~~text
F(m)
~~~

单调不降。

于是条件：

~~~text
F(m) > r[i]
~~~

是：

~~~text
false false ... false true true ...
~~~

可以二分第一个 true。

区间最大值用 ST / RMQ O(1)。

总复杂度：

~~~text
O(n log n)
~~~

对于 n<=3e5 完全够。

这说明：

> 即使完全不知道单调栈，赛时最后 30 多分钟其实已经碰到一条可 AC 的标准路线。

真正失败的是：
前面 Debug 消耗太大，
看到“还要手写 RMQ + 二分”后工程心理成本太高，没有继续。

# 6. 单调栈不是从天上掉下来的

从右往左看。

如果当前 r_i 已经 >= 栈顶 r_j，
那么 j 对更左边的位置还有意义吗？

没有。

因为：
i 更靠左，而且不比 j 低，
以后所有更左的人若需要一个“右边更大的候选”，
j 会被 i 挡掉。

所以 j 可以永久淘汰。

这就是单调栈。

因此 Day5 A 的学习链最好记成：

~~~text
O(n²) 逐个向右找
↓
区间 max + 二分 O(n log n)
↓
发现被更近、更高者遮住的候选可以永久删除
↓
单调栈 O(n)
~~~

这比只背一句：

> “第一个更大用单调栈”

更容易迁移。

# 7. 赛后 strict-NGE 版本又暴露了 sentinel 语义

赛后代码：

~~~text
next[i] = n+1
~~~

表示：
不存在更大的接管者。

早期版本后面却把 n+1 继续当普通位置判断。

最小反例：

~~~text
n=1
d1=2
~~~

正确整个三角形 doubled area = 4。

错误版把 n+1 当 blocker，算成 3。

所以：

> sentinel 是一种“状态”，不是一个合法数据点。

以后看到：
- -1；
- n+1；
- INF；
- null index；

进入普通转移前必须先显式分支。
