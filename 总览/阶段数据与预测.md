# 3. 真正的成长曲线不是分数曲线

Observed：

```text
45 → 130 → 204 → 0 → 15 → 115 → 145
```

若只看分数，是大幅震荡。

但错误发生的位置在逐渐后移：

```text
Day1  读题/范围/复杂度
  ↓
Day2  代码身份/提交/RE-CE
  ↓
Day3  猜想与证据等级
  ↓
Day4  oracle/冻结/环境
  ↓
Day5  数学 query → 数据结构接口
  ↓
Day6  数学条件必要且充分
  ↓
Day7  复杂度结构变换 / PROVED→FROZEN
  ↓
Coderlands
      OJ100后的证明审计 / bundled subtask 闭合
```

这意味着现在最危险的错误已经越来越少是：
> “题意完全没看懂。”

更多是：
> “数学已经接近、甚至证明了部分资产，但最后一步结构转换/物化/证明闭合没完成。”

# 6. 下一阶段分数预测：只做情景推演

**不是概率模型。**

假设下一场仍为 4题×100、强度接近近期高质量 CSP-S 模拟：

### 情景 A｜旧问题明显复发
- 前题能拿一题；
- 后题 partial 证明了但没交；
- 又有一题进入模型 Debug 黑洞。

**大致得分区间：100～150。**

### 情景 B｜当前流程被真正执行
- A/最稳题 100 左右；
- 至少两份 PROVED partial 被 10 分钟内物化；
- 深挖题会在无信息增益时止损；
- 不要求新算法水平突然增长。

**大致得分区间：150～210。**

### 情景 C｜流程执行 + 再跨过一处结构变换
例如：
- reverse time / DSU；
- 单调栈 query 识别；
- 一个高价值 70～100 分题真正闭合；
同时保住 partial。

**200～250 是合理的冲击区间。**

这不是“保证能考到200+”。

它说明：
> 当前目标 200～250 已经越来越不像“必须突然学会一堆新算法”，而是“减少已有数学资产的漏损 + 再完成一题结构跃迁”。

# 7. 下一阶段评价指标：不要只看总分

每场额外记录：

1. **首次确定得分时间**；
2. **首次提交时间**；
3. **PROVED partial 数量**；
4. **其中成功 FROZEN 的比例**；
5. **正确 brute 数量**；
6. **从 brute 到 full 的结构跃迁次数**；
7. **无新数学事实连续 Debug 的最长时长**；
8. **赛后发现的“提交版本≠测试版本”事故数**；
9. **oracle/checker 自身出错次数**；
10. **四题获得正常阅读时间的比例**。

如果这些指标变好，即使一场由于题目难度裸分低，也不应该直接判“状态退化”。

# 8. 当前最值得训练的不是更多模板，而是结构改写

下一阶段优先练：

```text
删除 / split
→ reverse time

存在某个对象
→ 固定对象 / swap quantifier

最小位置满足条件
→ monotonic / next occurrence

固定答案 R
→ 必须选择哪些对象

小值域
→ 状态压缩 / finite-state DP

重复大样例手工操作
→ script
```

这些正好对应最近真正卡住 full 的地方。
