# 1. 接手后第一件事：不要读“最新总结”就开始回答

必须先知道不同事实该去哪里取。

| 要回答的问题 | Source of truth |
|---|---|
| 最终得分 | OJ record / 测试点 score |
| 最终提交源码 | OJ source |
| 比赛中间到底写过什么 | Replay `file_changes` |
| 当时屏幕看到了什么 | screen |
| 为什么产生某个思路 | 录音原文 + notes |
| 精确快捷键/复制/搜索行为 | raw_keys |
| 算法是否正确 | 数学证明 [P] / 独立穷举 [E] |
| OJ 是否放过 | OJ-AC（**不能等价于 PROVED**） |
| 仓库当前维护进度 | 本文件 + `复盘产物覆盖矩阵.md` |
| 当前正式 BAG | `tools/vm/bag_v4_flat/` |

## 证据等级

- `[P]`：已证明；
- `[E]`：独立 brute / exhaustive 验证，尚未完全形式化；
- `[C]`：题面 / checker / 平台契约；
- `[H]`：猜想；
- `[X]`：已有反例；
- `OJ-AC`：官方数据通过，**不是证明等级**。

后续任何复盘必须把这几种状态分开。

# 2. 原始材料不能被“智能纪要”替代

用户反复明确要求：

> 给了一堆录音、Replay、虚拟机、归档，不是为了最后只读一份智能概要。

因此采用 **append-as-you-read**：

```text
读一段录音 / Replay / 版本历史
        ↓
得到一个可靠新事实
        ↓
立即写进该场《逐段考古纪要》
        ↓
标来源、时间点、证据等级、旧结论是否被修订
        ↓
再继续读下一段
```

禁止：
- 连读几十页后只写一段总结；
- 用最终代码倒推赛时思路；
- 用智能纪要代替原始转写；
- 看到最终短文件就推断“这题没写过”；
- 因为 OJ AC 就把赛时算法写成“已证明正确”。

详细格式见：
`模拟赛考古纪要协议.md`。

# 3. 回答用户题目时的固定教学顺序

用户要的是“像高质量竞赛 PPT 一样”，不是标准题解墙。

一道题默认：

```text
题目卡片
→ 人话重述
→ 数据范围 / 子任务在暗示什么
→ 赛时本人怎么想
→ 手玩小例子 / 大样例
→ 第一版 brute
→ 这个 brute 重复做了什么
→ 性质 / 等价改写
→ 正解为什么会被想到
→ 证明
→ 部分分梯度
→ 实现积木
→ 原代码最小修复
→ Hack / 对拍
→ “下次看到什么自动想到什么”
```

特别规则：

> **能沿用户原算法修，就先证明/修原算法；不要发现一个 Bug 就用标准解法把原路线盖掉。**

典型案例：
- Coderlands `net`：赛时 priority_queue 主体是强候选；已知 Bug 是直径路径 1-based 中点 off-by-one。同步剥叶应先作为独立 full/proof/oracle，而不是直接说“赛时算法错，换一个”。

# 5. 七场代码源的能力主线

不要只看裸分。

```text
Day1
题意/总范围/复杂度/部分分

  ↓

Day2
算法想法开始增加
但版本、RE/CE、假对拍、交付链仍乱

  ↓

Day3
大样例研究 / checker / brute / 结构发现变强
但 [P] 和 [H] 混淆，checker 验证不完整

  ↓

Day4
generator + brute + candidate + diff 真正跑起来
同时发现 oracle 自己也会错、环境也会炸

  ↓

Day5
数学 query 已经能说出来
瓶颈后移到“数学对象 → 正确数据结构接口”

  ↓

Day6
瓶颈继续后移：
数学判定是不是必要且充分

  ↓

Day7
正确 brute / profiler / 回滚 / 冻结 / offline 意识已有
缺“删除分裂 → 时间反演 → 加入合并 → DSU”
同时出现新瓶颈：
PROVED partial 没有快速物化为 FROZEN score asset
```

所以“分数波动大”不等价于“能力原地踏步”。

# 6. 目前最重要的跨场触发器

## 删除导致分裂
```text
固定顺序删除
+ 动态组件不断分裂
→ 尝试时间倒放
→ 加点 / 合并
→ DSU
```

来源：Day7 B。

## 说出“这 X 分一定能拿”
必须启动：
```text
PROVED
→ 10分钟内 CODED
→ VERIFIED
→ FROZEN
```

来源：Day7 C/D。

## 自由度已经很低
例如 `k=2` 只有一刀：

> 停止猜结构，枚举全部自由度。

来源：Coderlands game 第28组反例。

## 数据结构前先写数学 query
例如 Day5 A：

```text
min j>i such that r[j]>=r[i]
```

先把对象说清，再识别 Next Greater / monotonic stack。

## 一个 [H] 被打死
只删除依赖这个 H 的上层结论。

不要把底下已证明的 [P] 一起扔掉。

来源：Day3 B。

## 大样例开始反复手工变换
如果相同变换手工做了 ≥3 次：

> 写脚本批量做，不要停止研究大样例。

来源：Day3 B sample4、Coderlands game 第28组。

## 捆绑子任务
不要同时做四个 70% partial。

```text
一个包
→ 证明
→ 编码
→ 专项验证
→ FROZEN
→ 再开下一个包
```

来源：Coderlands tree。

# 10. 当前 backlog 的排序原则

不是“哪个目录最空先补哪个”。

优先：
1. **有原始证据、但尚未写入仓库的高信息内容**；
2. **会纠正旧结论的内容**；
3. **32题中 full / partial 题解缺口**；
4. **能形成跨场 trigger 的经验**；
5. **可视化/数据化，使趋势可审计**；
6. 最后才是格式美化。

每读一段、考古一段，先落盘，再继续。
