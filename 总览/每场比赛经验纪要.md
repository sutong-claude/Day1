## Day5｜15｜数学已经很近，但“查询对象”被数据结构偷换

### 得分
- A 0
- B 15
- C 0
- D 未交

### A 是整个阶段的重要案例

后期你已经口头说出：

> 要找右边**最小位置** j，使得 r_j ≥ r_i。

这实际上已经是正确 query。

但代码用：
- multimap lower_bound；
- unordered_map；
- 无序 vector 上的 upper/lower_bound；

去做“按值搜索”。

也就是：

```text
数学：
first position satisfying condition

代码：
some value satisfying condition
```

### 重要校正

这场不是“几十个 Bug 最终一个都没修”。

67 次保存考古表明：
- 大量实现 Bug 被逐步清掉；
- 第二版几何/DP/面积/边界已经高度接近正确；
- 最终上游 blocker query 仍错，于是下游大面积污染。

### 永久经验

> **数据结构名字最后出现。**

先写：
`min j>i such that r[j]>=r[i]`

再认：
> Next Greater or Equal / 单调栈。

不能反过来：
> “我会 lower_bound，所以看看能不能塞进去。”

## Day6｜115｜错误继续后移到“数学充要性”

### 得分
- A 100
- D 15

### A 的意义

约 50 分钟稳定 AC，说明前题完整建模 + 实现 + 交付重新恢复。

### B/C 为什么危险

它们不是简单 coding bug。

B：
> 最大允许速率被误翻译成固定平均速率。

C：
> 赛时已经想到四类局部状态，但 forced / optional / impossible / off 的语义映射错误。

### 从这里形成“数学语义契约”

写优化代码前必须能回答：

```text
对象是什么？
这个条件为什么必要？
为什么充分？
代码返回的和数学对象完全同义吗？
```

### 影响下一场

Day7 B 中，用户已经更愿意先写定义级 brute、再优化，而不是直接魔改正解形状。

## net：研究能力比最终 OJ100 更值钱

过程不是“一眼直径”。

而是：
- 大样例；
- 直径中心；
- 主动质疑；
- 二分；
- 重心；
- DP；
- 第一版模型；

- 重新证明中心；
- 推出最深前沿扩张；
- 推倒重写。

最终 OJ100 代码仍有三点链 off-by-one。

这反而给出更高阶经验：

> **OJ100 后还需要最小边界审计。**

## game：一次非常完整的“模型反例升级”

- 先把答案压成 0/1/2/3；
- 分类；
- 样例通过；
- 大样例第28组打脸；
- 精确定位输入行；
- 手算；
- 得出“k=2 只有一刀，直接枚举”；
- 不再给旧 heuristic 打补丁；
- 清 zombie logic；
- 修 off-by-one；
- 100。

这是一条可以反复复制的优秀研究链：

```text
heuristic
→ counterexample
→ 找自由度
→ exact algorithm
```

---

## core/tree：捆绑赛制给出的新课

core 识别 Trie / EMPTY 入口并不差。

tree 甚至有：
- fixed path earliest-time；
- N≤5000 O(n²) partial；
- 链时间逆流；
- 多个 special。

但多个包同时半成品，在 bundled scoring 下可能全 0。

所以：

> **以后遇到捆绑子任务，一次只闭合一个包。**

# 这一整个阶段真正形成的能力

