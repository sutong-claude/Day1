## 一、六场不是“分数乱跳”，而是三条能力曲线叠在一起

分数：
45 → 130 → 204 → 0 → 15 → 115。

真正应该拆成三条曲线看：

1. **解题/建模能力**：总体在上升。Day2 A、Day3 A、Day5 A 主干、Day6 A/B/C 都说明用户经常能碰到核心结构。
2. **分数兑现能力**：Day1～Day3 上升，Day4/5 崩，Day6 回升。核心取决于 partial 冻结、时间切换、oracle 正确性和提交链。
3. **研究工程能力**：从几乎没有证据链，发展到 checker、附件、大样例、brute、generator、diff、replay、file_changes、键盘语义日志。这个提升非常明显。

因此 204 不是永久能力峰值，0/15 也不是能力归零；raw score 受卷子 partial 友好度影响很大。

## 二、用户真正擅长的东西

### 1. 能从局部现象摸到数学结构

典型：
- Day2 A：从样例/位权一路走到有符号二进制；
- Day3 B：从直接翻转枚举摸到栈约简与循环结构；
- Day4 A：已经发现“有人要撑住极值”的额外代价；
- Day5 A：明确问题是“右边第一个真正挡住的位置”；
- Day6 A：二分 → 容量 → gap → 545 反例 → 相邻耦合 → 贪心；
- Day6 B：日志点 → compatibility DAG → 最长链；
- Day6 C：固定 k → k-1/k 四分类。

这说明最缺的不是想法数量。

### 2. 对反例和异常很敏感

用户会主动说：
- “这个值怎么超过理论上限？”
- “这个条件不够吧？”
- “这种判定方法好像不对。”
- “两个局部都取最大会不会把中间撑爆？”

这种敏感度很适合 OI 研究。

### 3. 当模型稳定后，代码并不差

Day6 A 是最强证据：8 个独立源码状态、1 个 CE，约 50 分钟首交 100。

所以不能再用“代码能力差”概括近期失败。

## 三、当前最危险的共同问题：最后一次语义变换

最近四场很多错误表面不同，实际上是同一件事：

- Day4 B：窗口状态没有闭合；
- Day5 A：要 first-by-position，却写成 value search；
- Day6 B：最大允许速度被改写成固定平均速度；
- Day6 C：四分类已经有了，但类别语义没落成 forced / optional / impossible / off。

统一描述：

> **题意已经理解七八成，但最后把自然语言压成代码 predicate / data structure query 时，偷偷换了问题。**

下一阶段训练重点是“数学语义契约”：
对象是什么？必要吗？充分吗？代码返回的是同一个对象吗？

## 四、暴力观念必须升级

以后暴力不是“慢一点的聪明算法”，而是：

> **完全照题意直译、几乎不需要新猜想的真值机。**

Day6 C 是最典型教训。n<=5 时，本可枚举随机区间配置 + 2^n 亮灭 mask + 逐灯模拟；赛时为了少枚举一层，先发明 cnt 判定，导致 oracle 自己变错。

暴力的三个职责：
- 交小数据 partial；
- 给 full 做对拍 oracle；
- 自动制造最小反例。

## 五、部分分策略的新版本

不再只看“分值高不高”，而看三件事：
- 编码时间；
- 数学风险；
- 能否独立验证。

高性价比 partial 的典型：
- 小数据真 brute；
- 特殊性质只消掉一个明确困难；
- 已有正确 brute 后的预处理升级。

低性价比 partial：
- 为十几分重新写一套复杂 DP；
- predicate 自己都没证明；
- 和 full 一样需要核心建模。

Day6 如果资产化更好，现实地板大约可从 115 提到 155 左右：
A100 + B small15 + C oracle10 + D15 + D第二档15。

## 六、看不出算法时的推理框架

不要先问“这是啥算法”。

按下面顺序：

1. 给一个候选方案，我能不能完全照题意检查？
2. 固定哪个全局量后，问题会简单？
3. 真正承载约束的是点、边、gap、段还是状态？
4. 原始对象虽然很多，但对未来只有几种行为？
5. 第一猜想的最小反例是什么？
6. 两两关系能不能压成每个对象一个 key / 势能 / slack？
7. 正确 brute 到底重复算了什么？
8. 最后才认出 DP / 贪心 / LNDS / 数据结构。

四道 Day6 正好对应：
- A：gap + 反例；
- B：pair → key；
- C：固定 k + 行为分类；
- D：brute → 去重复计算。

## 七、时间管理不能再用死板“多少分钟切”

真正应该看最近 15～20 分钟有没有**新数学事实**。

有：
- 新反例；
- 新不变量；
- 新等价变换；
- 新状态压缩；
- 复杂度明确下降；

可以继续。

如果只有：
- if/下标/iterator/map；
- 换容器；
- 样例错但说不清为什么；
- 重复修同一种局部 bug；

说明已经进入低信息增益区：
冻结 partial → 回 oracle → 仍无新事实就切题。

Day6 A 虽然花了约 50 分钟，但一直在产生新事实，所以继续是对的。
Day5 A 后半程长时间围绕查询容器打转，才是真正该止损的类型。

## 八、Day3 204 与 Day6 115 怎么理解

Day3 的 raw score 高，既有真实进步，也有卷子更 partial-friendly 的因素：
- 独立测试点更碎；
- 特殊性质更多；
- 很多中间成果能换 5/10/20 分。

Day6：
- 算法标签更隐藏；
- B/C 连小数据都要求先把判定语义弄对；
- subtask 更捆绑。

因此：
**分数不能横向直接减法比较。**

更应该比较：
- 四题是否及时扫完；
- 首份稳定代码在什么时候；
- 有几个冻结资产；
- 是否有 oracle；
- 研究最后 20 分钟是不是还在产生新事实。

## 九、下午比赛的目标

不是“必须 200”。

### 底线目标
- T+60 前至少有 1 份可提交资产；
- T+90 前四题全部扫完；
- 至少 2 份 frozen partial；
- 最后 30 分钟禁止发明新 predicate。

### 正常目标
- 如果卷子偏 Day6：先守 140～170 的真实地板；
- 如果卷子偏 Day3/真实 CSP-S：争取 180～220；
- 有一题 full 很稳以后，再冲 200～250。

## 十、今天下午最重要的五句话

1. **小数据先写字面 brute，不要聪明。**
2. **特殊性质只问“它消掉哪个困难”，别自创额外条件。**
3. **pair 条件先看能不能压成单点 key。**
4. **20 分钟没新数学事实，就不是研究，是 Debug 黑洞。**
5. **已经确定的分，立刻冻结，不让 full 试验把它吃掉。**

## 十一、赛前最后 5 分钟检查

- 编译标准确认；避开 lcm/gcd/next/prev/y1 等全局雷区；
- freopen 文件名；
- submit 源文件唯一；
- notes 顶部写：机械验证 / 当前对象 / partial / 当前假设；
- 对每个“我觉得”标记 H，不把猜想当事实；
- 附件/checker 先查覆盖范围，尤其 YES/NO 是否都验；
- 最后提交前只做：编译、样例、极端、文件名、上传。
