# 3. Bug 1：k=2 不能靠端点/形状猜

## 第一版为什么诱人

k=2 只能切一刀。

最初很自然会想：
- 左边能否保 bit0；
- 右边能否保 bit1；
- 首尾是什么；
- 是否是“一串1 + 一串2”。

这类结构在 k>=3 时确实常有用。

## 大样例第28组打脸

录音：
- 首样例通过；
- 随后跑更大数据；
- 明确定位“第28个”错误；
- 手算对应行；
- 发现正确答案3，而程序给2。

随后得出正确判断：

> “k等于2的时候应该直接枚举，因为你哪知道啥情况？”

这句话是本题非常好的研究动作：

> **低自由度情况反而用精确枚举，不再继续猜结构。**

## 修复

加入：

```cpp
r[n] = a[n];
for (int i=n-1; i>=1; i--)
    r[i] = r[i+1] & a[i];
```

再维护前缀 AND `l`，枚举唯一切点：

[
(l_AND);|;(r_AND)
]

复杂度 O(n)。


- 输出；

# 5. Bug 3：旧的 k=2 shortcut 没删干净

加入精确 k=2 后，代码里仍残留：

- `k==2 && (a[1]==3 || a[n]==3)`；
- “前面全1、后面全2”一类启发式；
- 后面答案2/1也残留 `k==2` 首尾 shortcut。

这就是录音里说的“僵尸代码”。

v3/v4 做的很关键：

> **新模型已经覆盖旧模型时，把旧特判彻底删除。**

否则同一 k 会被两个不一致规则抢先 return。

# 6. Bug 4：k>=4 / k>=5 的自由度分层

比赛中逐渐发现：

- k>=4 时，若能把 1 / 2 分别隔离到不同段，得到3的条件放宽；
- 相邻 `1,2` / `2,1` 可作为局部构造；
- 若端点已有某一 bit，内部有另一 bit，也可构造；
- k>=5 时，分段自由度更大，只要全局同时存在1和2，就能把它们隔离出来。

这解释了为什么最终代码会按 k 分层，而不是一条统一短公式。

重要的是：
- 这些不是赛后编的；
- Replay v3 确实在 v3 加入大量 k>=4/5 条件；
- 录音也逐个讨论。

# 7. Bug 5：k=2 prefix 更新顺序 off-by-one

v4 的循环：

```cpp
int l=a[1];
for (int i=1; i<=n-1; i++) {
    ans=max(ans, l | r[i+1]);
    l &= a[i];
}
```

问题：
- 第一次循环又 `l &= a[1]`，没有推进；
- 到后续切点时前缀对应关系错一位。

v5 修为：

```cpp
ans=max(ans, l | r[2]);
for (int i=2; i<=n-1; i++) {
    l &= a[i];
    ans=max(ans, l | r[i+1]);
}
```

这就是一个很纯的实现语义错误：

> 循环变量 i 表示“右端点已经扩到哪里”，必须先把 a[i] 纳入前缀，再查询切在 i 后的值。
