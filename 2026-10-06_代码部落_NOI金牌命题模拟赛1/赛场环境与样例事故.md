# 赛场环境与样例事故：tree 为什么失去可靠验证链

> 这不是“替 tree 的错误代码找借口”。  
> tree 最终代码确实有数学/实现漏洞。  
> 本文件单独回答另一个事实：**为什么比赛最后阶段你没有得到正常、可信的样例反馈。**

# 2. tree 题面真实输入格式

题面/屏幕显示：

```

```

```text

```

T4/notes.txt 里也手抄了同一类格式。

# 3. 赛时真正复制进 T4 的“样例”是什么

Replay timeline 显示比赛后段实际打开：

`sample/1611727-1611726/1611726/`

并把其中数据复制到 T4，随后：
- 编译；
- 运行；
- `./main < 1-1-01.in > ans.out`；
- `diff -w 1-1-01.out ans.out`。

所以这些文件确实被你当作当前题验证数据使用，不是赛后目录偶然残留。

# 4. 但文件格式根本不是 tree

实际 `T4/1-1-01.in`：

```text
1 0 0
8
412517541
```

`T4/1-1-02.in`：

```text
2 3 5
10 13
1 2
```

第一行都不是单个 N。

这和 tree 题面输入格式直接冲突。

因此可以确定：

> **复制进 T4 的这批文件不是可用于本题的正确样例/测试数据。**

# 5. 这对赛时发生了什么影响

录音后段连续出现：

- “这样例对吗？”
- “为啥我没搞懂这个输出呢？”
- “不是这数据对吗？”
- 最后“算了，管他对不对”。

这和 Replay 的错误数据文件完全吻合。

所以后半段存在一个真实环境事故：

```
想验证 tree
→ 下载/复制数据包
→ 数据格式与题面不符
→ 输出无法解释
→ 验证链失真
→ 最后无法靠样例快速收敛
```

# 6. 但不能把最终0分全怪样例

最终 tree.cpp 本身至少还有：

- N≤5000 分支起点时间语义错误；
- 性质A直接空 return；
- 链分支 `l[n-1]` 与 `line[n-1]` 对象错位；
- 其他 special 未完整证明。

所以因果应写成：

> **代码确实不正确；错误样例包又让最后阶段失去了本来应该有的快速验证/修复机会。**

这两个事实同时成立。

# 7. 为什么旧报告“目录污染”说得不够准确

旧版写：

> T4目录有旧测试残留。

这只能解释“这些文件不可信”，却解释不了：

- 它们是怎么进入T4的；
- 你为什么真的拿它们 diff；
- 为什么录音里突然觉得样例/输出完全看不懂。

Replay 证明这是**赛中主动下载/复制的验证材料事故**，不是简单旧文件污染。

# 8. 下次硬规则

任何下载样例/测试包，运行前先做 15 秒格式体检：

1. 第一行字段数；
2. 是否满足题面范围；
3. N 后面行数是否合理；
4. 输出是否在理论上下界；
5. 文件名/网页链接是否对应当前题。

如果连输入格式都不符：

> **立刻停用该包。**

然后改用：
- 题面可见样例手工复制；
- notes 已抄样例；
- 自造极小数据；
- brute 对拍。

不能在坏 oracle 上 Debug 正确/错误算法。
