## 2. 小 N：实现 Bug 被修了，语义 Bug 没动

v2 初写 DFS：

```cpp
if (reach > r[i]) ...
dfs(y, max(l[i], reach));
```

这里 `i` 在 dfs 中不存在。

v4/v5 很快依次修成：

```cpp
r[y]
l[y]
```

v6 再修 `push_baxk`，于是代码终于编译。

这是正常的实现层收敛。

但是从 v2 到 v12 始终不变：

```cpp
vis[i]=true;
d[i]=1;
dfs(i,0);
```

也就是：
> 对每个起点，路径传播从 time=0 开始，而不是从起点真实选择的访问日 `l[i]`（最早安排）。

因此语义 Bug 没有随着 CE 清理被发现。

硬反例：

```text
3
100 100
1 1
50 50
1 2
2 3
```

- final：3
- truth：2

正文两个样例则恰好：
- sample1 final=5
- sample2 final=3

全部与标准答案一致。

所以这是非常标准的：
> **编译层越来越干净 + 样例全绿，但 state invariant 仍错。**

## 3. 性质 A：正确口头降维出现后，代码分支仍从 v2 到 final 一直空

v2 首次搭框架时：

```cpp
if (A) {
    // task 3

    return 0;
}
```

这段直到 v12 一字未补。

而原始录音约 03:08 已经说出：
> “特殊性质A……图上最长上升……”

这个降维实际上非常接近完整 15 分解：

当 `l_i=r_i=t_i`：
- 若边 u-v 满足 `t_u<t_v`，可定向 u→v；
- `t_u=t_v` 的边不能用于严格递增访问；
- 原树定向后无环；
- 求最长有向路径即可；
- O(N)。

所以这 15 分的状态不是：
> UNKNOWN

而更像：
> IDEA/PROVED-DIRECTION → **never CODED**。

这是本场最明显的“已发现得分资产没有物化”。

## 5. 链：v9 一次性写入后，数学逻辑几乎再没被验证性修改

v9 一次加入：
- 复原 `line[]`；
- 左端 interval transfer；
- 右端 interval transfer；
- `l[n-1]` 初始化；
- 输出两端最大前缀。

v9→v10：
- **只修星形那一行 CE**。

v10→v11：
- 只加 n=1。

v11→v12：
- 只开文件 IO。

也就是说：
> 链 special 从“第一次可编译”到正式提交，没有发生任何数学修订。

而它至少有三层问题：
1. interval transfer 方向没有表达访问日期严格递增；
2. `l[n-1]` 把节点编号当链位置；
3. 只看两端出发的前缀，题目最优路径可以完全位于链内部。

干净实测：
- n=5001 自然链；
- ([i,i])（i<5001），最后 ([5001,5002])；
- 整条路径可取日期1..5001；
- truth=5001；
- final=2。

```

```

它**没有制造** tree 的算法 Bug，
但它确实摧毁了最后一次发现 Bug 的机会。

## 7. 这条版本链最值得留下的训练结论

### 不要按“代码能编译”判断 partial 已闭合

v6 能编译，但小N invariant 错。

### 一个 special 未进入 VERIFIED，不允许并行开下一个

v8 星形还是 CE，v9 已经写链。

### “我口头想到了”要立即进入状态机

性质A 的正确降维在 03:08 已出现，但代码分支一直空到结束。

### 正文样例不是 oracle

两个正文样例都过，却没碰到起点时间漏洞。

### 验证材料必须先验格式

错误 sample 包让 v10 后逻辑冻结版失去了最后反例反馈。
