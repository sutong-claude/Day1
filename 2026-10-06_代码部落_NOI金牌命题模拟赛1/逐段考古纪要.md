## E-CL-014｜net 01:11｜“我要对拍”出现了，但验证动作没有完成就切题

**来源**：`模拟赛1_原文.docx` 与 `2026-10-06 01_49 记录_原文.docx` 两份同场原始转写全文互校；正式 net 源码；赛后独立反例。

原始录音在 net 第二代代码完成、样例通过后，约 01:10:48～01:11 明确出现：

> “要不然我对拍一下……我对拍一下。”

但随后没有形成可见的独立 brute/oracle 闭环，约 01:13 已切到 game。

后来证据已经证明：
- net 正式源码 OJ100；
- 但 M=1 三点链存在极小反例；
- 所以“官方100”并不能替代当时缺掉的独立验证。

### 修订结论 [P/process + X]

net 的问题不应只写成“忘了对拍”。

更准确：

```
验证意识已经触发
→ 但没有把意图物化成 checker/brute/stress
→ 样例通过后切题
→ 边界 Bug 存活
→ OJ100 又进一步制造假安全感
```

这和 Day3 B 形成互补反例：
- Day3：**有 checker，但 checker 契约不完整**；

> “我准备对拍/等会对拍”不算验证资产；只有可重复运行的 brute + generator + mismatch 结果才进入 VERIFIED。


## E-CL-015｜tree 最终提交｜不是“几个零散 Bug”：六个评分子任务现在都有独立反例

**来源**：
- 正式目录 `ZJ-029658/tree/tree.cpp`（4875B，和 Replay 最终保存同 SHA）；
- 原始题面完整子任务表；
- 本轮直接编译正式源码运行；
- 回归脚本：
  `验证/tree_最终代码_六子任务回归反例.py`

原题六档：
1. 10分：N≤300；
2. 15分：N≤5000；
3. 15分：性质A，所有 `l_i=r_i`；
4. 10分：星形；
5. 20分：链，编号不保证按链顺序；
6. 30分：无特殊性质。

### task1 / task2：同一个 3 点反例直接杀掉小 N 分支 [X]

```text
3
100 100
1 1
50 50
1 2
2 3
```

正式代码：

```cpp
vis[i]=true;
d[i]=1;
dfs(i,0);
```

把“起点真实访问日”丢掉，默认从 time=0 开始。

实测：
- final 输出：`3`
- 真值：`2`

因为：
- 2→3 可在日期 1,50 访问；
- 任何包含三个点的有向路径都要求把 100、1、50 按链方向严格递增，这是不可能的。

所以原本想统一拿下的 N≤300 / N≤5000 两档，并没有形成正确 brute partial。

### task3 性质A：最终分支是空的，连输出都没有 [P/source + X]

n=5001 的自然链：

```
i 的窗口 = [i,i]
边 = 1-2-...-5001
```

显然：
- 1→2→...→5001；
- 访问日就是 1..5001；
- 真值 = 5001。

但正式代码：

```cpp
if (A) {
    // task 3

    return 0;
}
```

实测 `tree.out` 为 **0 字节**。

这和录音形成一个很强的“想到但没物化”对照：
约 03:08 本人已经明确说性质A应转成“图上的最长上升”问题，
但正式代码分支最终完全空着。

实际上固定日期 `l_i=r_i=t_i` 时：
- 每条树边若 `t_u<t_v`，可有向 u→v；
- 若相等则这条边不能用于严格递增路径；
- 问题就是这棵有向无环树上的最长有向路径；
- O(N) DP 足够。

所以这 15 分不是“没有入口”，而是入口没有进入 CODED/FROZEN。

### task4 星形：两层错误，最终输出 3，真值 2 [X]

构造 n=5001：
- 中心1：([1,2])
- 叶2：([1,2])
- 其余所有叶：([1,1])

任何三点路径只能是：
`leafA → center → leafB`

要长度3，需要三个严格递增整数访问日。

但所有叶子的最大日期 ≤2：
- 不可能安排三个严格递增整数；
- leaf([1,1]) → center(day2) 可行；
- 因此真值恰好 2。

正式代码实测：
> **输出 3。**

第一层实现错：
- d1/d2 循环把 `root` 自己也算成“能到中心/能从中心到达”的候选。

但即使把 root 排除，核心判定仍不充分：

```cpp
leafA 能单独走到 root
+
root 能单独走到 leafB
```

不推出：
> 存在**同一个 root 访问日**同时满足
> `x_A < x_root < x_B`。

本例中一片 ([1,2]) 叶会同时触发两个单边 predicate，
程序把它与其他叶拼成 3，
却没有做三点时间区间的联合可行性检查。

所以星形 special 不是只差 `if(i==root) continue`。

### task5 链：整条 5001 点明明全可走，final 只输出 2 [X]

自然链 1-2-...-5001：

- 对 i<5001：([i,i])
- 点5001：([5001,5002])

性质A被最后一个非单点窗口关闭，所以确实进入链 special。

真值：
- 路径 1→2→...→5001；
- 取 `x_i=i`；
- **5001 个点全部可访问**。

正式代码实测：
> **输出 2。**

这说明链 special 的问题远不止之前发现的：

```cpp
L = l[n-1], R = r[n-1];
```

把节点编号 `n-1` 当作 `line[n-1]`。

它的整体 interval transfer 方向也没有正确表达“沿路径访问日严格递增”。

更根本地，赛时录音 03:23～03:25 的“时间逆流、左右各来一次”只检查从**两端叶子出发**的可行前缀；
而题目允许最优路径从链内部任意点开始和结束。

所以即使修掉编号对象错位，endpoint-only 模型本身仍不等价于题意。

### task6 一般树：fallback=1 也有精确反例 [X]

取 n=5001 的“双中心树”：
- 中心 1—2 相连；
- 一半叶挂1；
- 另一半叶挂2；
- 所有点窗口都是 ([1,2])。

它：
- 不是星形；
- 不是链；
- A=false；
- n>5000；
所以进入最终：

```cpp
cout << 1 << '\n';
```

但真值恰好是 2：
- 任意一条边都能用 day1→day2 访问两个点；
- 所有窗口只有整数1、2，不可能访问3个点。

实测 final：
- 输出1；
- 真值2。

### 最终修订

tree 的 0 分现在不能再概括成：

> “小 N 起点 Bug + 链编号 Bug + 样例包错了。”

更完整的是：

```
task1/2  小N brute：时间状态契约错
task3    A：正确降维入口出现，但代码分支为空
task4    星形：把两个存在性条件错误拼成同一次中心时间
task5    链：时间变换错误 + 对象错位 + endpoint-only模型
task6    full：直接 fallback 1
+
最后用于验证的数据包格式又不是本题
```

这解释了为什么“错误 sample 包”只能解释**为什么最后没收到正确反馈**，
绝不能解释 tree=0 的算法原因。

## E-CL-016｜core 的 EMPTY 不是瞎猜｜赛时入口距离一个精确 O(N) 判定只差“数首字符”

**来源**：
- 原始题面；
- 原始录音 02:46～02:48；
- T3 三次 file_changes；
- 正式 `core.cpp`；
- 独立穷举：
  `验证/core_EMPTY严格判定与最小反例.py`

### 赛时原话非常关键

约 02:47：

> “第一步我会尽可能的先按空串，就是选择 K 个没有的先看能不能，如果不能的话，再想别的办法。”

这不是无效想法。

题目定义：
- 选 k 个字符串；
- L = 所选任意两串 LCP 的**最大值**；
- L=0 时核心串就是 EMPTY，而且空串在字典序上全局最小。

因此第一问确实应该是：

> 能不能让 L=0？

### 精确定理 [P]

对于非空小写字符串：

```
两串 LCP = 0
iff
首字符不同
```

而：

```
L = 所有 pair LCP 的最大值
```

所以：

```
L=0
iff
选出的 k 个字符串两两首字符不同
iff
原数组中至少存在 k 种不同首字符
```

因此：

> **EMPTY 是全局答案，当且仅当不同首字符种数 ≥ k。**

只需要一个 26 维 bool / counter，
复杂度 O(总字符数)。

特别地：
- 小写字母只有26种；
- **k>26 时 EMPTY 必然不可能。**

### 本轮独立验证 [E]

用小字符串宇宙：

```
a,b,c,aa,ab,ba,bb,ca
```

枚举：
- n=2..5 的所有多重集合；
- 所有 k=2..n；
- 对每个选择集合暴力算 pairwise LCP 和真正 core；
- 再与“不同首字符≥k”比较。

共 **4434** 个 `(multiset,k)`：
- 0 mismatch。

### 最小 final 反例

```text
2 2
a
aa
```

唯一选择就是 {a,aa}：
- LCP=1；
- 正确 core=`a`；
- final 无条件输出 `EMPTY`。

这已经是最小 n/k 反例。

正文样例也直接区分：
- sample1 k=3：首字符只有 `a,b` 两种 <3 → 正确 `a`，final 错；
- sample2 k=2：至少两种首字符 → EMPTY，final 对。

### 代码版本链进一步说明问题

T3 只有三次保存：

1. 345B：只完成读入；
2. 373B：加入无条件 `cout<<"EMPTY"`；
3. 377B：只再打开 `core.in/out`，成为正式提交。

所以赛时真正缺掉的不是 Trie 代码写到一半，
而是：

> **已经提出“先判 EMPTY”，却没有把 EMPTY 的存在性条件写成一个可证明的 predicate。**

这和 Day6 C 的教训高度相似：
自然语言分类入口是对的，
但没有把“什么时候成立”做成必要充分条件。

### 机会成本的准确说法

不能说：
> “数首字符就能保证拿某个完整子任务分数。”

因为子任务只限制 n/k，并不保证数据一定满足 EMPTY。

但可以说：
> 这是一个几分钟内能闭合的 **PROVED safe branch**。

赛中至少应该写成：

```cpp
if (distinct_first_chars >= k) {
    cout << "EMPTY\n";
    return;
}
```

然后：
- 该分支一旦触发，答案百分之百正确；
- 不触发再决定继续 Trie / 切题；
