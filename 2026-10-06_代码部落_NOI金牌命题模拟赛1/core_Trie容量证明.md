# core：Trie 容量 + 字典序扫描正解

> 这是赛后二次复盘独立推导；赛时只识别到 Trie / EMPTY 入口，没有完成这一步。

设选出的 k 个字符串集合为 S，`L` 是其中任意两串 LCP 的最大值。

核心串 t：
- 长度恰为 L；
- 是至少两串的公共前缀；
- 在满足条件的长度-L前缀中，字典序最小。

## 1. 固定深度 d：怎样保证最大 LCP≤d

看 Trie。

对某个深度 d 的前缀节点 u：

- 所有**恰好结束在 u** 的字符串可以全部选；它们两两 LCP=d，不会超过 d；
- u 的每个孩子子树中最多选1个，否则同一孩子内两串 LCP≥d+1。

因此在 u 这块区域里最多能选：

```text
local(u) = endcnt(u) + childcnt(u)
```

全局来看：

- 长度≤d 的字符串全部可以选；
- 长度>d 的字符串按“深度 d+1 前缀”分组，每组最多1个。

于是：

```text
globalCapacity[d]
= #长度≤d的输入字符串
+ #深度 d+1 的 Trie 节点
```

这就是“最大 pairwise LCP≤d”时能选的最多字符串数。

## 2. 固定候选核心串 u

若 u 的深度是 d，要让 u 成为核心串，必须：

1. `local(u)≥2`，这样至少有一对字符串 LCP 恰好为 d；
2. 所有字典序比 u 小的**同深度节点** v，都不能选到2个，否则 v 会成为更小的核心串；
3. 后面的同深度节点可以按原容量选择。

所以对每个更小的 v，需要把它从 `local(v)` 限制成1，损失：

```text
max(0, local(v)-1)
```

候选 u 可行当且仅当：

```text
local(u) >= 2
且
globalCapacity[d] - sum_{v<u}(local(v)-1)_+ >= k
```

因为只要最大可选数≥k，就可以：
- 先从 u 取2个；
- 再从其他允许槽位任取，补到恰好k个。

## 3. 为什么 Trie preorder 就是答案顺序

标准字符串字典序满足：
- 一个字符串是另一个的前缀时，短的更小；
- 否则看第一个不同字符。

Trie 做 preorder，并按孩子 a..z 访问，恰好得到所有前缀字符串的完整字典序：

```text
"" , "a", "aa", ..., "ab", ..., "b", ...
```

因此从 root 开始按 preorder 扫描，第一个满足可行条件的节点，就是所有可能核心串中字典序最小的那个。

root 对应空串，所以能选 k 个首字符互不冲突的字符串时会自然输出 `EMPTY`。

## 4. 如何 O(total length) 维护

对每个深度 d 维护：

- `globalCapacity[d]`；
- 已经扫描过的、更小的深度-d节点造成的总损失 `earlierLoss[d]`。

扫到节点 u 后若不可行，就：

```text
earlierLoss[d] += max(0, local(u)-1)
```

每个 Trie 节点只处理一次。

复杂度：
- 时间 O(总字符串长度 × 字符集常数)；
- 空间 O(总字符串长度)。
