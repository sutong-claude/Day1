# 试卷画像与榜单分析

> 这份文档回答的不是“我这场哪里错”，而是：**这套模拟赛本身是什么性质、分数有多可比、题目/数据/评分制度质量如何。**

## 1. 先看榜单：54 人不等于 54 个有效参赛样本

榜单共 54 行，但：
- 非零：15 人；
- 0 分：39 人；
- 非零率：27.8%；
- 全榜平均分约 40.6；
- 全榜中位数 0。

所以本人第 3/54 是真实榜单名次，但做阶段能力比较时不能机械理解为“54 个完整打满4小时的人里第三”。榜单明显包含大量零分/可能未有效作答账号。

更稳妥的两个视角：
- 全榜：3/54，前约5.6%；
- 非零选手：3/15。

本人200分仍然是很强结果，因为前两名分别220、210，第四/五名175。

## 2. 每题得分分布

| 题 | 非零人数 | 100人数 | 最高分 | 全榜平均贡献 | 观察 |
|---|---:|---:|---:|---:|---|
| net | 14/54 | 3 | 100 | 15.83 | 部分分很多，但满分少；T1并不送 |
| game | 14/54 | 8 | 100 | 20.00 | 最多人整题AC；对这批选手反而比net更容易做满 |
| core | 6/54 | 0 | 40 | 3.33 | 极难；绝大多数0，最高也只有40 |
| tree | 2/54 | 0 | 50 | 1.39 | 最难/最难兑现；只有两人非零 |

前15个非零总分依次为：

`220, 210, 200, 175, 175, 150, 140, 135, 135, 125, 120, 115, 110, 100, 80`。

非零选手中位数为135。这说明真正动手完成比赛的人并非整体弱，而是 C/D 的得分确实非常稀疏。

## 3. 难度结构：不像“标准 CSP-S 分数校准卷”

如果目标是预测真实 CSP-S 分数，这套卷的可信度要打折：

1. T1 net 只有3人满分；
2. T2 game 反而有8人满分；
3. T3 core 只有6人非零、最高40；
4. T4 tree 只有2人非零、最高50。

这更像：

> **前两题有完整思维题价值，后两题明显拔高的高强度训练卷。**

而不是典型的“按正式 CSP-S 参赛人群做稳定分层”的还原卷。

因此这场200分不能直接和代码源 Day3 的204、Day7的145比较。

## 4. 但赛制/交付环境的“正式感”反而更强

本场规则显式要求：
- 考号目录；
- 四道题各自英文子目录；
- cpp 文件名严格对应；
- 传统文件输入输出；
- 编译参数 `-O2 -std=c++17 -static`；
- 4小时限时；
- 结束后统一更新成绩；
- tree 明确采用整组 subtask 通过才给该组分。

所以它在**文件交付纪律、传统 OI 工作流、赛后统一评测**方面比代码源在线 OJ 更像正式线下考试环境。

结论应分成两轴：

| 维度 | 评价 |
|---|---|
| 考场交付/文件规范还原度 | 高 |
| 4小时 OI 工作流还原度 | 高 |
| 难度分布对 CSP-S 常规人群的还原度 | 中低 |
| 高难思维训练价值 | 高 |
| 裸分用于预测真实 CSP-S 成绩 | 低～中 |

## 5. 评分制度：对子任务“闭合”要求非常强

tree 是最典型例子。

本人 raw tests 实际通过不少：
- 第1组 7/8；
- 第4组 7/8；
- 其他组也散落多点 AC；

但每组只要一题错，整组归0，最终100分题得到0。

这会改变最佳比赛策略：

### 代码源式思路
`先写几个 special，能过多少点算多少。`

### 本体系正确思路
`选一个子任务 -> 把特殊性质写成完整命题 -> 专门造边界 -> 整包冻结 -> 再开下一个。`

因此这套赛制很适合训练**证明一个 partial 的完整性**，但不适合用 raw AC 点数估分。

## 6. 数据质量必须和题目质量分开评价

### net：数据存在明确漏洞

本人官方20/20、100分，但赛时最终程序在

```text
3 1
1 2
2 3
```

上输出2，正确答案1。

这是极小、极自然的中心点 off-by-one。官方数据完全没覆盖，说明 net 的隐藏数据质量至少存在一个明显缺口。

所以 net 应评价为：
- 题目结构/训练价值：可以很高；
- 本次官方数据完备性：有实证缺陷。

### game：当前证据更健康

最终代码不仅官方10/10，还在 n≤7 的所有数组/所有k 共145,636实例上与枚举切分真值0 mismatch。

至少小空间结构覆盖很强。

### tree：数据对错误 special 的击穿能力较强

本人多个 special 都能过一部分点，但各组都被边界数据击穿；从现象上看，tree 数据比 net 更能区分“不完整 partial”。

## 7. 对本人200分的正确解读

不应该写：

> “200分，所以能力≈代码源Day3 204。”

应该写：

> **在一套后半段极难、评分捆绑、前两题整题价值高的卷子上，前两题都完整做出，因此形成了非常干净的200分；这是‘整题闭合能力’的强证据。**

与此同时：
- net 的100有未被OJ发现的实现漏洞，所以是 OJ-AC，不是 PROVED；
- game 的100经过145,636小实例独立验证，证据更强；
- core/tree 的0也不能等价成完全不会：core抓到Trie入口，tree写了多个partial，但没有整包闭合。

## 8. 这套比赛今后在训练体系中的定位

建议标为：

> **高强度 CSP-S/NOI 风格思维训练 + 传统文件交付训练；不作为单独的真实 CSP-S 分数预测器。**

最值得继续打的训练目标不是“分数越高越好”，而是：
1. 前两题能否继续稳定做满；
2. C/D 能否至少闭合一个完整 subtask；
3. OJ100 后是否还能用独立 brute 找实现漏洞；
4. 最后30分钟的文件目录/freopen/版本检查能否零事故。
