## 三、net：100分，但必须纠正“100=绝对正确”

最终代码有：

```cpp
road.push_back(0);
...
int len = road.size() - 1;
int pos = len / 2;
int root = road[pos];
```

对三点链、M=1：

```
3 1
1 2
2 3
```

代码会取直径端点而不是中点，输出2；实际选房间2即可得到1。

这是一个真实最小反例。

### 为什么官方仍100

官方20个点没有击穿这个 off-by-one。这里必须明确：

> **OJ-AC 是“通过这批数据”的证据，不是数学证明。**

### 一行修正后的证据

把中点下标修正后，对 n≤7 的小树/不同M做精确枚举对比，目前检查 **43,491** 个实例，0反例。

因此现在的结论是：

- “从中心开始扩展最深前沿”的主体思路目前有很强证据；
- 赛时最终实现有一个哨兵造成的中点 off-by-one；
- 尚未在仓库里把主体定理写成完整证明，所以标记 BRUTE-VERIFIED，不冒充 PROVED。

## 四、game：本场最硬的成功

最终代码很长，但核心有两个正确决策：

1. k=2 不猜，直接前后缀 AND 枚举切点；
2. k≥3 利用数值只有0..3，最终答案也只有0..3，按“能否造出bit0 / bit1”的结构分类。

赛后验证：
- n=1..7；
- 所有 0..3 数组；
- 所有 1≤k≤n；
- 总计 **145,636** 个输入；
- 与枚举所有切分位置的真值逐个比较；
- **0 mismatch**。

这是非常重要的能力证据：你在考场里通过样例、反例、逐行输出不断补洞，最后确实把一个复杂分类讨论闭合了。

## 五、core：0分不等于“完全随机”

最终只输出 EMPTY，但 raw test 仍过 11/50。

赛时已想到：
- Trie 是自然结构；
- 最先要判断 L=0 是否可行；
- 若能选 k 个字符串让任意两串首字符不同，则 EMPTY 是最优。

真正没完成的是把“选择 k 个”转换为 Trie 上的容量/冲突约束。

这题应归类为：

> **识别数据结构正确，但组合约束没有数学化。**

而不是“不会 Trie”。

## 六、tree：这场最值得复盘的 partial 失败

你本来计划70分，但最终0。原因不只是捆绑制度，也有具体代码语义错误。

### N≤5000 暴力的最小反例

DFS 从起点调用：

```cpp
dfs(i, 0);
```

这等价于把起点访问时间当作0，却没有先选择一个 `x_i∈[l_i,r_i]`。

例如链：

```
3
100 100
1 1
50 50
1 2
2 3
```

程序从1出发会错误地认为可按 0→1→50 访问三个点，输出3。

但真实起点1只能在100访问，之后不可能去日期1的点2；反向50→1→100也不行。最优只有2。

所以 N≤300/5000 的“暴力 oracle”本身就没有精确模拟题意。

### 性质A

代码明确留空：

```cpp
if (A) {
    // task 3
    return 0;
}
```

这意味着该15分包不可能得到。

### 链分支还有明显下标问题

反向初始化写成：

```cpp
L = l[n - 1], R = r[n - 1];
```

这里用的是节点编号 n-1，而不是链上对应的 `line[n-1]`。编号不保证按链顺序，正好违反子任务说明。

所以“链20分”也不是差一个小边界，而是有明确对象错位。

## 七、为什么 raw tests 看起来过很多，最后仍是0

这是本场新增的 scoring lesson。

例如 tree：
- 第1组只差1个点；
- 第4组也只差1个点；
- 其他组也散落很多AC；

但每个子任务必须整组通过，任何一个WA都把整包清零。

这说明以后在这类比赛中：

> **测试点覆盖率不是得分预测器；子任务闭合度才是。**

赛中 partial 的工作流要改为：

1. 选一个子任务；
2. 写该性质的 iff / 精确模拟；
3. 为该性质造边界数据；
4. 通过后冻结；
5. 再进下一个子任务。

不要同时铺五个“差不多”的 special。
