# 二、v0→v1：不是最后一小时才突然写了个框架

v0 的确只有521B输入框架。

但 v1 直接长到1902B，一次性加入：
- `vis[]/d[]`；
- DFS 访问日期逻辑；
- N≤5000 循环；
- 性质A分支；
- 星形检测；
- 链检测。

这说明当时的策略就是：

> **先搭一个统一文件，把多个 subtask 的入口都铺出来。**

问题也埋在这里：铺得太宽，每个包还没证明就开下一个。

# 三、v1→v5：前20分钟主要在修“小数据暴力”的实现 Bug

连续几个版本字节几乎不变，但每次只有一行变化：

## v2

新增 `ans/res`，把 DFS 真正转成“求最长访问路径长度”。

## v3

```cpp
if (reach > r[i])
```

改成：

```cpp
if (reach > r[y])
```

这是典型“循环外 i 泄漏到递归语义”的变量错位。

## v4

递归：

```cpp
dfs(y, max(l[root], reach));
```

改成：

```cpp
dfs(y, max(l[y], reach));
```

又一次是“当前节点 root”和“下一节点 y”的对象错位。

## v5

`push_baxk` 才修成 `push_back`。

所以 tree 前段不是在研究新数学，而是：

> **把 N≤5000 这份基础 partial 从根本不能跑，逐步修到能跑。**

但它还留着更深的数学 Bug：起点仍用 `dfs(i,0)`。

# 四、v7：星形 special 真正形成

v6→v7 增加约45行。

新增：
- 找中心 root；
- `d1[i]`：尝试表示叶→中心可行；
- `d2[i]`：中心→叶可行；
- 根据两侧候选数量判断答案1/2/3；
- 两侧唯一时防止选到同一叶。

这说明录音里“星形最多三个点”的想法确实落进代码了。

但 v7 中甚至出现：

```cpp
int reach = l[root], l[i] + 1;
```

这种明显损坏的语句，v9才改。

# 五、v8：链 special 不是空想，完整算法块一次性出现

v7→v8 增加约50行。

新增完整：
- 找两个叶端；
- 恢复 `line[]`；
- 从左端维护 `[L,R]`；
- 每走一步 `L--,R--` 再与下一个窗口取交；
- 从右端对称再扫；
- 比较两边最长可行长度。

这就是录音里的“时间逆流”。

所以正确评价不是：

> “链题没想出来。”

而是：

> **链 special 的核心区间传播已经编码，但边界和对象索引没闭合。**

# 六、为什么最终仍0：三个独立层次

## 层1：基础 brute 自己不精确

`dfs(i,0)` 没把起点访问日放进 `[l_i,r_i]`。

## 层2：多个 special 没整包闭合

- A 最终空 return；
- 星形未独立验证；
- 链反向起点用 `l[n-1]` 而不是 `l[line[n-1]]`。

## 层3：最后 oracle 错题

赛末复制进 T4 的下载文件第一行 `1 0 0`，根本不符合 tree 输入格式。

因此后半段 Debug 无法获得可信反馈。

# 八、真正该学的

这份12代历史把 tree 的失败从“时间不够”拆开了：

```text
先铺5个包
→ 小数据分支持续修实现
→ 星形再开新包
→ 链再开新包
→ 每包都有未闭合条件
→ 最后又失去正确oracle
→ 捆绑计分全0
```

下一次捆绑子任务，应该改成：

```text
只开一个包
→ PROVED
→ CODED
→ VERIFIED
→ FROZEN
→ SUBTASK-CLOSED
→ 再开下一个
```
