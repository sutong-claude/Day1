# tree：N≤5000 的精确 O(N²) partial

赛时的 N≤5000 分支方向是对的，但 `dfs(i,0)` 把起点访问日语义写坏了。

正确版本其实很直接。

## 固定一个有向路径

若路径是：

```text
v1 -> v2 -> ... -> vk
```

最优做法一定是每个点尽量早访问：

```text
t1 = l[v1]
ti = max(l[vi], t(i-1)+1)
```

若某一步 `ti>r[vi]`，则这条方向不可能。

证明：任何其他合法安排在每个前缀上的访问时间都不会比这个“最早安排”更早，所以最早安排都超上界时，不存在别的救法。

## 树为什么能 O(N²)

固定起点 s 后，到任意终点 v 的简单路径唯一。

从 s 做一次 DFS，把“最早可行时间”向外传播：

- 若能到 v，则 s→v 是一条合法有向路径；
- 若在 v 失败，则从这个方向再往外只会更晚，也无需继续。

每个起点一次 O(N)，枚举 N 个起点，总计 O(N²)。

N=5000 时约 2500 万级节点转移，当前本地容器链状极限实测约 0.4s，仅作实现压力参考。

## 独立验证

`验证/tree_N5000_随机暴力.py` 做了 20,000 组随机小树：

- n≤8；
- 开放区间端点在1..6；
- 真值枚举所有有向端点对，并对路径日期做独立回溯搜索；
- 与 O(N²) earliest-time DFS 比较；
- **0 mismatch**。

C++ 版本实际编译，并通过题面两个正文样例：5、3。

证据等级：**PROVED + BRUTE-VERIFIED**。

这至少把赛时本来想拿的 N≤300 / N≤5000 小数据路线真正闭合；不冒充 tree 的满分解。
