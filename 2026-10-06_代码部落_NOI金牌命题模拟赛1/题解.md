# A. 网络重建 net

## 1. 题目人话

树上选择恰好 M 个房间放路由器，并且这些房间必须构成一个连通子树。

每个房间的损失是到最近路由器的树距离，目标：

> 最小化全树最大的这个距离。

所以本质是：

> **选一个大小为 M 的连通点集，使全树到该集合的最大距离最小。**

## 2. M=1 先看什么

M=1 时就是经典树中心：选一个点最小化最大距离。

这自然把视线拉到直径中部。

赛时正是从这里开始。

## 3. 赛时主体算法

最终代码采用：

1. 两次 BFS 找一条直径；
2. 取直径中部附近作为初始 root；
3. 以 root 为根，计算每个节点向下最深距离 d；
4. 把 root 放入 priority_queue；
5. 每次取当前 `d` 最大的边界点加入路由器集合，再把它的未选邻居加入队列；
6. 直到选择 M 个点；
7. 枚举 selected → unselected 的边界，取剩余子树最大深度作为答案。

它的核心直觉：

> 已选集合始终连通；每次优先吞掉目前最深、最可能控制最大损失的方向。

## 4. 最终提交有一个真实实现 Bug

代码先：

```cpp
road.push_back(0);
```

真实直径顶点在 `road[1..len]`。

随后却：

```cpp
int pos = len / 2;
int root = road[pos];
```

三点链：

```text
3 1
1 2
2 3
```

应选2号点，真值1；最终代码输出2。

所以最终代码证据等级是：

> **OJ-AC + COUNTEREXAMPLE**。

修正中点索引后，小树43,491实例暂0 mismatch，标 BRUTE-VERIFIED；当前仓库仍缺完整数学证明，不能写 PROVED。

## 5. 比赛时如何更稳

强猜想写完以后立刻扫：
- N=1/2/3；
- M=1；
- M=N；
- 直径顶点数奇偶。

这个 Bug 用 N=3,M=1 就能抓住。

# B. 分段游戏 game

## 1. 第一步：把数字看成两个 bit

`0,1,2,3` 分别表示两个徽记是否存在。

一个段的 AND 表示：

> 这个 bit 必须在该段每一张卡片上都存在，才能保留下来。

所有段再 OR 表示：

> 只要至少有一个段保住 bit0，就能得到1；至少一个段保住 bit1，就能得到2。

因此答案只有：

```text
0,1,2,3
```

整题变成“两个 bit 能不能分别被某些段保住”。

## 2. k=1：整段 AND

只有一种切法：

```cpp
ans = a1 & a2 & ... & an
```

O(n)。

## 3. k=2：不要猜结构，精确枚举唯一切点

只有一刀切在 i / i+1 之间。

左段：

```text
L[i] = a1 & ... & ai
```

右段：

```text
R[i+1] = a(i+1) & ... & an
```

答案：

```text
max_i ( L[i] | R[i+1] )
```

预处理 suffix AND，再滚动维护 prefix AND，O(n)。

### 为什么这一步很重要

赛时第一版曾尝试用端点和“1串/2串”结构猜 k=2。

大样例第28组直接反例后，才升级成这个精确算法。

这是正确的研究动作：

> **自由度只有一刀，就枚举一刀，不值得猜。**

## 4. k>=3：利用两个 bit 的有限状态做分类

最终赛时代码按“能否得到3→2→1→0”判断。

得到3意味着：
- 至少能构造一个段保住 bit0；
- 至少能构造一个段保住 bit1；
- 两者可以是同一段（AND=3），也可以来自不同段。

代码利用：
- 出现单个3；
- 首尾1/2互补；
- 前后连续结构；
- 相邻1/2；
- k>=4、k>=5 后分段自由度进一步增加；

逐层判断能否把1、2隔离到有利的段。

### 当前证据等级

这套分类：
- OJ 100；
- n≤7 的全部 0..3 数组、全部 k，共 145,636 个实例与暴力切分真值 0 mismatch。

所以标：

> **OJ-AC + BRUTE-VERIFIED。**

仓库当前没有一份完整形式化 casework 证明，所以暂不标 PROVED。

## 5. 本题真正值得学什么

不是背最终十几个 if。

而是：

```text
值域只有4
→ 拆成2个bit
→ 答案只有4种
→ 先做低自由度 k=1/2 exact
→ 再对高自由度做有限状态分类
→ 写小 brute 自动验证分类
```

这才是可迁移方法。

# C. 谁是核心串 core

## 1. 题目本质

从 n 个字符串中选 k 个。

定义 L：所选字符串中，任意两串 LCP 的**最大值**。

希望先让 L 尽可能小；达到最优 L 后，再找字典序最小的“核心串”。

## 2. 自然数据结构：Trie

因为所有约束都围绕前缀：
- 两个字符串在哪个深度还在同一 Trie 节点；
- 某个前缀下有多少字符串；
- 在某深度能否把 k 个选择分散到不同前缀块。

所以 Trie 识别是正确的。

## 3. 最先检查 L=0

L=0 等价于所选任意两串第一字符都不同。

若能选 k 个首字符互不相同的字符串，则：

```text
答案核心串 = EMPTY
```

这是赛时已经想到的正确入口。

## 4. 真正难点

不是“会不会写 Trie”。

而是：

> **如何在 Trie 上选择恰好 k 个叶子，使任意同一深前缀下的冲突受控，并同时处理最小 L 与字典序。**

这需要一个完整的组合/容量判定。

## 5. 当前材料边界

本轮用户提供的题面、录音、Replay、最终代码中，没有可靠官方完整题解，也没有我们已经独立证明的 full solution。

因此这里**不冒充满分题解**。

仓库当前能确定的是：
- Trie 是对的入口；
- L=0 / EMPTY 是第一层；
- 赛时卡在“选 k 个”的全局组合条件。

后续若拿到官方题解，应在此文件补：
- 对固定 L 的可行性条件；
- 最小字典序构造；
- 正确性证明与复杂度。

# D. 巡游树 tree

## 1. 固定一条有向路径后怎么验证

给定路径：

```text
v1 -> v2 -> ... -> vk
```

每个点选择访问日 `xi∈[li,ri]`，并要求严格递增。

最稳的可行性贪心：

```text
t = l[v1]
下一点 t = max(l[next], t+1)
若 t > r[next]，失败
```

为什么？

因为每一步选择**最早可能日期**，给未来留下的空间最大。

这就是赛时 N≤5000 / 链思路里真正正确的局部核心。

## 2. N≤300/5000：赛时想做暴力，但最终实现不是正确 oracle

赛时方向是：
- 从每个起点出发；
- DFS简单路径；
- 沿途维护最早可行时间；
- 取最大路径长度。

但最终代码调用：

```cpp
dfs(i, 0);
```

没有先让起点在 `[li,ri]` 内选择访问日期。

因此这份“brute”本身会造假路径。

## 3. 星形树

星形的简单路径最多：

```text
叶 -> 中心 -> 叶
```

所以只需判断能否访问1、2、3个点。

赛时代码用 `d1/d2` 判断两侧可达性，方向合理，但最终没有专项证明/独立 oracle，因此不能直接标完整10分。

## 4. 链：时间逆流/区间传播

恢复链顺序 `line[]` 后，赛时用可行时间区间 `[L,R]` 传播。

沿链走一步，相邻访问日至少差1，因此可把当前区间平移，再与下一点的 `[li,ri]` 取交。

从两端都做一次，可以研究最长可行前缀/后缀。

这是赛时很有价值的 special 思路。

但最终代码反向初始化：

```cpp
L = l[n-1], R = r[n-1];
```

把“链的第 n-1 个位置”写成“编号 n-1 的节点”，而题面明确节点编号不按链顺序。

所以对象错位。

## 5. 为什么最后没靠样例修掉

这场还发生真实验证事故。

赛末复制进 T4 并实际运行的所谓样例文件，第一行是：

```text
1 0 0
```

而 tree 的第一行应只有一个 N。

也就是说输入包根本不是本题格式。

所以最后反馈链变成：

```text
代码有错
+ 错误格式 oracle
→ 输出完全无法解释
```

这解释“为什么最后调不明白”，但不改变代码本身确实有漏洞的事实。
