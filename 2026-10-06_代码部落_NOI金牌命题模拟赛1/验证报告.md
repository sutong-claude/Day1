# 独立验证报告

## 1. net：官方100，但发现最小反例

最终官方：20/20 AC。

独立运行最终源码：

输入：

```
3 1
1 2
2 3
```

程序输出：

```
2
```

数学真值为1：只选择中间点2即可。

### 原因

代码先：

```cpp
road.push_back(0);
```

之后直径顶点实际在 road[1..len]，却用：

```cpp
int pos = len / 2;
int root = road[pos];
```

奇数个直径顶点时会向端点偏一格。

### 修正后的实验

修正中点索引后，用精确暴力枚举所有连通 M 点集合求真值，对 n≤7 的小树进行系统比较。

当前检查：**43,491 个 (tree,M) 实例，0 mismatch。**

结论：
- 最终赛时代码：OJ-AC，但存在已知反例；
- 修正版本：BRUTE-VERIFIED（小树），暂不冒充完整数学证明。

## 2. game：145,636 个穷举实例 0 mismatch

最终赛时代码重新编译。

真值程序：
- 枚举 n≤7 所有 0/1/2/3 数组；
- 枚举每个 1≤k≤n；
- 枚举所有恰好 k 段的切分；
- 计算每段AND、再OR，取最大。

总实例：

**145,636**

结果：

**0 mismatch。**

最终程序一次批量运行约0.03s（当前容器，仅作相对验证，不当作官方环境性能结论）。

证据等级：OJ-AC + BRUTE-VERIFIED。

## 3. core：EMPTY fallback

最终程序无条件输出 EMPTY。

官方 raw tests 50个中过11个，但由于子任务捆绑，总分0。

这只能说明某些数据确实允许选出 k 个字符串使最大两两LCP为0，不能说明算法覆盖了任何完整子任务。

## 4. tree：找到 N≤5000 分支的语义反例

最终小数据 DFS：

```cpp
vis[i]=true;
dfs(i,0);
```

没有把起点的访问日放入 [l_i,r_i] 语义中。

反例：

```
3
100 100
1 1
50 50
1 2
2 3
```

程序输出3。

真实最优2：
- 1→2 不可能，因为100后不能访问1；
- 3→2→1不可能，因为50后不能访问1；
- 可取2→3等长度2路径。

### 链 special 的明确对象错误

代码：

```cpp
L = l[n - 1], R = r[n - 1];
```

但链编号题面明确“不保证按链顺序”，这里应该使用复原后的 `line[n-1]` 对应节点，而不是裸编号 n-1。

### 性质A

该分支为空，直接 return，没有输出。

因此 tree 的0不能只归因于“捆绑评分太狠”：代码本身确实存在多个模型/实现缺口。
