# 2. net：不是一条线写到100，而是推倒过一代模型

10个保存状态最醒目的变化：

- v0/v1：约1444B，已有第一代树上算法；
- v2～v4：突然缩到796/764/703B——说明本人真的把一版思路推倒；
- v5以后重新增长到1586/1654/1715B；
- v8/v9 达到2306/2308B，形成最终直径+BFS/DFS+优先队列版本。

最终模块：
1. BFS 找直径一端；
2. 第二次 BFS 找另一端并保存前驱；
3. 回溯直径路径；
4. 选一个中部点作为初始路由器；
5. 以其为根算向下最深距离；
6. priority_queue 每次扩展当前最深前沿，保持选点连通；
7. 从 selected/unselected 边界估最终最大衰减。

### 已确认的最终实现漏洞

```cpp
road.push_back(0);
...
int len = road.size() - 1;
int pos = len / 2;
int root = road[pos];
```

`road[1..len]` 才是真路径。三点链 M=1 时会取到端点而非中点，精确复现见 `验证/net_最小反例.md`。

因此 net 的标签只能写：**OJ-AC + KNOWN-COUNTEREXAMPLE**；修正后的小树实验另记 BRUTE-VERIFIED，不能把最终提交标 PROVED。

## 5.1 N≤5000 分支

目标是从每个起点 DFS，沿路径维护最早可行访问日。

核心递推本来应该把当前节点真实访问时间带入下一步；最终代码却从：

```cpp
dfs(i, 0);
```

开始，等价于允许起点在第0天被访问，违反 `x_i∈[l_i,r_i]`。这不是“只差一个优化”，而是 brute oracle 本身语义不精确。

## 5.2 性质A

最终仍是：

```cpp
if (A) {
    // task 3
    return 0;
}
```

所以这一整包从源码层就不可能闭合。

## 5.3 星形 special

中期版本逐步加入 `d1/d2`：
- 叶子能否先到中心；
- 中心能否再到另一叶子；
- 判断最多走1/2/3个点。

这部分不是空想，Replay 确实记录了从空分支到具体实现的增长。

## 5.4 链 special：赛时“时间逆流”

v8 首次完整出现：
- 先复原链 `line[]`；
- 用可行访问时间区间 `[L,R]`；
- 每走一步整体减1再和下一节点窗口取交；
- 左到右、右到左各做一次。

这个思想本身是有内容的。

但反向初始化最终写成：

```cpp
L = l[n - 1], R = r[n - 1];
```

这里用“节点编号 n-1”，而不是“链上的第 n-1 个节点 `line[n-1]`”，再次出现数学对象与代码对象错位。
